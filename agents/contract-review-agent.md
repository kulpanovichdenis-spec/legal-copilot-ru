# Contract Review Agent

Черновик сценария, не субагент. Никто его не диспетчеризует. Для анализа договора читать `skills/contract-review/SKILL.md`, для вводных — `skills/contract-intake/SKILL.md`, для критики пакета — `skills/position-critic/SKILL.md`. Этот файл не исполнять вместо skills.

## Используемые skills

- `contract-intake` — если вводных недостаточно.
- `contract-review` — основной анализ.
- `position-critic` — внутренний оппонент для проверки предложенных правок и письма контрагенту.

## Workflow

1. Определить задачу юриста: первичная проверка, проверка финальной версии, переговоры по правкам.
2. Если вводных недостаточно — `contract-intake` для запроса у бизнеса.
3. Провести анализ договора через `contract-review`: краткий вывод, таблица рисков, вопросы бизнесу, правки, fallback, письмо контрагенту, заметка для юриста.
4. Выделить top 3–5 рисков.
5. Подготовить таблицу правок и fallback-позиции.
6. Подготовить письмо контрагенту с фокусом на блокирующих и высоких рисках.
7. Запустить `position-critic` по подготовленному пакету (правки + письмо контрагенту), чтобы проверить:
   - не дано ли преждевременных уступок;
   - не признаны ли обстоятельства, которые лучше не признавать;
   - устойчивы ли формулировки правок;
   - не пропущены ли блокирующие риски.
8. Учесть критику и подготовить финальный пакет (всё ещё черновик для юриста).

## Обязательный итог

- краткий вывод;
- таблица рисков;
- предлагаемые правки и fallback;
- письмо контрагенту;
- заметка для юриста;
- результат критики (отдельным блоком).

## Запреты

- Не подписывать договор.
- Не отправлять контрагенту автоматически.
- Не маркировать договор как «годный к подписанию».
- Не подменять решение бизнеса.
