# Workflow

Рабочая папка юриста. **Все документы, генерируемые skills проекта (договоры, ДС, иски, отзывы, претензии, ответы госорганам, объяснения, письма, анализы, карточки контрагентов и т. д.), сохраняются сюда.**

Правило закреплено в [`CLAUDE.md`](../CLAUDE.md) → раздел "Куда сохранять результаты работы" — обязательно для всех skills.

## Что здесь

- `.docx` — финальные и черновые версии документов;
- `.md` — анализы, разборы, risk matrices, чеклисты, карточки контрагентов;
- сводки, выписки, любые промежуточные материалы.

## Структура подпапок

На усмотрение юриста. Варианты:
- по делу: `workflow/А40-12345-2025/`
- по контрагенту: `workflow/ООО-Альфа/`
- по дате: `workflow/2026-06/`
- плоско в корне `workflow/`

Skill сам подпапку не выбирает, если юрист не указал. При очевидной категории в реплике (номер дела, контрагент) — может создать подпапку и сообщить юристу одной строкой.

## Служебные папки pre-LLM конвейера анонимизации: `_anonymizer/`

Всё, что относится к анонимайзеру, собрано в одном контейнере `_anonymizer/` — и рабочие папки, и оба ярлыка запуска. Так служебные папки конвейера не путаются с папками дел в корне `workflow/`.

Каркас ниже закоммичен в репозиторий (через пустые `.gitkeep`), чтобы после клона проекта конвейер работал сразу, без ручного создания папок. **Сами документы в этих папках остаются локальными.**

| Папка / файл | Назначение |
|---|---|
| `_anonymizer/_inbox/` | Входящие документы, профиль `full` — обезличиваются полностью |
| `_anonymizer/_inbox/analytic/` | Входящие, профиль `analytic` — суммы и даты остаются открытыми |
| `_anonymizer/_inbox/originals/` | Обработанные оригиналы (перемещаются сюда автоматически) |
| `_anonymizer/_inbox/failed/` | Документы, на которых конвейер упал |
| `_anonymizer/_ready/` | Результат: `<имя>.anon.md` + `<имя>.mapping.json` |
| `_anonymizer/Anonymizer Watcher.lnk` | Включить анонимайзер (двойной клик) |
| `_anonymizer/Anonymizer Restore.lnk` | Вернуть реальные данные (перетащить черновик + mapping.json) |
| `_anonymizer/<проект>/` | Проект в автоматическом режиме: оригиналы обезличиваются общим словарём, черновики ассистента сами восстанавливаются в `готово/`; в репозиторий не попадает целиком (см. `tools/pre_anonymize/README.md`, «Проекты») |

Ярлыки в git не уходят (`*.lnk` + `workflow/**` в `.gitignore`) — после клона/распаковки их ставит одна идемпотентная команда из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\pre_anonymize\install-shortcuts.ps1
```

Запуск без ярлыка — `tools/watch/start-watcher.bat` или
`python -m tools.watch.cli --daemon`; старые `.bat` анонимайзера и `_claims`
делегируют той же команде. Подробности — в
[`tools/pre_anonymize/README.md`](../tools/pre_anonymize/README.md).

## Единый watcher входных каналов

Один локальный Python-процесс обслуживает все входные каналы: два режима
анонимайзера и его проекты (`_anonymizer/<проект>/`), `_claims`,
`products/_inbox`, `corporate/_inbox`, `compliance/_inbox`, `clauses/_inbox`,
`document-samples/_inbox` и `_counterparty/_inbox`.
Он не вызывает LLM, не ходит в сеть и не выбирает модель. Результаты слоя A и
ссылки на приватные task-card попадают в `workflow/_watcher/queue/`; при старте
Claude Code или Codex hook показывает только агрегированное число задач.

`profile/knowledge/corporate/entities/` не является входным каналом: документы
корпоративного управления поступают через `corporate/_inbox`. Legal DD тоже не
входит в этот реестр — его dataroom watcher остаётся ручным и запускается по
инструкции `legal-dd-navigator`.

Полезные команды:

```powershell
python -m tools.watch.cli --once
python -m tools.watch.cli --selftest
python -m tools.watch.queue_cli list
powershell -NoProfile -ExecutionPolicy Bypass -File tools\watch\install_windows.ps1
```

Последняя команда без `-Install` только показывает будущую Windows-задачу.
Установка выполняется повторным запуском с `-Install` после проверки параметров.

## Канал приёма для авто-разбора: `_claims/`

Готовы детерминированное ядро, watcher и агент-классификатор.

Канал **один**: кладите сюда любой входящий или исходящий документ по спору — иск, отзыв, возражения, ходатайство, претензию, а также запросы, ответы и споры с госорганами. Разделять папки не нужно — конвейер сам определяет категорию.

Категория (спор с контрагентом / работа с госорганом) определяется **по адресату, а не по форуму**: если на другой стороне госорган — это работа категории `gov_response`, даже когда спор уже в суде. От категории зависит только то, какой skill будет предложен и что попадёт в `task_types` карточки дела.

### Где появится папка дела

**Это только канал приёма — папки дел в нём не создаются.** Дело живёт там же, где и раньше: `workflow/<дело>/` (например `workflow/А40-12345-2025/`). Конвейер находит существующую папку дела (по номеру дела, затем по контрагенту) или заводит новую — **в корне `workflow/`**.

```
workflow/
  _anonymizer/        ← служебный контейнер анонимайзера (папки + ярлыки)
  _claims/            ← кладёте документ сюда (канал приёма)
  А40-12345-2025/     ← дело: сюда попадает документ,
                        сюда же пишутся case-context.md и matter-timeline.yaml
```

### Как это работает и почему в два шага

Конвейер делится на две части — так устроено намеренно:

1. **Watcher** — чистый Python, без ИИ: дожидается, пока файл дозапишется, извлекает текст, вытаскивает номера дел, подбирает папку дела и складывает карточку задачи в `_claims/queue/`. Оригинал убирает в `processed/`.
2. **Агент в сессии** — по фразе «разбери входящие» читает очередь, определяет тип документа (через субагента `intake-classifier`) и раскладывает по делам. Если OCR не справился (рукописное заявление, плохой скан — Tesseract рукопись не читает), агент сначала сам дочитывает страницы по изображению и только потом классифицирует.

Причина разделения: определение типа документа требует модели, а Python-процесс сам вызвать её не может.

### Watcher держать включённым не обязательно

| Способ | Когда удобнее |
|---|---|
| **Ничего не включать** | Положили документы в `_claims/` и сказали в сессии «разбери входящие» — агент сам прогонит сканирование и разберёт. Годится, если документы приходят не часто |
| **Единый watcher** (`tools/watch/start-watcher.bat`) | Держать один процесс фоном для всех каналов. Документы проходят слой A по мере поступления; закрытие окна останавливает watcher |

**Что он потребляет, когда включён:** раз в 20 секунд смотрит список файлов в одной папке и снова засыпает — то есть почти всё время спит. **ИИ не вызывает, в интернет не ходит, денег не тратит.** Заметная работа бывает только в момент, когда документ реально появился (извлечение текста).

### Служебные подпапки канала

| Папка | Назначение |
|---|---|
| `queue/` | Карточки задач для агента (заполняет watcher, разбирает агент) |
| `processed/` | Обработанные оригиналы (перемещаются автоматически) |
| `failed/` | Не удалось прочитать (битый файл, нечитаемый скан) |
| `unsorted/` | **Не удалось уверенно определить** тип, дело или формат — ждёт вашего решения, конвейер не угадывает |
| `Intake Watcher.lnk` | Если старый локальный ярлык сохранился, его команда должна вести на единый watcher; в git ярлык не хранится |

### Что конвейер делает с файлами, которые не берёт в обычную обработку

Молча не исчезает ничего, кроме собственных артефактов:

| Случай | Поведение |
|---|---|
| Документ открыт в Word (`~$Иск.docx`) | Сообщает вам. Сам lock-файл — служебные ~160 байт с именем пользователя, **текста документа в нём нет**, разбирать нечего |
| Файл ещё качается (`.crdownload`, `.part`) | Ждёт и берёт на следующем проходе, когда дозагрузится |
| Формат не разбираем (напр. `.dwg`) | Уходит в `unsorted/` с пометкой — не игнорируется |
| Артефакт самого конвейера (`.anon.md`, `.mapping.json`) | Единственный случай тихого пропуска |

**Правила безопасности:** конвейер работает только с каналами приёма; папки дел, куда вы кладёте документы руками, не трогает. Существующие документы не перезаписываются (при совпадении имени — «Иск (2).docx»). Ничего не финализирует и не отправляет — только раскладывает и предлагает, каким skill продолжить.

Правила для агента (из `CLAUDE.md` → "Конфиденциальность"): работать только с `_anonymizer/_ready/*.anon.md`; оригиналы из `_anonymizer/_inbox/` (включая `originals/`, `failed/`) не читать; mapping-файлы в LLM-контекст не передавать — обратная подстановка только через `prepare.py restore`. В проектах `_anonymizer/<проект>/` — только `*.anon.md`, `case-context.md`, `deadlines.yaml`, `matter-timeline.yaml` в корне и `черновики/`.

## Приватность

Содержимое папки в `.gitignore` — **не уходит в репозиторий**. Поэтому здесь можно хранить документы с необезличенными данными: реквизитами контрагентов, ПДн, суммами, номерами договоров и дел. Папки конкретных дел и контрагентов (`workflow/<дело>/`) в репозиторий не попадают.

Исключение — только этот README и пустые `.gitkeep` служебных папок выше.

Для обезличенных образцов документов — личный слой профиля `profile/knowledge/document-samples/` (навигатор `references/legal-document-samples-usage.md`).
