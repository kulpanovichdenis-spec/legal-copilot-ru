# Клаузы (личный слой знаний)

Домен слоя знаний профиля: одобренные юристом формулировки отдельных условий
договоров и ДС. Персональный слой — содержимое в `.gitignore`, не пушится,
переносится с профилем. Общего базового набора в репозитории нет.

## Структура

- `_inbox/` — сюда кладёшь исходный договор/ДС/документ, из которого нужно вынуть клаузу. Единый watcher локально обезличивает файл, сохраняет закрытый mapping в `workflow/_watcher/staging/clause/` и создаёт task-card; карточку-клаузу пишет агент.
- `cards/` — карточки-клаузы `.md` (готовый текст формулировки + применимость).
- `originals/` — исходники после разбора.

## Карточка (`cards/<slug>.md`)

Frontmatter — ключи поиска:

```yaml
---
type: clause
name: "<название клаузы>"
aliases: ["<синонимы>", "<англ. термин>"]
applies_to: ["<к каким договорам>"]
lang: ru            # ru | en | bilingual
verification: verified   # candidate | verified
source_files: []
updated: 2026-09-17
---
```

Тело — готовый текст клаузы + строки «Применимо» / «Тактическая ценность».

## Как используется

Скилы `clause-library`, `contract-review`, `contract-drafter`, `amendment-drafter`
находят клаузу здесь через **Glob** (`cards/*.md`) + **Read** (выбор по таблице
навигатора `clause-library`), берут текст и **адаптируют** под конкретный договор
(наименования сторон, нумерация, предмет). ⚠️ Карточки в `.gitignore` — обычный
Grep-инструмент их не видит; для поиска по телу — `rg --no-ignore` через Bash. Клауза — **заготовка формы, не правовое основание**; норму проверять
отдельно по обычному циклу. Нет профиля/карточки — скил честно сообщает «в профиле
нет клаузы», без выдумывания.

До проверки юристом новая карточка имеет статус `candidate`; watcher никогда не
присваивает `verified` и не вызывает LLM сам.

Соглашение слоя — `references/profile-knowledge-layer.md`;
навигатор с правилами адаптации — `skills/clause-library/SKILL.md`.
