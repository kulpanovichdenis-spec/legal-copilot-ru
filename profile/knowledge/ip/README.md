# Реестр товарных знаков (profile/knowledge/ip)

Конфиденциальный слой: содержимое не коммитится, в git только скелет. Правила — `references/ip-registry-layer.md`.

- `_inbox/` — сюда класть новую выгрузку реестра (.xlsx) или документы (PDF, скан, HTML, изображение: свидетельство, решение, продление, выписка ФИПС, документ WIPO); watcher обработает сам. Первая выгрузка Excel создаёт базу, следующие только сверяются с ней;
- `originals/` — принятые выгрузки с датой в имени;
- `_inbox/failed/` — файлы, которые не удалось разобрать (причина — в карточке очереди и журнале watcher; прежний каталог не меняется);
- `documents/` — принятые документы и их текст `.md`;
- `pending/` — карточки документов, ждущих внесения (`<doc_id>.json`), и факты, сохранённые агентом (`<doc_id>.facts.json`); открытые карточки: `python -m tools.ip_registry pending`;
- `data/events.jsonl` — журнал событий, главный источник (только дописывается); `data/base.json` — снимок из журнала (в нём контакты поверенных, агент его не открывает); `data/marks/` — изображения знаков;
- `catalog.html` — каталог для юриста, открывается двойным кликом;
- `index/` — markdown для агента;
- `products.yaml` — справочник препаратов (правит юрист);
- `verifications.yaml` — сверки статусов стран; при `migrate` переносится в журнал и дальше не читается;
- `changes/` — отчёты: изменения между сборками, `ДАТА-документ-<имя>.md` по каждому документу, `ДАТА-сверка-excel.md` по повторной выгрузке Excel.

Как внести документ: положить файл в `_inbox/` и открыть сессию с агентом (skill ip-registry, режим «Документы»); спорное агент не вносит, а предлагает вам команду. Открытые решения: `python -m tools.ip_registry pending`.

Данные — внутренний реестр на дату выгрузки или документа, не сведения Роспатента/WIPO.
