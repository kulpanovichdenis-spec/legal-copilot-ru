# slop_check — линтер AI-slop

Детерминированный проверяльщик текстов на **AI-slop** (пустые клише, тэллы языковых моделей, типографика). Ничего не переписывает — подсвечивает кандидатов с указанием строки и категории. Решение убрать/оставить — за человеком (как `cross-ref-checker` не удаляет ссылки сам).

Правило и реестр — `references/anti-slop.md`, единственный источник: блоки `yaml slop` в каждом пункте реестра. `patterns.py` их загружает (своего списка нет), структурные проверки (повторы, вводная = заголовок, риторический заголовок, плотность тире) — функции в `check.py`, пороги — в реестре. Водяные знаки (Unicode/статистические) тул **не трогает** — только лингвистический slop.

## Запуск

```
python tools/slop_check/check.py <файл> [<файл> ...]
```

Принимает `.txt`, `.md`, `.docx` (для `.docx` нужен `python-docx`). Для `.docx` номер «строки» = номер абзаца; текст берётся с принятыми исправлениями (удалённое рецензированием не проверяется).

Код возврата: `1`, если найден хотя бы один паттерн `severity=high`; иначе `0`. Находки `review` код возврата не меняют (контекстно-зависимы — например, многоточие в цитате нормы).

## Когда применять

Перед сохранением любого документа для человека в `workflow/` — часть пресейв-гейта (`CLAUDE.md`, «Финальная валидация перед сохранением»; `references/docx-generation.md`).

Главное в тестах — **калибровка**: линтер не должен флагать правовые связки («на основании», «в связи с», «в силу»), формулы цитирования и намеренный дипломатический регистр письма-обоснования («обращаем внимание», «вынуждены отметить», «не можем согласиться», «полагаем возможным», «выражаем надежду»).

## Как расширять реестр

Правится только `references/anti-slop.md`: в блок `yaml slop` нужного пункта добавить элемент `{id, severity, regex, message}` или `{id, severity, check, params, message}`. Новая структурная проверка — функция в `check.py` и запись в `STRUCTURAL`; если реестр объявит проверку, которой нет в коде, линтер не запустится. `test_registry_coverage` не даст оставить пункт реестра без проверки. При добавлении паттерна — позитивный и (при риске ложных срабатываний) негативный тест в `test_check.py`.
