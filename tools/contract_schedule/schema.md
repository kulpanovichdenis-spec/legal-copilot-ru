# Схема JSON обязательства — контракт между моделью и скриптом

Модель извлекает из договора массив объектов. Скрипт считает даты и рисует .xlsx.

```json
{
  "id": 7,
  "clause": "п. 4.2",
  "title": "Оплата аванса 30%",
  "obligor": "Покупатель",
  "kind": "payment",
  "amount": 1500000,
  "term_verbatim": "в течение 10 (десяти) рабочих дней с момента подписания Договора",
  "anchor": "contract_signing",
  "offset": 10,
  "unit": "business_days",
  "direction": "after",
  "duration": 0
}
```

| Поле | Тип | Обязательное | Значение |
|---|---|---|---|
| `id` | int | да | уникальный номер строки, на него ссылаются цепочки |
| `clause` | str | да | пункт договора («п. 4.2»); нет пункта — `""` |
| `title` | str | да | наименование обязательства |
| `obligor` | str | да | обязанная сторона как в договоре |
| `kind` | str | да | `payment` / `delivery` / `stage` / `acceptance` / `notice` / `warranty` / `term` |
| `amount` | number\|null | нет | сумма платежа; для неденежных — `null` |
| `term_verbatim` | str | да | **дословная** формулировка срока из договора; не редактируется |
| `fixed_date` | str\|null | нет | `YYYY-MM-DD`, если в договоре прямо указана календарная дата |
| `anchor` | str\|null | да, если нет `fixed_date` | имя события или ссылка `item:<id>.start` / `item:<id>.end` |
| `offset` | int | да, если есть `anchor` | величина срока в единицах `unit` |
| `unit` | str | да, если есть `anchor` | `calendar_days` / `business_days` / `banking_days` / `weeks` / `months` / `years` |
| `direction` | str | нет (умолч. `after`) | `after` — срок течёт после события; `before` — отсчёт назад («за 30 дней до») |
| `duration` | int | нет (умолч. `0`) | собственная длительность в тех же единицах `unit`; `0` = веха (точка) |

## Правила заполнения

- **`term_verbatim` заполняется всегда**, даже когда дата вычисляется. Это опора юриста, если расчёт неверен.
- **Не выдумывать `anchor`.** Если из текста непонятно, от чего течёт срок, — `anchor: null`; строка попадёт в файл как `not_computed` с маркером `[ПРОВЕРИТЬ СРОК]`. Это нормальный результат, а не брак.
- **Имена событий** — латиницей, стабильные: `contract_signing`, `advance_paid`, `delivery_accepted`, `invoice_received`. Юрист задаёт их даты через `--anchor`.
- **Цепочки** — когда срок течёт от другого обязательства: `"anchor": "item:5.end"`.
- `direction: "before"` в рабочих днях не поддержан — если в договоре «за 10 рабочих дней до», оставить `anchor: null` и маркер.
