# docx_redline — правки режимом исправлений Word

Когда что применять — `references/docx-generation.md`, раздел «Редлайн». Все скрипты: PowerShell 5.1 + Word COM, файлы `.ps1` в UTF-8 с BOM.

| Скрипт | Назначение |
|---|---|
| `compare.ps1` | Свой документ: сравнение файла юриста с чистой новой версией → редлайн. |
| `apply_ops.ps1` | Чужая форма «как есть»: точечные правки по JSON-списку на копии файла. |
| `verify.ps1` | Проверка любого редлайна: авторы и счёт `w:ins`/`w:del`/`w:moveFrom`/комментариев из XML, итоговый текст (все исправления приняты во временной копии) с номерами списков. |
| `selftest.ps1` | Прогон `apply_ops` + `verify` на обезличенном примере `example/`. |

## Порядок работы с чужой формой

```powershell
# 1. Номера абзацев исходника (поле p)
powershell -NoProfile -ExecutionPolicy Bypass -File tools/docx_redline/apply_ops.ps1 -Src "<форма>.docx" -List
# 2. Правки
powershell -NoProfile -ExecutionPolicy Bypass -File tools/docx_redline/apply_ops.ps1 -Src "<форма>.docx" -Out "<форма> rev1 (редлайн).docx" -OpsPath ops.json
# 3. Проверка
powershell -NoProfile -ExecutionPolicy Bypass -File tools/docx_redline/verify.ps1 -Docx "<форма> rev1 (редлайн).docx"
```

Исходник не меняется. Выходной файл уже существует → ошибка (перезапись только с `-Overwrite`). Лог — рядом с результатом (`*.ops.log`) или в `-LogPath`. При любой ошибке выходной файл удаляется, код возврата 1.

**Автор правок** — `Application.UserName` (обычно сам юрист). `-Author "<имя>"` [`-Initials "<ин.>"`] ставит другое имя через `Options.UseLocalUserInfo` + `UserName`; прежние значения возвращаются в `finally`.

PDF для визуальной проверки — отдельным запуском (`tools/docx_render/render_docx.py`): `ExportAsFixedFormat` в том же процессе Word после правок может уронить Word (`RPC_E_DISCONNECTED`).

## ops.json

Объект `{"ops": [...]}` (допустим и голый массив). Пример — `example/ops.json` к образцу из `example/make_sample.py`.

| Поле | Смысл |
|---|---|
| `op` | Тип операции (ниже). |
| `p` | Номер абзаца по исходнику, как в выводе `-List` (с 1; конец строки таблицы — тоже абзац). |
| `anchor` | Начало абзаца для сверки (сравнивается после `TrimStart`). Указывать всегда: защищает от сдвига нумерации. |
| `find` | Подстрока в абзаце. |
| `occ` | Номер вхождения `find` (по умолчанию 1). |
| `new` | Новый текст. |
| `c` | Комментарий: ставится на вставленный текст, а при удалении — на удалённый. |
| `cat` | Фраза внутри правки (до 255 знаков), к которой крепится комментарий `c`. Ищется во вставленном тексте, у `delete`/`delete_para`/`comment_para` — в исходном. Указывать, когда правка длиннее одной фразы: комментарий ставится точечно к месту, о котором он, а не на весь абзац или блок. |
| `nobold` | `true` — снять жирный со вставки (вставка наследует формат заменяемого текста). |

| `op` | Что делает |
|---|---|
| `replace` | `find` → `new` (пустой `new` = удаление). |
| `delete` | Удалить `find`. |
| `insert_after` | Вставить `new` сразу после `find`. |
| `replace_tail` | Заменить текст от `find` до конца абзаца на `new`. |
| `replace_para` | Заменить весь текст абзаца (без знака абзаца) на `new`. |
| `delete_para` | Удалить абзац целиком со знаком абзаца (не для последнего абзаца ячейки таблицы — там `replace_para` с `"new": ""`). |
| `comment_para` | Комментарий `c` на весь абзац. |

## Как устроено (и почему)

1. Абзацы (`Range.Start/End/Text`) читаются до правок; все позиции считаются по исходнику.
2. Все операции проверяются до первой правки: абзац есть, `anchor` совпал, `find` найден, `Range(s, e).Text` равен ожидаемому тексту, правки не пересекаются. Любое расхождение — ошибка без частичного результата.
3. Включается `TrackRevisions = true`, `TrackFormatting = false`; операции применяются с конца документа к началу, поэтому ранние позиции не сдвигаются.
4. Замена: новый текст вставляется в конец старого (наследует его формат), затем старый удаляется.

Ограничение: если в редактируемом абзаце уже есть чужое удаление, `Range.Text` содержит удалённый текст и сверка `find` не пройдёт — такую правку внести вручную или через `find` по фрагменту без чужой правки. Чужие исправления в других местах не мешают и не принимаются.

Ловушка PowerShell для доработок: имена переменных не различают регистр, поэтому переменная `$ops` затирает параметр `$Ops`. Внутри скриптов ни одна переменная не повторяет имя параметра.
