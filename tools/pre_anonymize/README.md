# pre_anonymize — pre-LLM анонимизация документов

## Для юриста — как пользоваться (коротко)

Анонимайзер автоматически убирает конфиденциальные данные (ФИО, реквизиты, суммы, адреса и т. д.) из документа, прежде чем он попадёт в работу ассистенту/ИИ. Оригинал документа никуда не уходит — остаётся у вас на компьютере.

**Где всё лежит:** все папки конвейера и оба ярлыка собраны в одной папке —
`workflow\_anonymizer`. Рабочий стол они не занимают.

**Как включить:**
1. Дважды кликнуть по ярлыку **«Anonymizer Watcher»** в папке `workflow\_anonymizer`.
2. Ярлык запускает единый watcher всех входных каналов. Откроется окно консоли —
   сверните его (не закрывайте!).

**Шаг 1 — обезличить входящий документ:**
1. Положите документ (`.docx`/`.doc`/`.rtf`/`.pdf`/`.xlsx`/`.pptx`/скан) в папку `workflow\_anonymizer\_inbox`.
   - Если нужно, чтобы суммы и даты остались видны (например, для анализа договора) — кладите в `workflow\_anonymizer\_inbox\analytic` вместо обычной `_inbox`.
2. Подождите несколько секунд — анонимайзер обработает файл сам.
3. Появятся два файла в `workflow\_anonymizer\_ready`:
   - **`<имя>.anon.md`** — обезличенный текст. Его отдаёте ассистенту, либо переносите в отдельную папку `workflow\...`, где вы работаете над задачей. Далее ставите задачу агенту — например, «подготовь протокол разногласий по этому документу»;
   - **`<имя>.mapping.json`** — словарь «плейсхолдер → реальные данные». **Никогда не передавайте этот файл ассистенту/ИИ** — он нужен только вам на шаге 3.
4. Оригинал документа автоматически переместится в `workflow\_anonymizer\_inbox\originals` — он никуда не пропадает, просто убран с дороги.

**Шаг 2 — получить черновик от ассистента:**

Ассистент работает только с обезличенным текстом и никогда не видит `mapping.json` — это осознанно так устроено, чтобы конфиденциальность не терялась на полпути. Поэтому готовый черновик (протокол разногласий, претензия, любой другой документ), который вам пришлёт ассистент, будет **всё ещё содержать плейсхолдеры** (`[КОМПАНИЯ_1]`, `[ФИО_1]` и т. п.) вместо реальных названий и имён — это ожидаемо, а не ошибка.

**Шаг 3 — вернуть реальные данные в готовый документ:**

Так же просто, как и анонимизация — без PowerShell и без ручного набора команд:

1. Возьмите два файла — черновик от ассистента (`.docx`/`.md`/`.txt`) и файл с данными `<имя_исходника>.mapping.json` из `workflow\_anonymizer\_ready`.
2. Перетащите оба файла прямо на **закрытый** ярлык «Anonymizer Restore» в папке `workflow\_anonymizer` — открывать/запускать его предварительно не нужно, достаточно "бросить" файлы на его иконку. Windows сам запустит его с этими файлами, откроется окно с результатом. Порядок файлов не важен.
3. Результат появится рядом с черновиком, с припиской `.restored` в имени (например, `черновик.restored.docx`) — это и есть финальный документ с реальными названиями, именами и реквизитами, готовый к дальнейшей работе/отправке/подписанию. Работать нужно именно с файлом `.restored.docx`, а не с черновиком от ассистента (в нём так и останутся плейсхолдеры).

Важно: mapping.json — это файл **от исходного документа**, который вы анонимизировали на Шаге 1 (не от нового черновика — у черновика своего mapping.json нет, он использует тот же словарь, что и исходник).

Если файлов несколько (например, ассистент подготовил и протокол разногласий, и сопроводительное письмо на основе одного и того же исходника) — перетащите на ярлык каждый черновик отдельно вместе с тем же mapping.json.

Если перетащить на ярлык только один файл (забыли mapping.json или черновик) — откроется окно с понятной ошибкой, что нужно перетащить оба файла сразу.

**Если что-то пошло не так:**
- Файл появился в `workflow\_anonymizer\_inbox\failed` — значит, не удалось прочитать текст (плохой скан, повреждённый файл) или формат не поддерживается (например, `.odt`, `.pages`). Сообщите об этом; попробуйте пересканировать документ или пересохранить его в `.docx`/`.pdf`. Причина без имени файла записана в журнал watcher (`unsupported ext=…` или `failed ext=…`). В проекте такой файл уходит в `_служебное\не-обработано\`.
- В консоли `restore` пишет, сколько подстановок сделано; для текстовых файлов (`.md`/`.txt`) он также предупредит, если какой-то плейсхолдер не нашёлся в словаре. **Для `.docx` такого предупреждения сейчас нет** — после восстановления один раз откройте финальный `.restored.docx` глазами и убедитесь, что плейсхолдеров вида `[...]` не осталось.

**Важно:**
- `.mapping.json` содержит настоящие данные — храните его так же осторожно, как сам исходный документ; **никогда не передавайте его ассистенту/ИИ**.
- Для по-настоящему чувствительных документов (NDA и т. п.) — перед тем как отдавать `.anon.md` дальше, один раз просмотрите его глазами: автоматическая маскировка не даёт стопроцентной гарантии.
- Чтобы выключить анонимайзер — просто закройте окно консоли.

## Проекты: автоматический режим (для юриста)

Если по делу много документов, удобнее завести **проект**: тогда не нужно ни
искать `mapping.json`, ни перетаскивать файлы на ярлык Restore.

**Как завести.** Создайте папку внутри `workflow\_anonymizer\`, например
`workflow\_anonymizer\2026 проект-07`. Watcher заметит её сам и создаст
служебные подпапки. Папка в обычном `workflow\` (без `_anonymizer`) работает
как раньше, без автоматического режима.

| Где | Что |
|---|---|
| корень проекта | сюда кладёте оригиналы; через несколько секунд их здесь уже нет |
| `analytic\` | сюда — оригиналы, где суммы и даты должны остаться открытыми |
| `документ-01.anon.md`, `документ-02.anon.md`… | обезличенные тексты — с ними работает ассистент |
| `черновики\` | сюда ассистент сохраняет документы (с метками `[КОМПАНИЯ_1]`) |
| `готово\` | сюда **сам** приходит документ с реальными данными (имя файла — с метками) — это ваш результат |
| `_служебное\оригиналы\` | ваши оригиналы под теми же номерами: `документ-01.pdf` — исходник `документ-01.anon.md` |
| `_служебное\не-обработано\` | документы, из которых не удалось извлечь текст (плохой скан) |

**Как это работает.** У проекта один словарь: «ООО Ромашка» во всех его
документах станет `[КОМПАНИЯ_1]`. Ассистент сохранил
`черновики\Письмо в [КОМПАНИЯ_1].docx` — в `готово\` появится
`Письмо в [КОМПАНИЯ_1].docx` с реальными данными внутри. Имя файла остаётся
с метками — так ассистент не видит реальные названия даже в списке файлов;
перед отправкой переименуйте файл. Восстанавливаются только `.docx`.

- **Ваши правки не теряются.** Если вы уже правили документ в `готово\`, а
  ассистент переделал черновик, рядом появится `… (2).docx`.
- **Продолжить по вашей версии** — положите правленый документ в корень
  проекта: он обезличится тем же словарём, метки совпадут. Файл в корне
  проекта, где есть хоть что-то похожее на реальные данные (дата, сумма, имя),
  считается оригиналом и обезличивается — даже если это черновик ассистента;
  так безопаснее.
- **Не переносите в проект** готовые `.anon.md` из `_ready\`: у них другой
  словарь, метки не совпадут. Кладите в проект оригиналы.
- **Предупреждения** (возможные остатки реальных данных после обезличивания;
  метки, которые не удалось восстановить в `готово\`; нечитаемый документ)
  попадают в очередь: при старте сессии видно их число, список —
  `python -m tools.watch.queue_cli list` (без имён и текста документов).

**Ограничения:**
- **Падежи.** Одно лицо в разных падежах получает одну метку, если ФИО полное —
  с отчеством («Иванова Ивана Петровича» и «Иванову Ивану Петровичу» — обе
  `[ФИО_1]`). Восстанавливается форма в именительном падеже, если она где-то
  встречалась, иначе первая встреченная: «направляем [ФИО_1]» станет
  «направляем Иванов Иван Петрович». Поправьте падеж при вычитке. Без отчества
  («Иванов И. П.», «Сидорова Валентина») формы не склеиваются: так разные люди
  с похожими фамилиями не получат одну метку.
- **Имя папки проекта видно ассистенту.** Если название контрагента само по
  себе чувствительно, называйте папку нейтрально («2026 проект-07»). Имя
  оригинала видно несколько секунд, пока watcher его не обработал.
- **Проверки по реальным данным** (DaData по ИНН, поиск дела по номеру) внутри
  проекта не работают — делайте их вне проекта.
- Ассистенту закрыты оригиналы, `_служебное\` и `готово\`: так велит правило
  CLAUDE.md, а у Claude Code, Codex и Cursor его подкрепляет страховка-хук.

**В GitHub папки проектов не попадают** — ни оригиналы, ни `.anon.md`, ни
черновики, ни `готово\`. В репозитории только код и настройки.

**Codex:** после обновления один раз разрешите хук «Проверяю доступ к проекту
анонимайзера»: в приложении Codex — «Настройки → Hooks», в терминальном Codex
CLI — команда `/hooks`. Хук описан в `.codex/hooks.json`; секции `[hooks]` в
`config.toml` нет, это нормально. Пока хук не разрешён, Codex его молча
пропускает.

## Техническое описание (для агента/поддержки)

Локальный конвейер «документ → Markdown → обезличенная копия», работающий **вне
LLM-контура**: модель видит только результат, оригинал не покидает машину.
Ядро обезличивания — `tools/pre_anonymize/anonymizer.py`, конвертация — `tools/doc_ingest` (markitdown),
сканы и изображения — локальный OCR (`ocr.py`, Tesseract, тоже офлайн).

## Схема

```
workflow/_anonymizer/            ← контейнер: все папки конвейера + оба ярлыка
  _inbox/                        ← юрист кладёт входящий .docx/.pdf/.md/...
  _inbox/analytic/               ← то же, но профиль analytic (суммы/даты открыты)
        │ tools.watch (единый фоновой процесс)
        ▼
  _ready/<имя>.anon.md           ← это читает агент/LLM
  _ready/<имя>.mapping.json      ← словарь плейсхолдер→оригинал (LLM не показывать)
  _ready/<имя>.quality.json      ← автопроверка обезличивания (счётчики, без значений)
  _inbox/originals/              ← оригинал после обработки
  _inbox/failed/                 ← если извлечь текст не удалось (см. watcher.log)
  Anonymizer Watcher.lnk         ← ярлыки ставит install-shortcuts.ps1; в git не
  Anonymizer Restore.lnk            уходят (*.lnk + workflow/** в .gitignore)
```

Поддерживаемые форматы: `.docx/.pdf/.txt/.md/.html/.xlsx/.pptx/.csv` +
изображения `.png/.jpg/.jpeg/.tif/.tiff/.bmp/.gif`. Сканированный PDF без
текстового слоя и изображения распознаются локальным OCR. **Если текст извлечь
не удалось** (скан плохого качества, OCR пуст) — файл уходит в `failed/` с
пометкой, а не создаёт пустой `.anon.md` (защита от «ложного готово»).

## Проекты (автоматический режим) — техническое описание

- `project_layout.py` — имена папок проекта, allow-list файлов агента, список
  поддерживаемых форматов (один источник для `watcher.py`, `project.py`,
  `project_guard.py`); без тяжёлых импортов.
- `project.py` — `find_projects`, `ensure_layout`, `process_original` (общий
  словарь через `Anonymizer.from_state` / `export_state`, нейтральные имена,
  `quality_report`, черновик в корне → `черновики/`), `restore_draft`
  (`черновики/*.docx` → `готово/`, имя файла остаётся с метками (решение юриста 2026-10-08), правка юриста
  → `(2)`, невосстановленные метки считаются).
- Состояние проекта — `_служебное/состояние.b64`: base64 от JSON со словарём,
  таблицей имён (`документ-NN` → исходное имя) и хэшами restore. Base64 — не
  шифрование, а страховка от случайного поиска по тексту. Пишет только watcher.
- Канал единого watcher `anonymizer_projects` (`tools/watch/handlers/anonymizer.py`):
  вход `workflow/_anonymizer`; предупреждения — карточки очереди
  `quality_review`, `not_processed`, `restore_leftovers` (без значений и
  исходных имён файлов). Разовый проход:
  `python -m tools.watch.cli --once --channel anonymizer_projects`.
- Страховка `project_guard.py --runner claude|codex|cursor-read|cursor-shell`:
  `.claude/settings.json` (PreToolUse `Read|Grep|Bash|PowerShell`), `.codex/hooks.json`
  (PreToolUse `Bash`), `.cursor/hooks.json` (`beforeReadFile`,
  `beforeShellExecution`). Не видит путь, собранный внутри кода скрипта, и
  документ, переданный прямо в чат.
- **Известные ограничения страховки** (это страховка от случайного промаха,
  а не граница безопасности; решение юриста — цель «удобство»):
  - не видит путь, собранный внутри кода (переменные, `Join-Path`, вызовы
    .NET вроде `[IO.File]::ReadAllText` в конвейере), экранирование внутри
    слова `_anonymizer`, короткие имена 8.3, намеренные маски вида `[^x]`
    или `*{.md,}`; документ, переданный прямо в чат;
  - `cd` в той же команде не меняет рабочую папку, которую видит страховка;
  - поиск Grep из папки выше репозитория с маской `**/*` не распознаётся;
  - **ложные отказы:** команда, где путь `workflow/_anonymizer/…` упомянут
    как текст (шаблон поиска, многострочное сообщение коммита) рядом с
    читающим словом (`cat`, `grep`, …), запрещается — для поиска по коду
    используйте инструмент Grep, сообщение коммита передавайте файлом
    (`git commit -F <файл>`); маски без расширения (`Makefile`, `*test*`)
    при поиске из корня репозитория запрещаются;
  - рекурсивный поиск в терминале по `workflow/` утилитами, игнорирующими
    `.gitignore` (`grep -r … workflow`), видит текстовые оригиналы в
    `_служебное/` — ограничивать его нельзя: так ищут прошлые дела в обычных
    папках `workflow/`;
  - при аварийном падении самого скрипта страховки раннер пропускает действие.
- Тесты: `python -m pytest tools/pre_anonymize tools/watch -q`.

## OCR (сканы и изображения)

Полностью офлайн, скан никуда не уходит. Требует нативный движок **Tesseract**
(не ставится через pip):

```powershell
winget install UB-Mannheim.TesseractOCR --source winget   # языки rus+eng в комплекте
python -m pip install pytesseract pypdfium2 Pillow          # python-обвязка
```

Путь к `tesseract.exe` берётся из `PRE_ANON_TESSERACT_CMD`, иначе из стандартной
установки `C:\Program Files\Tesseract-OCR\`. Язык OCR — `PRE_ANON_OCR_LANG`
(по умолчанию `rus+eng`; для иных языков доставить пакет, напр. `chi_sim`).

Обратная подстановка в готовый черновик (md/txt/docx):

```powershell
python tools/pre_anonymize/prepare.py restore "workflow/письмо.docx" --mapping "workflow/_anonymizer/_ready/договор.mapping.json"
```

## Запуск watcher

- Обычный способ — ярлык **«Anonymizer Watcher»** в папке `workflow\_anonymizer`
  (создаётся при установке проекта, SETUP.md Шаг 9а). Если ярлыков нет — оба
  создаёт одна идемпотентная команда из корня проекта:
  `powershell -NoProfile -ExecutionPolicy Bypass -File tools\pre_anonymize\install-shortcuts.ps1`.
  Окно консоли сворачивать, не закрывать.
- Вручную: двойной клик `start-watcher.bat` или
  `python -m tools.watch.cli --daemon`. Старый `.bat` делегирует единому watcher.
- Разовый проход: `python -m tools.watch.cli --once --channel anonymizer --channel anonymizer_analytic`.
- Проверка всех маршрутов без рабочих документов: `python -m tools.watch.cli --selftest`.
- Автозапуск при входе в Windows сначала просмотреть, затем установить:
  `powershell -NoProfile -ExecutionPolicy Bypass -File tools\watch\install_windows.ps1`
  и после проверки вывода повторить с `-Install`.

Прямой `python tools/pre_anonymize/watcher.py --once` оставлен как диагностический
совместимый путь, но не создаёт второй штатный фоновый процесс.

## CLI без watcher'а

```powershell
python tools/pre_anonymize/prepare.py prepare "Договор.docx" --profile full     # всё маскируется
python tools/pre_anonymize/prepare.py prepare "Договор.docx" --profile analytic # суммы/даты открыты
python tools/pre_anonymize/prepare.py selftest
```

## Профили

| Профиль | Маскируется | Когда |
|---|---|---|
| `full` (по умолчанию) | всё: ПДн, реквизиты, компании, суммы, даты, сроки, описания | переписка, NDA-материалы, кадровое |
| `analytic` | всё, кроме СУММА/ДАТА/СРОК_ОПЛАТЫ/КОЛИЧЕСТВО/ПРОЦЕНТ/НДС | договорная аналитика: LLM нужны сроки и расчёты |
| `sample` | стороны, имена, адреса, реквизиты, контакты, номера, даты рождения, суммы, количества; **не** маскирует предмет услуг/описания, страны, даты, сроки оплаты, проценты, НДС | слой образцов `document-samples` (решение юриста 2026-10-05): без предмета и дат образец теряет смысл; профиль по умолчанию для `sample_intake` |

## Whitelist своей компании

Реквизиты, которые маскировать не нужно (своя организация), — по одному на
строку в `tools/pre_anonymize/whitelist.local.txt` (файл в `.gitignore`,
строки с `#` — комментарии).

## NER-слой (опционально)

Regex не ловит наименования без ОПФ/кавычек («ПАО Сбербанк» в середине фразы).
Закрывается локальной NER-библиотекой: `pip install natasha`, затем запуск
watcher/prepare с переменной `PRE_ANON_NER=1`. Без natasha флаг тихо игнорируется.

**Важно:** `natasha` — модель для **русского** языка. Для англоязычных
фрагментов (двуязычные международные контракты и т. п.) NER-слой не
подключается совсем — там работает только regex (см. «Ограничения» ниже).

## Ограничения (честно)

- Regex+NER — не гарантия 100 %: незнакомое наименование без якорей может
  проскочить. Для NDA-критичных документов юрист просматривает `.anon.md`
  перед передачей агенту.
- **Реальный баг, найденный и исправленный 2026-07-30** (на настоящем двуязычном
  контракте): (1) компания с запятой перед `LLC`/`Inc`/`Ltd` («Name, LLC») не
  распознавалась вовсе; (2) латинское ФИО со средним инициалом («Anton A.
  Tikhonov») не маскировалось совсем — самый серьёзный из трёх; (3) англоязычные
  адреса (улица/город/регион/индекс/страна) не имели своего паттерна и ловились
  только случайно. Все три исправлены и закрыты регрессионными тестами.
- **Реальный баг, найденный и исправленный 2026-07-31** (та же русская колонка
  того же двуязычного контракта — англоязычные фиксы от 2026-07-30 её не
  закрывали): (1) `ADDRESS_INDEX` (русский формат адреса) не доходил до маркера
  «ул.»/«дом», если между индексом и маркером встречались сокращения с точкой
  («г.», «с.», «обл.») — целый русский адрес («142143, Россия, Московская
  область, г. Подольск, с. Покров, ул. Сосновая 1») оставался полностью
  открытым; (2) названия стран на кириллице («Россия», «Российская Федерация»,
  «Китай» и т. п.) не имели своего паттерна вовсе — маскировались только страны
  на латинице. Оба исправлены и закрыты регрессионными тестами. Побочно
  обнаружен и исправлен третий, более тонкий баг: после того как
  `ADDRESS_INDEX` начал матчиться, его хвост без точек мог «перепрыгнуть» через
  границу столбца markdown-таблицы (символ `|`) в соседнюю ячейку — добавлено
  исключение `|` как терминатора наравне с точкой/`;`/переносом строки.
- **Остаточное ограничение после фикса**: голое название города/населённого
  пункта без соседнего маркера («Region»/«City»/«village» и т. п. рядом) всё ещё
  может проскочить — например, «Shanghai»/«Шанхай» само по себе, без
  слова-маркера рядом (в любом из двух языков). Список стран — фиксированный
  (не бесконечный, поэтому покрыт для обоих языков), а вот исчерпывающий
  гэзетир городов регэкспом не построить. Для документов с реальными
  геонаименованиями — проверять `.anon.md` глазами, как и с любыми
  NDA-критичными материалами.
- **Системная переработка 2026-09-30 / 2026-10-01** (реальный двуязычный договор
  поставки из PDF + ДС): движок одновременно портил текст и пропускал данные.
  - *Ложные замены:* ФИО определялось только по форме (2–3 слова с заглавной) —
    в английском договоре все определённые термины («Effective Date», «Business
    Days», «Purchase Order») становились `[ФИО_n]` (191 замена, реальных имён —
    единицы). Теперь ФИО-паттерны проходят фильтр словаря документа: слово,
    встречающееся в тексте со строчной буквы (по основе), или слово определённого
    термина в кавычках (`(the “X”)`, `(далее — «X»)`, по основе) — не имя; фраза
    с аббревиатурой в скобках («… Data Sheet (MSDS)») — не имя; отчество — всегда
    имя. Стоп-лист латиницы пополнен должностями и географией.
  - *Утечки:* адрес и подписант маскируются **целым фрагментом по якорю**
    («address at / Registered address: / located at / адрес места нахождения: /
    по адресу: / Грузополучатель: / Адрес банка:» … до «, hereinafter / ,
    именуем / (далее / является / пустой строки / следующей метки»; фрагмент
    переходит через одиночный перенос строки PDF); «represented by <должность>
    <имя>» / «в лице <должности> <имя>». Латинские якоря реквизитов (INN/KPP/
    OGRN/OKPO/BIC/Account/A/C, `SWIFT CODE:`, счёт группами цифр, «Registration
    number»), URL, номер документа с буквами («№ ДП-400-2023»; номера НПА и
    судебных актов — не трогаются), «Co., Ltd.» / LIMITED / «Ко., Лтд.», «K.
    Matveev», телефон «+8620-…» и «Тел./факс: (495) …», e-mail с markdown-хвостом
    и OCR-пробелом, дата в прямых кавычках, наименование банка, метка стороны в
    реквизитах («The Manufacturer: …»).
  - *Распространение по документу:* слово, замаскированное в адресе/имени/
    компании, маскируется везде в документе (закрывает голые города в
    OCR-перемешанных таблицах).
  - *Проверка на выходе* — `quality.py`: независимые широкие детекторы остатков
    (e-mail, телефон, латинский реквизит, длинный номер, URL, SWIFT-подобный код,
    КАПС-компания) + признаки ложных замен (ФИО в кавычках определения, частые
    повторы метки ФИО) → `verdict: ok | needs_review`. Отчёт — только счётчики и
    номера строк. Пишется в `_ready/<имя>.quality.json`, в лог watcher, в шапку
    оригинала образца и в задачу очереди (`anon_quality`).
  - *Идеи стороннего анонимайзера (2026-10-02, код не копировался):*
    контрольные суммы ИНН/ОГРН/ОГРНИП/БИК — реквизит маскируется и без метки,
    число без валидной суммы (номер заказа) не трогается; распространение
    кириллических слов с падежами («Петров» → «Петрову», «Ромашка» → «Ромашке»);
    голый домен без www/http (публичные правовые ресурсы — pravo.gov.ru,
    kad.arbitr.ru, consultant.ru, *.gov.ru — не маскируются ни как домен, ни как
    URL); жёсткий режим в блоке реквизитов (после заголовка «Реквизиты / Подписи
    сторон / Signatures / Bank details»): оторванные от меток номера ≥ 6 цифр и
    коды вида BKCHCNBI9SA. Без заголовка блок не угадывается по объёму текста.
  - *Перепроверка старых образцов (2026-10-05):* ФИО из полных слов (без инициалов
    и отчества) принимается только при известном имени среди слов (рус. — в любом
    падеже, лат. — точно) — иначе «Злоупотребление Истцом», «Управление Росреестра»,
    «Western Blotting» становились ФИО и распространялись по документу; якоря
    «Mr./Ms./Attention:/Name:»; роли сторон (Customer, Supplier…) — не имена;
    дата рождения — отдельный тип `ДАТА_РОЖДЕНИЯ` (маскируется и в профиле без
    дат); маркеры адреса без учёта регистра (шапка иска капсом); «(OKPO) 123…» —
    скобка между меткой и номером; проверка на выходе не считает остатком ссылки
    на публичные правовые ресурсы.
  - *Код разработки препарата (решение юриста 2026-10-06):* код вида «FBGL-010426»
    рядом со словом «препарат / ЛП / drug / product» маскируется как
    `[КОД_ПРЕПАРАТА]` и распространяется по документу (в т. ч. с префиксом).
    Названия продуктов и МНН не маскируются.
  - *Согласованность меток (2026-10-08, по живой проверке проектов):*
    - одно лицо в разных падежах — одна метка `[ФИО_N]`, только для полного ФИО
      из трёх слов с отчеством не на первом месте (отчество различает пол;
      фамилия на «-ич» — «Бабич» — не считается отчеством); ключ — основы слов
      без падежных окончаний; для восстановления — именительный падеж, если
      встречался, иначе первая форма;
    - сдвиг окна: если неполная находка (без инициалов и отчества, кончается
      именем) стоит прямо перед отчеством — «Направляем Иванову Ивану |
      Петровичу», — она началась на слово раньше и отбрасывается; берётся полное
      ФИО. Полное ФИО не сдвигается («Ивановым И. П. Основной долг…»);
    - женское отчество в косвенном падеже («Ивановне», «Павловне», «Юрьевне»,
      «Михайловне», «Львовне») признаётся только при основе-имени (с
      нормализацией: Павл → Павел, Юрь → Юрий, Михайл → Михаил) — прилагательные с
      теми же окончаниями («Основной», «Публичной», «Верховной») не считаются
      отчеством; короткие имена в косвенном падеже («Анну», «Анне») узнаются;
    - номер договора, контракта, соглашения, спецификации, заказа, доверенности
      (в т. ч. англ. Agreement/Contract/Order No.) из цифр («№ 15/2026», «от
      01.03.2026 № 1234», «Purchase Order No. 4521») маскируется как `[НОМЕР_ДОК]`;
      номер от 6 цифр или с разделителем от 5 знаков («15/2026») закрывается во
      всём документе, короткий («№ 4521», «№ 2-15») — только после «№» и не у
      публичного акта (чтобы не задеть «125 дней», «ст. 125», «пункты 2-15»);
      короткий номер без разделителя («ДС № 14»), номера постановлений, приказов,
      указов, решений, дел («по делу № 2-1234/2025») и Executive/Court Order —
      открыты; «договор контрактного производства», «разрешения», «указанного»
      исключениями не считаются; правило стоит последним, чтобы не перехватывать
      счета, телефоны и даты;
    - «+» телефона внутри метки; число в конце документа больше не принимается
      за сумму (голый «$» в шаблоне цены означал «конец текста»).
  - NER-слой: фильтр госорганов/судов/регуляторов (перенесён из
    legal-assistant-v4), длинный текст — по частям, а не молчаливое отключение.
  - Остаточное: голый город без якоря и без повторов в замаскированных фрагментах,
    название приложения/бренда площадки, SWIFT без метки — `quality.py` ловит
    часть; NDA-критичное по-прежнему просматривается глазами.
- Анонимизация с потерей контекста: в профиле `full` LLM не видит сумм и дат —
  анализ сроков/расчётов будет с плейсхолдерами.
- `.doc` (старый формат) не поддерживается — пересохранить в `.docx`.
- **OCR не идеален**: качество зависит от разрешения и чёткости скана; на плохих
  сканах часть реквизитов может быть распознана с ошибками и не замаскирована.
  Скан-документы обезличивать со включённым OCR, но для NDA-критичных — юрист
  сверяет `.anon.md` с оригиналом перед передачей агенту. Без установленного
  Tesseract сканы/изображения уходят в `failed/`, а не обрабатываются молча.
- mapping.json содержит реальные значения — живёт только в `workflow/`
  (gitignored), в контекст LLM не передаётся.
