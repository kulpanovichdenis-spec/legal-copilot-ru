# tools/corporate_governance — корпоративный слой (Entity Governance)

Детерминированное ядро класса A для модуля «Corporate Governance». Хранит профиль компании, правила из устава, реестр документов и аудит; проверяет схему и provenance; считает проекции. Правовых выводов не делает: квалификацию по закону и оценку конфликтов выполняет агент по `skills/charter-review/SKILL.md`, решение принимает юрист. Методика — `references/corporate-governance-method.md`.

Данные компании: `profile/knowledge/corporate/entities/<slug>/` (`sources.yaml`, `rules.yaml`, `profile.yaml`, `audit.jsonl`, `_work/`). Каталог можно переопределить параметром `--entities-dir`.

## Команды

Запуск: `python tools/corporate_governance/governance.py <команда> --slug <slug> ...`; `validate-cards` и `selftest` `--slug` не принимают (полный список: `--help`).

| Команда | Что делает |
|---|---|
| `init-entity` | заводит компанию: папка и пустые yaml |
| `register-source` | регистрирует документ (`--kind`, `--file` относительно `corporate/`, число страниц PDF определяется само) |
| `update-source` | уточнить реквизиты документа: название, вид (`--kind`, если зарегистрирован неверно), дата редакции, запись ЕГРЮЛ (`--grn` с `--grn-date`); смена редакции снимает статус `current` |
| `set-source-status` | статус источника вручную; `current` требует `--basis` (чем подтверждена актуальность) и `--by` (ФИО юриста, не роль) |
| `supersede-source` | новая редакция заменяет старую; правила и факты старой переходят в `needs_review` |
| `fetch-egrul` | получает официальную выписку ЕГРЮЛ с egrul.nalog.ru по ОГРН/ИНН (`gov_egrul.py`), кладёт в `originals/`, регистрирует `egrul_extract`, пишет текст страниц для `verify-quotes`; при отказе ФНС объясняет ручной путь |
| `check-edition` | сверяет ГРН на уставе с последней действующей записью об учредительном документе в выписке: совпало — `current` по выписке, есть более поздняя — `current` снимается |
| `egrul-summary` | из выписки: лица без доверенности, участники и доли, последняя запись об уставе (со страницами) |
| `render-pages` | PDF → PNG страниц и текст в `_work/<source>/`: текстовый слой PDF, если он есть на каждой странице, иначе локальный OCR |
| `add-rule`, `update-rule` | правило из документа со страницей, пунктом и дословной цитатой; кандидат |
| `set-freshness` | результат Legal Freshness Check по правилу (нужен заданный `law_ref`; `--checked-source` по умолчанию `pravo-gov-ru`, для другого provider указывать явно) |
| `add-fact`, `update-fact` | факт профиля компании (классификация, участники, органы, назначения) |
| `add-assumption` | допущение вместо молчаливого стандартного правила |
| `resolve-assumption` | снимает допущение, когда недостающее получено (`--basis`, `--source-id`); запись остаётся, в отчётах — отдельной строкой «Снятые допущения» |
| `verify-quotes` | нечёткая сверка цитат с OCR-текстом страниц (порог 0,90) |
| `inconsistencies` | кандидаты на внутренние противоречия (лид, не вывод) |
| `stale` | правила без проверки нормы или с устаревшей проверкой (`--days`, по умолчанию 30) |
| `confirm` | переводит записи в `verified` по решению юриста (`--by`); отказы объясняются |
| `validate` | схема, provenance, ссылки и дубли |
| `report` | проекции (`--view`: competence, voting, meetings, confirmation, other, profile, inconsistencies, all) в markdown или `.docx` (`--format docx --out <файл>`) |
| `validate-cards` | проверка карточек-указателей норм `references/corporate-norm-cards/llc/` |
| `selftest` | сквозной сценарий на временной папке |

### Реестр группы и корпоративные списки

Реестр группы `profile/knowledge/corporate/group/group.yaml` не привязан к одной компании: команды `group-*` идут без `--slug` и берут блокировку реестра сами. Методика: `references/corporate-lists-method.md`.

| Команда | Что делает |
|---|---|
| `group-sync` | выписка ЕГРЮЛ (`--ogrn` с egrul.nalog.ru или `--file` уже скачанная) → общество, участники с датами записей об участнике и о размере доли, ЕИО; выбывшие закрываются датой выписки «не позднее» |
| `group-add` | завести или изменить лицо (`--key` для существующего); иностранный номер, страна, доля общества, прекращение (`--closed` дата или год) |
| `group-link` | отрезок владения долей; пересекающийся отрезок отклоняется, тот же отрезок обновляется |
| `group-officer` | ЕИО или член совета директоров с датами |
| `group-relative` | родственная связь физических лиц (п. 7 ч. 1 ст. 9 Закона № 135-ФЗ) |
| `group-pbu11` | участник совместной деятельности или НПФ для перечня связанных сторон; `--none`, если таких лиц нет (перечень покажет «нет» с источником вместо маркера) |
| `group-show` | реестр и аффилированные лица общества на дату |
| `group-lists` | четыре черновика `.docx`: список аффилированных лиц (журнал изменений с `--period-start`), перечень связанных сторон (за `--related-start`…`--related-end`, по умолчанию тот же период; `--related-without-leavers` — без выбывших в периоде), список участников, схема владения |

У ручных команд `--source` обязателен.

Значения: `--value "текст"` (для правила сохраняется как `{"text": ...}`) или `--value-json '{"text": "...", "amount": 30}'`. Команды с JSON запускайте из Bash: PowerShell портит кавычки в аргументах.

### Компетенция (competence-engine)

Каталог типовых решений ООО — `references/corporate-decisions/llc.yaml` (общий слой, правится только по указанию юриста).

| Команда | Что делает |
|---|---|
| `validate-catalog` | проверка каталога решений (без `--slug`) |
| `tag-decisions` | привязка правила к позициям каталога (`--rule-id` с `--add`/`--remove` или `--map` yaml); снимает подтверждение правила |
| `competence` | по позиции каталога: привязанные правила, допущения, давность проверок норм, статус `BLOCKED`/`NEEDS_FRESHNESS`/`NEEDS_REVIEW`/`ASSUMPTION`/`RESOLVED`; `--decision` можно повторить |
| `decisions-review` | `.docx` юристу: правила по позициям каталога и правила без привязки |

`validate --catalog <файл>` сверяет привязки `decisions` с каталогом.

После замены редакции устава (`supersede-source`) правила старой редакции дают `BLOCKED`: снимите с них привязку (`tag-decisions --remove`) и привяжите правила новой редакции.

## Тесты

```bash
python -m pytest tools/corporate_governance -q
python tools/corporate_governance/governance.py selftest
```

Тесты на настоящем OCR пропускаются, если на машине нет tesseract или шрифта с кириллицей. Локальный tesseract ищется по цепочке `TESSERACT_CMD`, PATH, стандартные каталоги установки (`tools/doc_ingest/ocr_tesseract.py`).

## Модули

| Файл | Ответственность |
|---|---|
| `gov_schema.py` | перечни допустимых значений и валидаторы (единственный источник схемы) |
| `gov_quotes.py` | нормализация и нечёткая сверка цитат |
| `gov_store.py` | yaml-файлы компании, идентификаторы, append-only аудит, блокировка компании (`.lock`) |
| `gov_views.py` | проекции, кандидаты противоречий, отчёт `stale`, markdown |
| `gov_docx.py` | сборка `.docx` по профилю «аналитическая заметка» (`tools/docx_style`) |
| `gov_cards.py` | проверка карточек-указателей норм |
| `gov_egrul.py` | получение выписки ЕГРЮЛ с egrul.nalog.ru (шаги формы ФНС, без браузера, капча не обходится) и разбор её текстового слоя; годится и для других модулей |
| `gov_group.py` | реестр группы: лица, отрезки владения, должности; перенос выписки ЕГРЮЛ в реестр |
| `gov_group_calc.py` | группа лиц, аффилированные лица с датами оснований, журнал изменений, связанные стороны (чистые функции) |
| `gov_group_docx.py` | четыре документа по реестру группы и схема владения (SVG → PNG через PyMuPDF) |
| `make_norm_cards.py` | генератор скелетов карточек по темам таксономии (существующие не перезаписывает) |
| `gov_cmd_*.py` | команды CLI по группам; `governance.py` собирает парсер |
