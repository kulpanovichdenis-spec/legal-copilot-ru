# Реестр договоров (contract_registry)

Досье договора: реестр ключей, папка с подписанными документами, карта изменённых пунктов, связь с задачами. Правила работы юриста — `references/contract-dossier-usage.md`. Тексты договоров и ДС в досье не правятся; агент только читает кеш текста и пишет через CLI.

## Структура досье

Корень реестра по умолчанию: `workflow/_contracts/` основного чекаута (`--root` переопределяет). Из git worktree реестр тоже берётся в основном чекауте (через `git rev-parse --git-common-dir`), поэтому `--task` должен быть путём внутри его `workflow/` (абсолютным, если команда запущена из worktree). Реестр ключей — `registry.yaml` в корне. Папка досье: `<ключ> <контрагент>`.

```
workflow/_contracts/
  registry.yaml                  # ключи договоров, алиасы, ИНН, временные ключи
  <ключ> <контрагент>/
    contract-card.md             # карточка договора (frontmatter + 9 разделов), card_status: draft|reviewed, reviewed_hash
    documents.yaml               # перечень документов: id, file, text, kind, status, evidence, sha256, relations, ...
    docs/                        # копии подписанных документов (исходные файлы)
    _text/D-001.txt.md           # кеш текста по id документа (для сверки цитат; у сканов — OCR-текст)
    amendments.yaml              # карта изменённых пунктов: clauses -> исходная редакция, changes
    links.yaml                   # задачи, черновики, конфликты с досье
    matter-timeline.yaml         # хронология дела (tools/matter_model)
```

`documents.yaml` — статус `signed` требует `evidence` (скан, ЭДО, слово юриста); `unconfirmed` допускается без него. Документы с одинаковым sha256 не добавляются повторно (`result: exists`). Необязательное поле `relations: [{type, target, quote, quote_check}]` хранит связи документа-источника (`amends`, `supersedes`, `annex_to`); записи без него валидны.

## Команды CLI

Запуск из корня репозитория: `python -m tools.contract_registry <команда> [--root PATH]`. Вывод — JSON (UTF-8).

| Команда | Назначение | Пример |
|---|---|---|
| `lookup QUERY` | поиск в реестре: ключ и алиас-номер дают `exact`; ИНН и название контрагента только `partial` | `python -m tools.contract_registry lookup "Д-200-2026"` |
| `init --key --counterparty [--inn] [--alias ...] [--temporary]` | завести досье (карточка-скелет, пустые реестры, хронология); ключ или `--alias`, совпавший после нормализации с ключом или алиасом другого досье, отвергается с именем его папки | `... init --key "Д-200-2026" --counterparty "Альфа"` |
| `add-doc --key --file --kind --status [--evidence] [--date]` | добавить документ: копия, хеш, кеш текста; id `D-00N` это максимальный номер + 1; `--date` только `ГГГГ-ММ-ДД` или пусто (иначе код 2) | `... add-doc --key Д-200-2026 --file "Договор.docx" --kind contract --status signed --evidence скан` |
| `set-doc-status --key --doc --status signed\|unconfirmed [--evidence]` | подтвердить подписание добавленного документа (или вернуть `unconfirmed`); `signed` требует непустой `--evidence`; если карточка была `reviewed`, она возвращается в `draft` (в ответе `card_note`) | `... set-doc-status --key Д-200-2026 --doc D-002 --status signed --evidence "скан с подписями"` |
| `sync-check --key --task` | сверить папку задачи с досье по хешам; файлы блокировки Word `~$*` пропускаются (`--task` только внутри папки `workflow/`, где лежит `--root`, и не внутри `_contracts`) | `... sync-check --key Д-200-2026 --task "workflow/<папка задачи>"` |
| `rename-key --old --new` | переименовать временный ключ (старый остаётся алиасом; строки `key:` и `number:` карточки и `matter:` хронологии меняются на новый ключ); пустой ключ отвергается; при сбое папка и реестр остаются как были | `... rename-key --old "Альфа 2026-11-19" --new Д-200-2026` |
| `link-task --key --task` | связать задачу с досье и обновить `case-context.md`: в `contracts:` пишется канонический ключ реестра, даже если найден по алиасу (`--task` только внутри папки `workflow/`, где лежит `--root`, и не внутри `_contracts`) | `... link-task --key Д-200-2026 --task "workflow/<папка задачи>"` |
| `add-draft --key --task --file` | записать черновик задачи в `links.yaml` (`--task` с теми же ограничениями, что у `link-task`; хранится имя папки) | `... add-draft --key Д-200-2026 --task "workflow/<папка задачи>" --file "ДС 2 черновик.docx"` |
| `add-conflict --key --field --dossier-value --new-value --source` | зафиксировать расхождение досье и нового источника (id `K-00N`: максимальный номер + 1) | `... add-conflict --key Д-200-2026 --field "Цена" --dossier-value "1 000 000" --new-value "1 200 000" --source "ДС 1"` |
| `amend-clause --key --clause --doc --quote --location` | зафиксировать исходную редакцию пункта | `... amend-clause --key Д-200-2026 --clause "4.1" --doc D-001 --quote "Цена работ составляет 1 000 000 рублей." --location "раздел 4"` |
| `amend-change --key --clause --doc --quote --location [--date]` | зафиксировать изменение пункта документом любого статуса; изменение из `unconfirmed` в `current` идёт как `pending`. Порядок вызовов `amend-change` по пункту это хронология изменений: `current` берёт последнее по порядку из `signed` | `... amend-change --key Д-200-2026 --clause "4.1" --doc D-002 --quote "Цена работ составляет 1 200 000 рублей." --location "п. 1" --date 2026-11-19` |
| `link-doc --key --doc --type amends\|supersedes\|annex_to --target --quote` | связать документ-источник `--doc` с `--target`; цитата из `--doc` обязательна (не короче 3 слов или 15 символов) и должна дословно быть в кеше `--doc` (цитата только из `--target` отвергается; что цитата называет `--target`, проверяют агент и юрист по `summary`/`chain`); отвергаются (код 2) неизвестный id, связь на себя, дубль, цикл `amends`/`supersedes`, `amends` от документа не вида `amendment`/`disagreement_protocol`, `annex_to` от документа не вида `annex`/`specification` или к документу не вида `contract`, `amendment`, `disagreement_protocol`, `supersedes` между разными семействами видов (договор и протокол разногласий / ДС / приложение и спецификация); `reviewed` карточка возвращается в `draft` (`card_note`). `add-doc` не меняется: `link-doc` вызывается сразу после него | `... link-doc --key Д-200-2026 --doc D-002 --type amends --target D-001 --quote "к Договору № Д-200-2026 от 01.10.2026"` |
| `unlink-doc --key --doc --type --target` | снять связь (нет такой связи: код 2); `reviewed` карточка возвращается в `draft` | `... unlink-doc --key Д-200-2026 --doc D-002 --type amends --target D-001` |
| `chain --key` | цепочка редакций: `contracts` — договоры и протоколы разногласий без исходящих связей или только с `supersedes` (`supersedes` — id заменяемых документов); у каждого `amendments` (ДС, сводящиеся к нему, по дате, без даты — после датированных, затем по id, со `status`, `amends`, `superseded`, `superseded_by`), `relations` (связи с цитатой: `type`, `target`, `quote`; есть и у главного документа), `annexes` (id документа → `[{doc, quote}]`), `supersessions` (кто кого заменяет, статус, цитата); `unlinked` — документы, не сводящиеся ни к одному главному (ДС без `amends`, приложение без `annex_to`); ДС, заменивший другой ДС, остаётся в цепочке своего договора; через другой главный документ цепочка не идёт (ДС к новой редакции не попадает к заменённому договору) | `... chain --key Д-200-2026` |
| `current --key` | текущая редакция каждого изменённого пункта, только из `signed`; у пункта `source_status` (статус документа, из которого взят `text`), `quote_check`, `pending` и `superseded`. Исходная редакция из неподписанного договора идёт с его id в `pending` и `source_status: unconfirmed`. Изменение из документа, заменённого подписанным (`supersedes`), не действует и идёт в `superseded`. Если документ исходной редакции пункта заменён подписанным документом: `text` из подписанной незаменённой новой редакции, заменяющей его (прямо или через цепочку `supersedes`), или из ДС к ней даёт `source_status: signed` и пустой `superseded`; `text` из заменённой редакции или ДС к ней даёт `source_status: superseded` и id исходного документа в `superseded` | `... current --key Д-200-2026` |
| `validate --key` | вывод `{"errors": [...], "warnings": [...]}`; предупреждения (ДС без связей; ДС из карты изменений без пути `amends` или `supersedes` к документу исходной редакции; приложение или спецификация без `annex_to`) код выхода не меняют; ошибки связей (неизвестный документ или тип, цикл, связь на себя, дубль связи, вид документов не подходит связи, цитата не подтверждена) — ошибки. Проверка карточки (форма; у каждого пункта списка ссылка D-00N из `documents.yaml` или маркер `[ПРОВЕРИТЬ …]`; цитата «…» после ссылки сверяется с кешем; в разделах «Стороны», «Цена и порядок оплаты», «Срок действия и пролонгация», «Ответственность и неустойки», «Применимое право и споры» цитата обязательна после каждой ссылки и не короче 3 слов или 15 символов; ссылка на документ не `signed` или на документ, заменённый подписанным (`supersedes`), требует маркера `[ПРОВЕРИТЬ`; строка в разделе поля не пунктом списка это ошибка; `key` карточки должен совпадать с ключом реестра; у `reviewed` карточки, изменённой после проверки, ошибка «карточка изменена после проверки юристом»; битый frontmatter это ошибка валидации, а не сбой), карты изменений и хронологии | `... validate --key Д-200-2026` |
| `summary --key` | предпросмотр для юриста: поля карточки (`fields`: раздел и строка пункта как написана), документы (id, файл, вид, статус, дата, признак подписания, `superseded_by`: подписанные документы, которые его заменяют), `relations` (id документа → его связи), `card_status`, число маркеров `[ПРОВЕРИТЬ`, открытые расхождения, `warnings` (в т. ч. «карточка изменена после проверки юристом») | `... summary --key Д-200-2026` |
| `set-card-status --key --status reviewed\|draft` | сменить `card_status` карточки; тело файла не меняется. `reviewed` отвергается (код 2), если полный `validate` (карточка, поправки, хронология) находит ошибки или есть открытые расхождения; при `reviewed` во frontmatter пишется `reviewed_hash` (sha256 тела и полей counterparty, our_party, number, date, aliases, key; `summary` показывает их в `frontmatter`), `draft` его удаляет | `... set-card-status --key Д-200-2026 --status reviewed` |

Цитаты в `amend-clause` и `amend-change` проверяются строго: каждая цитата должна дословно присутствовать в тексте документа. Копируйте цитату из кеша `_text/<doc_id>.txt.md`, а не с бумажного оригинала; для сканов кеш содержит OCR-текст, поэтому цитируется он.

### `link-task` и поле `case_context`

`link-task` всегда добавляет задачу в `links.yaml` и возвращает `{"case_context": ...}`:

- `updated` — ключ дописан в `contracts:` фронтматтера `case-context.md` задачи;
- `already` — ключ уже есть в `contracts:`, файл не менялся;
- `missing` — нет `case-context.md`, фронтматтера или закрывающей `---`; файл не создаётся;
- `manual` — форма `contracts:` не разобрана безопасно; файл не тронут, связь вносит юрист вручную.

## Коды выхода

- `0` — успех;
- `1` — ошибки валидации (`validate`): вывод `{"errors": [...], "warnings": [...]}`;
- `2` — `RegistryError` или `ForbiddenPath` (ошибка данных, нарушение правил); текст в stderr с префиксом `ОШИБКА:`. Пути внутри `workflow/_anonymizer/` не обрабатываются: досье по ним не ведётся.
