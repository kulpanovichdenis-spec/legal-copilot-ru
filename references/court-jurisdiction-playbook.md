# Court Jurisdiction Playbook — индекс-роутер нормативного resolver'а

Это **нормативная часть** `court-jurisdiction-resolver` (ТЗ §2.1): факты дела → компетенция → процессуальный режим → родовая подсудность → территориальная подсудность → jurisdiction anchor. Online-часть (конкретный суд, адрес, реквизиты) — `references/court-online-resolver.md`. Расчёт госпошлины — `tools/court_jurisdiction/state_duty.py` + `references/court-jurisdiction-response-schema.md`.

**Правило подгрузки: не читать все карточки.** Пройти общую логику ниже (routers, gates, priority engine), затем открыть только карточки спецкатегорий, которые сработали по таблице триггеров в конце файла — обычно 1-3 из 16.

**Статус проверки норм (2026-09-16).** Родовая структура глав о подсудности АПК/ГПК/КАС (номера статей, деление на уровни судов) — устойчивая многолетняя структура кодексов, не менявшаяся в последних масштабных редакциях; отдельно **верифицированы дословно** в ходе сборки этого playbook: пороги ст. 23 ГПК РФ (50 000 / 100 000 руб.) и существование Пленума ВС РФ № 39 от 23.12.2025. Специальные/более редкие нормы (санкционная ст. 248.1-248.2 АПК, компетенция СИП, банкротные нормы) отмечены в карточках как требующие сверки редакции юристом перед использованием — `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ РЕДАКЦИИ]`.

## 1. Общий порядок (ТЗ §12, сжато)

```
факты → fact sufficiency gate → procedural form gate → foreign element gate
→ court system router → procedural regime → special competence (карточки)
→ родовая подсудность → территориальная подсудность (priority engine P0-P9)
→ jurisdiction anchor → [online resolver — отдельный reference] → госпошлина
```

Каждый переход — это отдельное **утверждение с собственным основанием** (ТЗ §121): «спор относится к этой системе судов» ≠ «компетентен суд такого уровня» ≠ «эту территорию сейчас обслуживает такой-то суд» ≠ «сейчас для оплаты опубликованы такие-то реквизиты». Смешивать нормативный вывод и online-подтверждение в одном шаге запрещено.

## 2. Fact model и provenance (ТЗ §8-11)

Каждый существенный факт — со своим provenance: `value`, `source_type` (`user`/`document`/`registry`/`inferred`), `source`, `confidence`. **Запрещено достраивать предположение до факта** — сумма требования не подразумевает автоматически природу правоотношения; неизвестная природа спора → `status: INSUFFICIENT_DATA`, а не «наиболее вероятная» квалификация.

### Fact Sufficiency Gate

Различать `missing_non_material_fact` (не блокирует) и `missing_jurisdiction_material_fact` (блокирует финальный вывод). Material facts как минимум: предмет требования, характер правоотношения, адрес ответчика, местонахождение недвижимости (если применимо), наличие jurisdiction/arbitration clause, цена иска (если влияет на мировой/районный уровень), иностранный элемент, число ответчиков. Не хватает material fact → `INSUFFICIENT_DATA` с явным перечнем `missing`, а не «наиболее вероятный» суд.

## 3. Procedural Form Gate (ТЗ §6)

До запуска resolver'а проверить, действительно ли это иск, а не:

| Альтернатива | Признак | Действие |
|---|---|---|
| Судебный приказ | Бесспорное требование из перечня ст. 122 ГПК РФ / ст. 229.2 АПК РФ (задолженность по договору, алименты без спора об отцовстве, начисленная зарплата и т. п.) | WARNING: требование может относиться к приказному производству; resolver продолжает работу, но перед составлением иска нужно проверить допустимость исковой формы |
| Административный иск | Оспаривание решения/действия/бездействия органа власти, публичное полномочие ответчика | → КАС-router (§7 ниже), не ГПК |
| Особое производство | Установление факта, признание безвестно отсутствующим и т. п. — нет спора о праве | WARNING: особое производство, не исковое |
| Банкротное заявление | Признаки несостоятельности, включение в реестр, оспаривание сделки должника | → карточка `bankruptcy` |
| Третейское разбирательство | Действующая арбитражная оговорка | → карточка `arbitration_agreements` до основного resolver'а |

Skill не разрешает альтернативную процедуру полностью — только предупреждает и продолжает определение суда для избранной формы.

## 4. Foreign Element Gate (ТЗ §32)

`foreign_element: true` (иностранная сторона, иностранное место исполнения, санкционный статус) блокирует прямой переход к территориальной подсудности внутри РФ. Сначала — международная компетенция российских судов:

- **АПК**: гл. 32 АПК РФ (ст. 247-248) — общие правила международной подсудности по экономическим спорам с иностранным участием; отдельно **ст. 248.1-248.2 АПК РФ** — исключительная компетенция российских арбитражных судов по отдельным санкционным спорам. `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ РЕДАКЦИИ]` — предмет частых уточнений практики ВС РФ, сверить действующую редакцию и практику применения перед выводом.
- **ГПК**: разд. V ГПК РФ (ст. 402-406) — подсудность дел с участием иностранных лиц.
- **КАС**: ст. 25 КАС РФ — производство по административным делам с участием иностранного лица.

Подробности и триггеры — карточка `foreign_parties`; санкционная специфика — карточка `sanctions`.

## 5. Court System Router (ТЗ §7, §13-16)

**Запрещена упрощённая логика** «ООО против ООО = арбитраж», «физлицо = СОЮ», «госорган = КАС», «есть ТЗ/патент = СИП». Статус сторон — один из факторов, не единственный.

| Кодекс | Стартовая норма | Логика |
|---|---|---|
| **АПК** | ст. 27-33 АПК РФ (гл. 4) | Экономический характер спора + предпринимательская/иная экономическая деятельность, либо специальная компетенция по прямому указанию закона (независимо от статуса стороны — корпоративные, банкротство, часть IP-споров, СИП-категории). Третейские споры и вопросы содействия/контроля за третейским разбирательством — тоже в этой главе (ст. 33 АПК РФ) |
| **ГПК** | ст. 22 ГПК РФ | Гражданские, семейные, трудовые, жилищные, земельные, экологические и иные частноправовые споры, **за прямым исключением** дел, отнесённых к компетенции арбитражных судов. Для связанных требований разной подсудности — отдельное правило (см. §9 ниже, карточка `connected_claims`) |
| **КАС** | ст. 1, 17 КАС РФ | Требуется одновременно: публичное правоотношение + ответчик реализует публичное полномочие + оспаривается именно реализация этого полномочия + спор не относится к арбитражной компетенции. Наличие госоргана как стороны — недостаточно само по себе (гражданско-правовой договор с госорганом ≠ административный спор — карточка `public_law`) |

Порядок проверки: сначала — не относится ли спор к прямо перечисленной специальной компетенции АПК (§9 ниже) **независимо от того, что интуитивно выглядит как «обычный гражданский спор»**; затем — экономический характер + субъекты (АПК общий критерий); затем — публично-правовая природа (КАС); residual — ГПК.

## 6. Special Competence — карточки (ТЗ §114)

После определения предварительной ветки (АПК/ГПК/КАС) — обязательно проверить триггеры специальных категорий **до** перехода к родовой/территориальной подсудности, так как они меняют и то, и другое.

| Триггер в фактах дела | Карточка | Меняет |
|---|---|---|
| Спор между участниками юрлица, корпоративный конфликт, оспаривание решений органов управления | [corporate](court-jurisdiction-cards/corporate.md) | Компетенция (АПК даже при физлице-стороне) |
| Признаки несостоятельности, требование в деле о банкротстве, оспаривание сделки должника, субсидиарная ответственность | [bankruptcy](court-jurisdiction-cards/bankruptcy.md) | Компетенция + отдельный суд + госпошлина |
| Товарный знак, патент, авторское право, доменный спор, акт Роспатента | [ip](court-jurisdiction-cards/ip.md) | Родовая подсудность (СИП vs обычный арбитраж/СОЮ) |
| Права на земельный участок, здание, помещение | [real_estate](court-jurisdiction-cards/real_estate.md) | Исключительная территориальная подсудность |
| Истец — потребитель (Закон о защите прав потребителей) | [consumer](court-jurisdiction-cards/consumer.md) | Альтернативная территориальная + льгота по пошлине |
| Трудовой спор (работник/работодатель) | [labor](court-jurisdiction-cards/labor.md) | Альтернативная территориальная + льгота по пошлине |
| Брак, дети, алименты, раздел имущества супругов | [family](court-jurisdiction-cards/family.md) | Родовая (мировой при разделе ≤ 50 000) + альтернативная территориальная |
| Наследство, открытие наследства | [inheritance](court-jurisdiction-cards/inheritance.md) | Исключительная территориальная (место открытия наследства) |
| Военнослужащий, воинская часть, командир как ответчик | [military](court-jurisdiction-cards/military.md) | Компетенция (военные суды) |
| Госорган/муниципальный орган как ответчик, оспаривание акта/действия/бездействия | [public_law](court-jurisdiction-cards/public_law.md) | АПК vs КАС |
| Иностранная сторона, иностранное место исполнения | [foreign_parties](court-jurisdiction-cards/foreign_parties.md) | Международная компетенция (P0) |
| Санкционный статус стороны, невозможность судебной защиты за рубежом | [sanctions](court-jurisdiction-cards/sanctions.md) | Исключительная компетенция РФ (ст. 248.1-248.2 АПК) |
| Договор содержит оговорку о суде или третейском разбирательстве | [arbitration_agreements](court-jurisdiction-cards/arbitration_agreements.md) | P6 (договорная) или блокирует госсуд (третейская) |
| Более одного ответчика | [multiple_defendants](court-jurisdiction-cards/multiple_defendants.md) | Выбор из нескольких надлежащих подсудностей |
| Несколько связанных требований разной подсудности/природы | [connected_claims](court-jurisdiction-cards/connected_claims.md) | Объединение или разделение |
| Ответчик — филиал/представительство, спор из его деятельности | [branches](court-jurisdiction-cards/branches.md) | Альтернативная территориальная (по месту нахождения филиала) |

Несколько триггеров сработали одновременно (например, корпоративный спор с иностранным элементом) — применяются все релевантные карточки последовательно (сначала Foreign Element Gate, затем остальные), конфликт результатов → `MANUAL_REVIEW_REQUIRED` (§13 ниже).

## 7. Родовая подсудность по регламентам (ТЗ §18-24)

### ГПК (residual — районный суд)

```
special jurisdiction (карточки §6)? → ВС РФ (ФКЗ о Верховном Суде, ст. 27 ГПК отсылочная)?
→ суд субъекта (ст. 26 ГПК РФ + спецнормы)? → военный суд (карточка military)?
→ мировой судья (ст. 23 ГПК РФ)? → районный суд (residual)
```

**Мировой судья** (ст. 23 ГПК РФ, verified 2026-09-16): судебные приказы; расторжение брака без спора о детях; раздел имущества супругов при цене иска ≤ 50 000 руб.; обычные имущественные споры при цене иска ≤ 50 000 руб. (кроме наследства и ряда IP-категорий); потребительские имущественные споры при цене иска ≤ 100 000 руб. **Цена иска — не единственный classifier**: наследство и IP-категории уходят в районный суд независимо от суммы (карточки `inheritance`, `ip`).

Запрещённые упрощения: «первая инстанция СОЮ → всегда районный суд» (не проверив ст. 26 и спецнормы), «мировой судья определяется только ценой иска» (не проверив предмет).

### КАС (residual — районный суд)

```
мировой судья? → военный суд? → суд субъекта (гл. 2 КАС РФ)?
→ Верховный Суд РФ? → районный суд (residual)
```

Глава 2 КАС РФ (ст. 17-21) прямо распределяет категории между уровнями; не заменять её общими правилами ГПК.

### АПК

```
special first-instance rule (СИП — карточка ip; окружной суд как первая инстанция — редкие прямые указания закона)?
→ ДА: специальный суд
→ НЕТ: арбитражный суд субъекта РФ (общее правило)
```

### Верховный Суд РФ как суд первой инстанции

Отдельная проверка по ФКЗ «О Верховном Суде Российской Федерации» — ст. 27 ГПК РФ сама отсылает определение этой подсудности к ФКЗ, не содержит исчерпывающего перечня внутри себя. Требует прямого указания закона; не выводится по аналогии.

## 8. Территориальная подсудность — priority engine (ТЗ §34-38)

Правила проверяются **строго в этом порядке**, не в произвольном:

```
P0 — международная компетенция (Foreign Element Gate, §4 выше), если есть иностранный элемент
P1 — специальная исключительная компетенция (санкции ст. 248.1-248.2 АПК — карточка sanctions)
P2 — судебная система / процессуальный режим (уже определены выше)
P3 — родовая подсудность (уже определена выше)
P4 — исключительная территориальная подсудность (недвижимость, наследство — карточки real_estate, inheritance)
P5 — специальные территориальные правила (карточки: consumer, labor, branches, multiple_defendants, connected_claims)
P6 — договорная подсудность (карточка arbitration_agreements, только если допустима — не отменяет P1-P5)
P7 — альтернативная подсудность (§39-40 ниже)
P8 — связанные требования / несколько ответчиков (карточки multiple_defendants, connected_claims — если ещё не закрыли вопрос на P5)
P9 — общая территориальная подсудность (ниже)
```

**Почему договорная подсудность не проверяется первой (ТЗ §35):** найденная в договоре оговорка о суде не отменяет автоматически родовую подсудность, специальную компетенцию или исключительную территориальную подсудность. Порядок: сначала подтвердить, что оговорка вообще юридически допустима в данной категории спора (исключительная подсудность и некоторые публично-правовые категории не могут быть изменены соглашением сторон), и только затем применять её как основание P6.

### Общая территориальная подсудность (P9)

| Регламент | Норма | Правило |
|---|---|---|
| ГПК | ст. 28 ГПК РФ | физлицо-ответчик → место жительства; организация-ответчик → адрес организации |
| АПК | ст. 35 АПК РФ (общее) + ст. 36 (выбор истца) + ст. 37 (договорная) + ст. 38 (исключительная) — гл. 4 АПК | по адресу/месту жительства ответчика, с учётом ст. 36 при выборе истца |
| КАС | ст. 22 (общее) + ст. 23 (исключительная) + ст. 24 (выбор административного истца) + ст. 25 (иностранные лица) + ст. 26 (связанные дела) | собственный территориальный блок — не подменять положениями ГПК |

## 9. Несколько допустимых судов (ТЗ §39-40)

Закон даёт истцу выбор → resolver возвращает **все юридически допустимые варианты**, `recommended_court: null`. Skill отвечает на вопрос «какие суды юридически допустимы», не «какой суд стратегически лучше» (это отдельный workflow, не входит в scope). Автоматический выбор одного варианта запрещён — см. `references/court-jurisdiction-response-schema.md`, раздел «Альтернативная подсудность».

## 10. Jurisdiction Anchor и адрес (ТЗ §41-44)

```yaml
jurisdiction_anchor:
  type: defendant_residence | defendant_registered_address | claimant_residence
      | property_location | place_of_performance | branch_location
      | public_authority_address | corporate_entity_address | debtor_address
      | inheritance_opening_place | other
  raw_value:
  normalized_value:
  source:
```

- **Адрес организации** — предпочтительно актуальный зарегистрированный адрес, не адрес из старого договора. Есть доступ к реестровой проверке (ЕГРЮЛ/ЕГРИП через `counterparty-check`/DaData) — сверить; расхождение с договором → WARNING в финальном выводе, с указанием, какой адрес использован для подсудности.
- **Нормализация адреса** — разложить минимум на `country/region/district/municipality/city/settlement/street/house/building/structure/apartment`. Номер дома, корпус, строение — **не отбрасывать**: официальный сервис Москвы (`mos-gorsud.ru/territorial`) требует их напрямую для корректного определения подсудности.
- **Неполный адрес** (например, «ул. Ленина, Москва» без номера дома, когда для вывода нужен конкретный районный суд) → `INSUFFICIENT_DATA`, `missing: [house_number]`. Запрещено выбирать «наиболее вероятный» районный суд по названию улицы.

## 11. Confidence / Status Model (ТЗ §84-89)

Семантические статусы, не число:

| Статус | Условие |
|---|---|
| `CONFIRMED` | Все условия §12 `court-jurisdiction-response-schema.md` «Definition of Done» выполнены одновременно (юридический + суд + госпошлина + реквизиты) |
| `LEGAL_CONFIRMED_OPERATIONAL_UNVERIFIED` | Нормативный вывод завершён, online-подтверждение (конкретный суд/адрес/реквизиты) недоступно или не выполнено |
| `AMBIGUOUS` | Конкурирующие квалификации, неясная оговорка, несколько допустимых толкований нормы |
| `INSUFFICIENT_DATA` | Не хватает jurisdiction-material факта (§2 выше) |
| `MANUAL_REVIEW_REQUIRED` | Конфликт правил одного приоритета (§12 ниже), конфликт официальных источников, нестандартная спецнорма |
| `BLOCKED` | Процессуальная форма явно недопустима (например, третейская оговорка исключает госсуд без её оспаривания) |

## 12. Conflict Detector (ТЗ §118)

Если два правила одного приоритета в priority engine (§8) дают разные результаты — это не решается моделью «на глаз». Результат автоматически `MANUAL_REVIEW_REQUIRED` с явным указанием обоих правил и обеих норм-оснований.

## 13. Versioning (ТЗ §94-96)

Нормативные правила с датированными порогами (мировой судья — ст. 23 ГПК; специальные суммовые критерии) фиксируются как versioned rule object с `effective_from`/`effective_to`/`last_verified`/`source` — по образцу `tools/court_jurisdiction/rules/state_duty_rates.yaml`. Изменение нормы создаёт новую версию, не переписывает существующую. На дату сборки (2026-09-16) отдельного YAML-реестра для территориальных/родовых правил не создано (в отличие от госпошлины) — правила живут как текст в этом playbook и картах; при первом практическом расхождении с нормой (правка после жалобы юриста) — вынести в versioned YAML по этому же образцу.
