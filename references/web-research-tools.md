# Web Research Tools — общий слой веб-инструментов

Базовый reference для **любого web-поиска** в работе проекта: судебная практика, актуальность норм, проверка контрагента, разъяснения госорганов, отраслевая практика, скачивание актов.

Используется всеми skill-ами (см. раздел «Поиск информации» в каждом SKILL.md). Не привязан к конкретной задаче — это **инструментальный слой**, на котором строятся специализированные протоколы (например, `trademark-search-automation.md` для ТЗ-поиска).

**Никаких выдуманных данных.** Если инструмент не вернул результат — так и пишется. Маркер `[ИНСТРУМЕНТ НЕДОСТУПЕН]` для среды без штатной автоматизации.

## 1. Доступные инструменты

| Инструмент | Что делает | Среды | Лимиты | Лучше всего для |
|---|---|---|---|---|
| **`agent-browser`** (Vercel Labs) | Полная браузерная автоматизация: navigate, click, fill форм, snapshot accessibility tree, screenshot, eval JS. Работает в реальном Chromium с persistent сессиями | Claude Code (нужен PowerShell/Bash) | — | Form-driven SPA, авторизованные страницы, обход CAPTCHA (1× руками), сайты с JS-рендером |
| **Tavily `/search`** | LLM-оптимизированный веб-поиск с scoring и фильтрами по доменам | локальный Overlay: `mcp__legal-overlay__tavily_search` | Расходует credits; health холостой запрос не делает | Поиск по теме с приоритетом релевантности; фильтр по официальным доменам |
| **Tavily `/extract`** | Извлечение чистого markdown с конкретного URL, с поддержкой JS-рендера | Claude Code (REST) | 1 кред = 5 успешных | Известные URL карточек (Madrid Monitor, ФИПС, PDF-страницы); статика с JS |
| **Tavily `/research`** (mini/pro) | Многошаговый research-агент с цитированием и синтезом | Claude Code (REST) | 4-110 (mini) / 15-250 (pro) кред | Многоисточниковый вопрос-ответ (например, «известен ли бренд в фарме») |
| **`WebFetch`** | Простой HTTP GET без JS, c обработкой через small LLM | Claude Code / Cowork (встроенный) | — | Статические страницы по известному URL; не SPA |
| **`WebSearch`** | Встроенный поисковик с фильтрами по доменам и датам | Claude Code / Cowork (встроенный) | — | Общий поиск, когда не нужен LLM-scoring и достаточно простой выдачи |
| **MCP-коннекторы** (`fas-search` и др.) | Специализированные правовые базы через MCP | Claude Code (`.mcp.json`) / Claude Desktop / Cowork / Cursor / Codex | По коннектору | Когда задача попадает в покрытие коннектора (например, реклама → fas-search) |

## 2. Дерево выбора инструмента

```
Задача требует поиска информации?
├── Да: есть ли специализированный MCP-коннектор?
│   ├── Да (например, fas-search для рекламы ФАС) → MCP-коннектор (приоритет)
│   └── Нет → следующий шаг
│       │
│       Есть ли заранее известный URL?
│       ├── Да:
│       │   ├── статика → WebFetch (быстро, дёшево)
│       │   ├── JS-рендер → Tavily /extract (надёжнее, но кредит)
│       │   └── SPA с формой / авторизацией → agent-browser
│       │
│       └── Нет, нужно искать по теме:
│           ├── общий поиск → WebSearch
│           ├── приоритет официальных доменов / scoring → Tavily /search с include_domains
│           ├── многошаговый ресёрч → Tavily /research mini
│           └── сложная навигация (форма + фильтры + парсинг таблицы) → agent-browser
│
└── Нет → не использовать инструменты, отвечать на знаниях LLM с маркерами `[ПРОВЕРИТЬ НОРМУ]` / `[ПРОВЕРИТЬ ИСТОЧНИК]`
```

## 3. Типовые сценарии юридического поиска

### 3.1. Судебная практика

| Источник | URL | Тип | Инструмент |
|---|---|---|---|
| Картотека арбитражных дел | https://kad.arbitr.ru/ | SPA, поиск по № дела / сторонам | agent-browser; для конкретного дела можно WebFetch на прямой URL |
| Реестр судебных актов АС | https://ras.arbitr.ru/ | поиск по тексту акта | agent-browser / Tavily /search с site:ras.arbitr.ru |
| Верховный Суд РФ | https://vsrf.ru/ | статические страницы постановлений Пленума, обзоров | WebFetch / Tavily /extract |
| ГАС «Правосудие» (СОЮ) | https://sudrf.ru/ | агрегатор СОЮ | WebSearch с site: / agent-browser |
| СудАкт | https://sudact.ru/ | бесплатный агрегатор опубликованных полных текстов | WebSearch/WebFetch; резерв при отсутствии платной базы или недоступности официального поиска |
| КС РФ | https://ksrf.ru/ | статика | WebFetch / Tavily /extract |
| Pravo.ru, Закон.ру | https://pravo.ru/, https://zakon.ru/ | аналитика и новости | Tavily /search с include_domains |

При цитировании — обязательно по `references/citation-rules.md`.

**Обязательное правило при пустом локальном слое практики (`search_positions` вернул пусто).** Веб-поиск ведётся **в первую очередь по kad.arbitr.ru и официальному сайту ВС РФ (vsrf.ru)**. СудАкт допустим как бесплатный резерв для поиска и раскрытия опубликованного полного текста: по нему можно предварительно подтвердить существование, реквизиты и содержание акта. Поскольку это не официальный портал, прохождение по инстанциям, отмену/изменение и актуальный статус по возможности сверять по КАД, сайту ВС РФ или сайту суда. Если официальный источник недоступен, ссылка на СудАкт допустима с явной пометкой `secondary_public_aggregator` и оговоркой, что процессуальный статус независимо не проверен. Остальные агрегаторы и энциклопедии (ГАРАНТ, КонсультантПлюс, Право.ру и т. п.) без раскрытого полного текста остаются только навигационным лидом. **Реквизиты конкретного судебного акта (суд, дата, номер дела) не выводятся юристу, пока открыт хотя бы полный текст и позиция сверена** — маркер `[ПРОВЕРИТЬ РЕКВИЗИТЫ]` не заменяет эту проверку и не оправдывает вывод непроверенного/нерелевантного акта. Полная формулировка и обоснование — `references/source-hierarchy.md`, «Рабочий цикл» п. 5 и раздел «Что делать, если обе базы пустые».

### 3.2. Актуальность нормы и поиск НПА на pravo.gov.ru

**Локальный snapshot — основной путь discovery, но не verification нормы.** `find_by_act_number`, `search_legal_kb` и `get_legal_text` помогают найти акт и identity.

**Verification выбирается по capabilities, а не по имени базы.** Сначала вызвать `route_norm_verification(jurisdiction="RU", probe=true)` и использовать только provider с `usable_now: true`. Для прямого адаптера pravo.gov.ru маршрут обычно указывает `pravo_resolve_act` → `pravo_get_document` / `pravo_get_article`; профессиональная правовая система допустима, если её профиль подтверждает полный текст, редакцию, статус, pinpoint и provenance.

Порядок:
1. Выполнить discovery и установить identity акта; `NOT_FOUND` в локальном реестре считать пробелом покрытия.
2. Вызвать `route_norm_verification(..., probe=true)` и выбрать маршрут `usable_now: true`.
3. Открыть полный текст указанным инструментом, проверить реквизиты, редакцию, текущий статус, pinpoint и provenance. Если маршрут ведёт на pravo.gov.ru, детальный протокол разрешения `nd` — `references/pravo-gov-ru-search-protocol.md`.
4. Если пригодного маршрута нет, не считать карточку или snippet проверкой: поставить `[ПРОВЕРИТЬ НОРМУ]`.

**Формат запроса на портал (через поисковик).** В строке поиска (Яндекс/Google) — префикс `http://pravo.gov.ru/` + название акта или тема. Пример:

```
http://pravo.gov.ru/ О защите прав потребителей
```

Официальный текст открывается в результате вида `pravo.gov.ru › proxy/ips/...` — это ИПС «Законодательство России». Эквивалент — оператор `site:pravo.gov.ru <тема>`.

| Источник | URL | Инструмент |
|---|---|---|
| Pravo.gov.ru — ИПС «Законодательство России» | https://pravo.gov.ru/ | После `route_norm_verification(..., probe=true)`: `pravo_resolve_act` → `pravo_get_document` / `pravo_get_article`. Ручной веб — для диагностики/навигации по протоколу; поисковый snippet не цитировать как норму |
| Официальное опубликование | http://publication.pravo.gov.ru/ | WebFetch / Tavily по акту (первая публикация, редакции) |
| КонсультантПлюс | https://www.consultant.ru/ (свободная) / https://cloud.consultant.ru/ (облако, личный логин) | Самостоятельный discovery-provider; capability-smoke пройден 2026-10-09, для norm verification использовать только при ответе route с `usable_now: true` и в пределах ограничений профиля. Детальный протокол — `references/consultant-plus-automation.md` |
| Гарант | https://www.garant.ru/ | Отключён как подключённая база; сайт — только навигационный лид через Tavily |
| Минюст РФ | https://minjust.gov.ru/ | WebFetch |

**Правила маршрутизации:**
- существование ссылки и локальная карточка — discovery; норму подтверждает только раскрытый текст от `usable_now: true` verification-provider;
- действующая редакция — по ИПС портала; при сомнении — маркер `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ РЕДАКЦИИ]` (или `[ПРОВЕРИТЬ РЕДАКЦИЮ]`);
- КонсультантПлюс через Overlay (`consultant_search`) — основной внешний профессиональный поиск с раскрытием доступного полного текста; дата редакции из заголовка не заменяет проверку точного статуса или исторической редакции. Веб-страницы consultant.ru/garant.ru через веб-поиск — только навигационный лид; статус, опубликование и реквизиты судебного акта сверяются по официальному порталу.

## 4. Принципы

1. **Не выдумывать**. Если поиск не дал результата — так и пишется. Никаких «вероятно», «обычно», «по практике» без конкретного источника.
2. **Иерархия источников** — строго по `references/source-hierarchy.md`: законы / НПА / официальные сайты / судебные акты / профессиональные базы → аналитика только как вспомогательное.
3. **Цитирование** — по `references/citation-rules.md` (акт, дата, номер, статья, часть, пункт, редакция; суд, акт, дата, дело, пункт, источник).
4. **Конфиденциальность**:
   - в публичные API (`Tavily`, `WebSearch`, MCP) не передаются: ПДн клиента, коммерческая тайна, NDA-материалы, тексты черновиков документов клиента;
   - публичные идентификаторы (ИНН, ОГРН, № дела, URL судебного акта) — разрешены;
   - для чувствительных задач — пометка `[НЕ ПЕРЕДАВАТЬ В ПУБЛИЧНЫЕ API]` и работа на знаниях LLM с явной отметкой ограничения;
   - подробности — `references/confidentiality-rules.md`.
5. **ToS источников**:
   - не делать массовый scraping (Madrid Monitor, fas.gov.ru и иные госпорталы);
   - соблюдать rate-limits (для Tavily, MCP-коннекторов);
   - использовать прямые ссылки на конкретные записи, а не bulk-выгрузку;
   - прямой FAS provider: 20 запросов/мин, 300/сутки на IP — учитывать при массовом аудите.
6. **Логирование** — в отчёт **обязательно**:
   - какой инструмент использовался;
   - какие запросы выполнены (текст / URL);
   - какие источники найдены (с прямыми ссылками);
   - какие маркеры остались.
7. **Среды исполнения** — подключённые раннеры этой установки: Claude Code, Codex, Cursor (`references/agent-runners.md`). Если нужного инструмента в сессии нет — `[ИНСТРУМЕНТ НЕДОСТУПЕН]` и работа с тем, что есть.

## 6. Специализированные протоколы (надстройки над этим слоем)

- `references/trademark-search-automation.md` — детальные протоколы для **поиска товарных знаков** (linkmark.ru, WIPO GBD, WIPO Madrid Monitor). Использует agent-browser + Tavily; настоящий файл — базовый слой инструментов.
- `references/pravo-gov-ru-search-protocol.md` — provider-specific протокол прямого поиска НПА на `pravo.gov.ru`: точный URL, CP1251, разбор `nd`, получение и сверка полного текста.
- `references/consultant-plus-automation.md` — discovery и проверка документов в свободной/облачной версии; capability-smoke пройден, norm verification только при `usable_now: true` и в пределах профиля.
- Практика ФАС — Overlay `search_fas_ad_practice` / `get_fas_case` / `list_fas_filter_options`. Отдельный MCP-коннектор ФАС не подключать.
- `references/agent-browser-cheatsheet.md` — локальная справка `agent-browser` (команды, опции, выгрузка `--help`).

При появлении новых задач, требующих автоматизированного поиска (судебная практика для конкретной категории дел, мониторинг сроков по конкретным контрагентам и т. п.), создаются дополнительные специализированные reference-ы — со ссылкой на настоящий общий слой.

## 7. Связанные файлы
