# Risk Scale

Назначение: единая шкала оценки рисков во всех skills и agents.

## Уровни риска

### Блокирующий

Условие или ситуация делают сделку / документ / действие невозможными в текущем виде. Без устранения двигаться нельзя.

Признаки:
- прямой запрет закона;
- нарушение публичного порядка;
- риск уголовной ответственности или административной ответственности с существенными санкциями;
- риск утраты лицензии, разрешения, статуса;
- риск признания договора недействительным / незаключённым по существенным условиям;
- риск признания сделки крупной / с заинтересованностью без надлежащего одобрения;
- условие, которое лишает компанию ключевого средства защиты (например, безусловный отказ от ответственности контрагента, отказ от подсудности РФ без альтернативы).

### Высокий

Существенно ухудшает позицию компании. Требует обязательной правки или мотивированного решения юриста.

Признаки:
- асимметричная ответственность не в пользу компании;
- штрафы и пени без верхнего предела;
- сокращённые сроки приёмки / претензий не в пользу компании;
- отсутствие закрывающих документов;
- широкие основания для одностороннего отказа контрагента;
- неясный предмет, цена, объём;
- риски по ПДн, рекламе, ИС, санкциям, ЛП/БАД, не закрытые в договоре.

### Средний

Заметно ухудшает позицию или несёт неопределённость. Желательно править, но допустимо принять с компенсирующими механизмами.

Признаки:
- неудобная подсудность, но не блокирующая;
- неоптимальные сроки оплаты;
- штрафы выше рынка, но в пределах разумного;
- неполные, но рабочие условия о конфиденциальности;
- отсутствие части стандартных заверений.

### Низкий

Несущественно ухудшает позицию или техническая шероховатость. Можно принять. Фиксируется в комментариях.

### Вопрос бизнесу

Не риск юриста, а бизнес-решение. Юрист передаёт развилку бизнесу без собственной рекомендации, кроме случаев очевидного перекоса. Формулировка:
> «Это бизнес-решение. Юридически возможны оба варианта. На что обратить внимание: …»

## Правила применения

- Один пункт договора может нести несколько рисков. Каждый отражается отдельной строкой в таблице рисков.
- Уровень риска выставляется по худшему сценарию, реально применимому к компании.
- Если уровень риска зависит от факта, которого нет, — ставить уровень и маркер `[ПРОВЕРИТЬ ФАКТ]`.
- В таблице рисков уровень указывается в отдельной колонке. Текстом дублировать не нужно.
- Если предложена правка — указывать, какой риск она снимает.
- Fallback-позиция — указывать, какой уровень риска остаётся при принятии fallback.

## Машиночитаемые значения (для `clause-review` JSON и Word Add-in)

При использовании в JSON-формате (skill `clause-review`, см. `references/clause-review-response-schema.md`, и Word Add-in TaskPane) уровни кодируются строго фиксированными значениями:

| Человеко-читаемо | Машиночитаемо (`riskLevel`) |
|---|---|
| Блокирующий | `"блокирующий"` |
| Высокий | `"высокий"` |
| Средний | `"средний"` |
| Низкий | `"низкий"` |
| Вопрос бизнесу | `"вопрос-бизнесу"` (через дефис, без пробела) |

**Правила**:
- значения — строго нижний регистр, как в таблице (для парсинга на стороне backend / UI);
- никаких синонимов / вариантов перевода («blocking», «critical», «high», «medium», «low»);
- если для пункта применим **только** уровень «вопрос-бизнесу» (бизнес-решение без юридического вывода) — в `issue` и `recommendation` использовать формулировку из раздела «Вопрос бизнесу» выше (передать развилку без своей рекомендации, кроме очевидного перекоса).

## Цветовое кодирование в UI (рекомендация для Word Add-in)

Для удобства визуального восприятия в TaskPane:

| Уровень | Цвет (рекомендация) |
|---|---|
| `"блокирующий"` | красный (`#D73A49` / Bootstrap `danger`) |
| `"высокий"` | оранжевый (`#E36209`) |
| `"средний"` | жёлтый / янтарный (`#DBAB09`) |
| `"низкий"` | зелёный (`#28A745` / `success`) |
| `"вопрос-бизнесу"` | синий / нейтральный (`#0366D6` / `info`) |

Это рекомендация, не обязательное требование; команда UI может выбрать другие оттенки.

## Применимость к разным контекстам

| Skill / контекст | Использование шкалы |
|---|---|
| `contract-review` | В таблице рисков, колонка «Уровень» — человеко-читаемые значения («Блокирующий», и т. д.) |
| `clause-review` | В JSON-поле `riskLevel` — машиночитаемые значения (`"блокирующий"`, и т. д.) |
| `procedural-document-drafter` | При оценке процессуальных рисков — человеко-читаемые |
| `gov-response` | При оценке риска ответа госоргану — человеко-читаемые |
| `amendment-drafter` | При оценке риска изменений — человеко-читаемые |
| `position-critic` | При оценке риска линий защиты — человеко-читаемые |
