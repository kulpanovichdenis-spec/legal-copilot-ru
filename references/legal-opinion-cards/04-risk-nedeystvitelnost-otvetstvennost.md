# LO-4 — Риск (недействительность / ответственность / регуляторный)

Архетип вопроса: **«какие риски, если …», «действительна ли сделка», «чем грозит нарушение»**. Тонкая карточка-роутер — самый делегирующий. Компонент «стоимость риска / принятие риска» **обязателен**.

## Когда триггерится
Сигналы: «какие риски», «чем грозит», «действительна ли сделка, если …», «оспорят ли», «какая ответственность за нарушение», «оштрафуют ли», «есть ли риск недействительности / взыскания / привлечения».

## Какие вводные запросить у юриста
- какое действие/нарушение/дефект оценивается (конкретно);
- на чьей стороне вопрос (риск для нас / риск для контрагента);
- есть ли уже спор/претензия/проверка, или оценка предварительная;
- суммы/размеры (для цены вопроса), если известны — иначе под маркер.

## Порядок исследования (делегирование существа)
1. Определить природу риска и делегировать существо:
   - **недействительность/оспоримость** → сценарная карточка `search_legal_kb("проверка недействительности сделки")` (маршрут: дефект → режим → субъект/срок → последствия);
   - **ответственность за нарушение** → `search_legal_kb("нарушение договора убытки неустойка проценты ответственность")` (не смешивать убытки, неустойку, проценты, возмещение потерь, лимиты);
   - **регуляторный/административный** → профильный skill (`skills/fas-ad-practice-search/SKILL.md`, `skills/fz248-knm-rospotrebnadzor/SKILL.md`, `skills/fz184-technical-regulation/SKILL.md`).
2. Якорь на норму (`get_legal_text`, при отсутствии — `pravo.gov.ru`) + позиции ВС (`search_positions`, связь через `list_position_norm_links`).
3. Санкции/размеры — **из раскрытой нормы** по `route_norm_verification(..., probe=true)` и `usable_now: true`, не по памяти; сомнение в редакции — `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ РЕДАКЦИИ]`.

## IRAC-скелет жанра
- **Вопрос:** каков риск [недействительности / ответственности / санкции] при [X].
- **Правило:** основание риска (норма о недействительности/ответственности) + режим последствий + практика.
- **Анализ:** есть ли состав; что его смягчает/устраняет; как складывается практика; разграничить средства защиты.
- **Вывод:** **калиброванная** оценка («есть риск», «по общему правилу», уровень по `../risk-scale.md`), не абсолют. Нет практики — `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`.

## Стоимость риска, lawful course и residual risk (обязательный блок)
Наследует компонент 2 из CLAUDE.md («Блок "что поправить"»), обобщённый под гражданские вопросы. Три элемента:
1. **Цена вопроса** — конкретно, не «уровень риска»: для админ/регуляторных — штраф из раскрытой через capability-маршрут нормы; для гражданских — размер взыскания/убытков/неустойки, риск недействительности и реституции, утрата права. Суммы не выдумывать — из нормы либо `[ПРОВЕРИТЬ ФАКТ]` / `[ПРОВЕРИТЬ РАЗМЕР]`.
2. **Иные последствия** — срыв сделки/сроков, предписание, переделка, репутация, риск повторности.
3. **Доведение до бизнеса + решение** — совокупная «цена» одной строкой; назвать lawful course, mitigation и residual risk. Бизнес выбирает между законными вариантами и может принять их остаточный риск (`[ВОПРОС БИЗНЕСУ]` / `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`). Юрист озвучивает цену, не решает за бизнес. Нарушение и блокирующий риск как вариант «принять» не предлагаются; последствия нарушения объясняются отдельно.

## Типовые ошибки и маркеры
- вывод «практики нет» после одного пустого `search_positions(keyword=...)` — поиск лексический,
  0 по keyword не означает 0 по `article=`/`query=`; обязательна query expansion (`../query-cookbook.md`)
  прежде чем заключать об отсутствии практики;
- абсолют «сделка ничтожна / оштрафуют» без разграничения состава и режима;
- смешение убытков/неустойки/процентов/потерь; экстраполяция регионального УФАС на всю РФ;
- «уровень риска высокий» вместо конкретной цены вопроса;
- решение о принятии риска принято за бизнес.
