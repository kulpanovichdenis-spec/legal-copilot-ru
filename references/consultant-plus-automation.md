# КонсультантПлюс — автоматизация discovery и проверки источника

## Текущее подключение Legal Copilot

Основной внешний профессиональный источник — внутренний MCP КонсультантПлюс
через `legal-overlay`. Использовать только read-only инструменты
`consultant_search`, `consultant_get_text`, `consultant_get_document` и
`consultant_status`. Он доступен из корпоративной сети или VPN и не требует
пользовательских логина, пароля, токена либо HTTP-заголовков. ГАРАНТ отключён и
не вызывается.

## Рабочий маршрут MCP (канонический)

Этот раздел имеет приоритет над описанным ниже браузерным сценарием. Доступность
проверяет `route_norm_verification(jurisdiction="RU", probe=true)` через дешёвый
`tools/list`; `consultant_status` не вызывается перед каждым поиском, потому что
он расходует одно обращение к поставщику. Затем работа идёт точечно по одному
документу:

1. `consultant_search({"query": "..."})` — найти кандидатов. В запросе указать
   вид акта, орган, номер/дату или нейтральный правовой вопрос; не передавать
   текст документов, персональные данные, суммы, номера договоров или названия
   непубличных контрагентов.
2. `consultant_get_document({"bank_name": "...", "document_number": N})` —
   открыть карточку и прочитать доступные реквизиты и ограничения метаданных.
   Дата `edition` производна из заголовка, а `status_search_category` не
   подтверждает точный статус. Координаты берутся только из фактической выдачи.
3. `consultant_get_text({"bank_name": "...", "document_number": N,
   "paragraph_start": A, "paragraph_end": B,
   "include_references": true})` — прочитать только нужный диапазон абзацев.
   Не выгружать документ целиком и не запрашивать диапазоны «на всякий случай».
4. `consultant_status({})` — только при отдельной необходимости проверить дату
   пополнения комплекта. Это не проверка редакции или статуса документа.

| Инструмент | Подтверждённая схема | Допустимая роль |
|---|---|---|
| `consultant_status` | аргументы не требуются | Дата пополнения комплекта; один расходуемый вызов, не routine health-check и не статус документа |
| `consultant_search` | обязательный `query: string` | Поиск кандидатов и их координат |
| `consultant_get_document` | обязательные `bank_name: string`, `document_number: integer` | Карточка и реквизиты; дата редакции производна из заголовка, статус — поисковая категория поставщика |
| `consultant_get_text` | обязательные `bank_name`, `document_number`, `paragraph_start`, `paragraph_end`; опциональный `include_references` | Точечное чтение текста и ссылок |

### Границы юридического использования

- Поисковая выдача и карточка — навигация, а не самостоятельное доказательство
  нормы или судебной позиции.
- Перед выводом по норме применить
  `route_norm_verification(jurisdiction="RU", probe=true)`. Capability-smoke К+
  как `live_professional` пройден 2026-10-09, но использовать его можно только
  при `usable_now: true` и в пределах ограничений профиля; иначе ставить
  `[ПРОВЕРИТЬ НОРМУ]`.
- Для судебного акта К+ помогает найти материал, но суд, дату, номер дела,
  итог и правовую позицию сверять по первоисточнику (КАД, сайт ВС РФ или сайт
  суда). Для опубликования НПА — по официальному источнику.
- ГАРАНТ отключён: не использовать как fallback и не выполнять `garant_*` без
  нового явного решения юриста.

### Ошибка, недоступность и текущий smoke

При ошибке `consultant_search`, `consultant_get_document` или
`consultant_get_text` не повторять запрос сериями и не достраивать результат.
Зафиксировать coverage gap и перейти по `references/source-hierarchy.md` к
официальному или иному разрешённому маршруту. Не переустанавливать сервис и не
менять серверную конфигурацию.

Живой smoke 2026-10-09 на production `consultantplus-mcp` 0.2.0: статус вернул
дату поступления 2026-10-08; поиск по ГК РФ вернул кандидатов; карточка и
адресный диапазон текста открылись. Карточка помечает `edition` как производную
из заголовка, `status_search_category` — как поисковую категорию, а отсутствие
точного статуса и выбора исторической редакции — как ограничения. Поэтому
раскрытый текст пригоден как `live_professional`, но точный статус, нужная
историческая редакция и опубликование проверяются официально.

Описанная ниже браузерная автоматизация — запасной ручной маршрут, когда MCP
недоступен или не покрывает материал. Личные учётные данные не переносить в
настройки Overlay и не вводить автоматически.

> **Этот файл — специализация над общим слоем веб-инструментов** `references/web-research-tools.md`. Базовые принципы выбора инструмента (agent-browser / Tavily / WebFetch / WebSearch / MCP), правила конфиденциальности и общие маркеры — там. Здесь — детальный протокол работы с **одной конкретной базой: КонсультантПлюс** (свободная версия `www.consultant.ru` + коммерческая облачная `cloud.consultant.ru`).
>
> Механизм построен по образцу `references/trademark-search-automation.md` (agent-browser + сессии + snapshot→подпись→ref + передача управления юристу + журнал автоматизации + запрет вымысла). Отличия — в модели доступа (личный логин) и в **дисциплине цитирования** (КонсультантПлюс = навигация к первоисточнику, не источник цитаты).

Данные о структуре свободной версии основаны на **реальной разведке 2026-08-19** (тестовый запрос — «Приказ Минздрава России N 4н»). Структура авторизованной облачной версии за формой входа в разведке **не вскрывалась** (агент не вводит пароли — см. §3) и требует проверки при первом запуске (см. §11).

## 0. Когда включается этот механизм

КонсультантПлюс включается как самостоятельный доступный источник для discovery либо проверки документа. Наличие или отсутствие акта в локальном SQLite не является триггером само по себе:

```
1. Discovery: использовать любой доступный подходящий источник, включая КонсультантПлюс.
2. Verification нормы: вызвать route_norm_verification(jurisdiction="RU", probe=true).
3. Раскрытый документ КонсультантПлюс подтверждает норму только при usable_now: true и в объёме capabilities профиля.
```

Типичные документы, для которых удобен КонсультантПлюс:
- **подзаконные и ведомственные акты** (приказы, письма, разъяснения Минфина/ФНС/Минздрава/Минтруда и т. п.);
- **региональные и муниципальные НПА**;
- **текущая доступная редакция** акта; исторические редакции и точный статус
  проверяются отдельным официальным маршрутом;
- **судебная практика** (когда локальный слой `search_positions` и kad.arbitr.ru/vsrf.ru не закрыли вопрос);
- **комментарии, обзоры, «Готовые решения», «Путеводители»** — как навигационный лид (не как источник права).

**Роль определяется профилем:** поисковая карточка всегда остаётся навигацией.
После capability-smoke 2026-10-09 раскрытый полный текст может подтверждать
норму, только когда route возвращает `usable_now: true` и только в пределах
заявленного coverage. Производная дата редакции и поисковая категория статуса
не заменяют официальную проверку исторической редакции и точного статуса.

### 0А. Два режима включения: «документ не найден» И «проверка цитаты»

Есть два независимых режима: **discovery документа** и **проверка уже найденной ссылки**. Они не образуют фиксированную цепочку после локальной базы:

> Если тезис вывода опирается на источник, который **не открыт лично** (пришёл из слоя позиций `legal-kb`, от субагента, из веб-сниппета или «по памяти») — и этот источник **доступен** в КонсультантПлюс (типично: **точная формулировка пункта Пленума/Обзора ВС**, **судебный акт**, конкретная редакция), — его нужно **открыть и сверить**, а не отдавать юристу с маркером `[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]`.

Порядок для verification: **сначала свободная версия** `www.consultant.ru` (§6; для многих документов — Пленумы, кодексы, известные акты — этого достаточно и логин не нужен), при нехватке — облако (§7). Для **судебной практики** (полные тексты определений/постановлений ВС и КС, свежие кассационные СОЮ) облако предлагается **по умолчанию**: агент запускает страницу и идёт по flow §3 — **сначала ждёт автологин ~5–8 с** (persistent-сессия), и **только если вход не сработал — просит юриста** выполнить вход (пароль агент не вводит). Маркер `[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]` остаётся **только для реально недоступного** (нет в свободной версии, а облако недоступно/юрист не выполнил вход; либо среда без инструментов). Маркер — не замена одному дешёвому `tavily_extract`/`WebFetch` по URL свободной версии (§6.3, «Быстрый путь без браузера»).

Это прямо связано с шагом source verification в заключениях: `references/legal-opinion-method.md` §10 (CLAIM_LEDGER) и `CLAUDE.md`, «Финальная валидация перед сохранением». Дисциплина цитирования из §9 сохраняется (КонсультантПлюс = навигация к первоисточнику; для практики — открыть сам судебный акт).

## 3. Авторизация в облачной версии — передача управления юристу (НЕ автоввод пароля)

**Агент не вводит пароли в формы аутентификации** (правило безопасности проекта — то же, что запрет самому решать CAPTCHA и подавать документы). Вход в коммерческую версию выполняется по модели **login-handoff**, полностью аналогичной CAPTCHA-handoff из ТЗ-протокола:

1. agent-browser открывает окно входа **в headed-режиме**:
   ```powershell
   agent-browser --headed --session consultant open https://login.consultant.ru/ --json
   ```
2. **Сначала подождать автологин (решение юриста 2026-08-20).** После открытия страницы **выждать ~5–8 секунд** (`agent-browser --session consultant wait 6000`) — сохранённая persistent-сессия `--session consultant` или запомненный вход могут авторизовать автоматически. Затем проверить состояние: `snapshot` / `eval "window.location.href"`. Если открылась рабочая область облака (URL `…req=home…`, а не форма входа с `textbox "Введите логин"`) — **вход уже выполнен, handoff НЕ нужен**, сразу переходить к работе (§7). **Просить юриста только если после ожидания всё ещё видна форма входа.**
3. Если автологин не сработал — агент сообщает юристу:
   > Нужен вход в КонсультантПлюс. Окно Chrome открыто на `login.consultant.ru`.
   > 1) Введи логин и пароль (они у тебя в `.env`: `CONSULTANT_LOGIN` / `CONSULTANT_PASSWORD`);
   > 2) **поставь галочку «Запомнить меня»** (на форме, слева от кнопки «Войти») — иначе вход придётся повторять каждый раз;
   > 3) нажми «Войти», дождись, пока откроется рабочая область облака;
   > 4) напиши «готово» — продолжу.
4. Юрист вводит учётные данные сам, **отмечает «Запомнить меня»** и нажимает «Войти».
5. После подтверждения авторизация **сохраняется в persistent-сессии** `--session consultant` (cookies/localStorage в `~/.agent-browser/sessions/consultant/`) — повторный вход при следующих запусках обычно не требуется, пока сессия/долгий cookie живы (поэтому шаг 2 в следующий раз чаще всего проходит автоматически).

**Почему «пароль в Google Chrome» здесь не помогает автоматически.** Пароль, сохранённый в обычном Chrome пользователя, лежит в его личном профиле. `agent-browser` запускает **отдельный профиль Chrome for Testing** (`~/.agent-browser/…`) — сохранённых паролей обычного Chrome в нём нет. Поэтому «не вводить каждый раз» в автоматизации обеспечивают **две вещи вместе**:
- **галочка «Запомнить меня»** на форме входа → сервер выдаёт долгоживущий cookie сессии;
- **`--session consultant`** сохраняет этот cookie в persistent-профиле agent-browser между запусками.

Первый вход всё равно делает юрист (агент пароли в форму не отправляет), но при отмеченной «Запомнить меня» он нужен **один раз**, а не каждый раз. Если сессия всё же протухла (сервер разлогинил, чистили профиль) — повторить handoff.

`CONSULTANT_LOGIN` / `CONSULTANT_PASSWORD` в `.env` — это **личное хранилище пользователя** (чтобы не искать креды каждый раз при первом входе). Агент их читает только чтобы **показать юристу, что вводить**, но **сам в форму входа не отправляет**.

**Ограничение по числу сессий.** У коммерческого доступа обычно лимит одновременных сессий. Если юрист параллельно работает в КонсультантПлюс в обычном браузере — вход агента может вытеснить его сессию (или наоборот). Предупредить об этом и согласовать момент запуска.

## 4. Глобальные принципы автоматизации

1. **Никакого вымысла.** Если поиск не дал документа или инструмент упал — это фиксируется в отчёте. Никаких «подставленных» номеров, дат, редакций, реквизитов актов или судебных дел. Правило проекта №1.
2. **КонсультантПлюс — навигация, не источник цитаты.** Найденный документ — повод открыть первоисточник и сверить реквизиты (§9). Реквизиты акта в вывод юристу попадают только после сверки с официальной публикацией; для практики — после открытия первоисточника (kad.arbitr.ru / текст судебного акта).
3. **Ref-ы НЕ стабильны между страницами.** Каждый раз: `snapshot` → найти элемент **по подписи** (`textbox "Поиск: Кодексы, законы и другие материалы"`, `button "Найти"`) → взять его `@eN`. **Хардкодить ref-ы запрещено** (то же правило, что в ТЗ-протоколе).
4. **Логин — через юриста** (§3). CAPTCHA (если появится) — тоже через юриста (`references/trademark-search-automation.md` §9).
5. **Точечно, без массовой выгрузки.** Работаем «как юрист смотрит конкретный документ»: нашли — открыли — сверили. Не выгружаем разделы банка целиком (ToS правообладателя).
6. **Все запросы — в журнал** (§10): версия, дата/время, версия базы (свободная/облако), текст запроса, persistent URL, что найдено, ошибки.
7. **Конфиденциальность (§8).** В строку поиска КонсультантПлюс не вводить тексты документов клиента, ПДн, суммы, номера договоров — только правовой запрос и публичные реквизиты (номер акта, название, номер дела).

## 5. Технические правила agent-browser

Полностью наследуются из `references/trademark-search-automation.md` §3 (headed-режим, `--session`, запрет пайпинга через `Select-Object`, формат `--json` для команд и plain для `snapshot`, cleanup `close`, «snapshot → подпись → @eN»). Здесь — только специфика КонсультантПлюс:

- сессия называется **`consultant`** (единая для свободной и облачной версии);
- **cookie-баннер**: при первом открытии свободной версии внизу появляется баннер cookies с `button "Понятно"` — если он перекрывает элементы, кликнуть его по подписи (найти `@eN` через snapshot);
- для облака часть интерфейса может быть в **iframe** — если `snapshot` не видит поле поиска на верхнем уровне, искать во вложенных фреймах (`snapshot` выводит дерево целиком; если элемент во фрейме — использовать соответствующий ref).

### 5А.1 Быстрый поиск vs Карточка поиска — что выбрать

| Инструмент | Когда | Как |
|---|---|---|
| **Быстрый поиск** | «Ленивый» быстрый поиск, когда нужно просто найти хоть что-то релевантное и интересует **всё, что найдётся** по всей базе | Точка входа по умолчанию. Ключевые слова — в строке поиска |
| **Карточка поиска** | **Прицельно**, когда заранее известны рамки: конкретный **вид документа** / **принявший орган** (только Решения ВС РФ, только Федеральные законы, только Постановления Правительства) или нужен **конкретный период** — то есть поиск **не по всей базе** | Поля «Вид документа» / «Принявший орган» — сузить тип; поле «Дата» — задать **диапазон**; ключевые слова — в поле «Текст документа» |

### 5А.2 Как формулировать запрос по ключевым словам (расширение через усечение `*`)

Работает и в строке Быстрого поиска, и в поле «Текст документа» Карточки. Цель — **больше релевантных вариантов, меньше мусора**:

1. **Выкинуть «мусорные» слова**, которых в тексте акта/решения не будет: родовые вроде «дела», «вопрос» — они только ломают выдачу.
2. **Выкинуть предлоги и союзы** («по», «в», «на», «о», «и»…) — их не ищем.
3. **Окончания — через усечение `*`**: вместо перебора форм («незаконные / незаконный / незаконная») писать **корень со звёздочкой** — `незакон*`. Звёздочка ловит все окончания, гадать не нужно.
4. Итог — короткий запрос из значимых корней с `*`.

**Пример.** Задача «найти дела по сносу незаконных построек»:
- «дела» — убрать (в тексте не будет), «по» — предлог, убрать;
- «сносу / незаконных / построек» → корни с `*`;
- **готовый запрос: `снос* незакон* построек*`**.

### 5А.3 Как отличить недействующий документ

- в **выдаче** у недействующего сразу стоит отметка, что он недействующий;
- при **переходе** в документ вверху надпись «**Документ утратил силу в связи…**» (в свободной версии — «Документ утратил силу или отменён»);
- для правового вывода брать **действующую редакцию**; статус и редакции смотреть в «**Справке**».

### 5А.4 Судебная практика — рабочий маршрут (через Быстрый поиск)

1. обычный «ленивый» Быстрый поиск по правилу 5А.2 (корни с `*`);
2. перейти на «**Все результаты поиска**» (кнопка **справа вверху над результатами**);
3. в **левом сайдбаре** выбрать раздел «**Судебная практика**»;
4. внутри — **начинать с «Решения высших судов»** (ВС РФ / КС РФ), далее остальные разделы по списку.

Альтернатива для прицельного поиска — Карточка поиска → «Судебная практика», либо «Ещё → Спец. поиск судебной практики».

### 5А.5 Что брать для цитаты

- цитировать **абзац дословно, без изменений**;
- реквизиты для ссылки брать из раздела «**Справка**» (правый верхний угол карточки) — копировать «**Название документа**».

Это **не отменяет §9**: для федеральных НПА применить capability-маршрут и проверить редакцию/статус/pinpoint/provenance; судебную практику цитировать только после открытия самого акта.

## 6. Свободная версия — протокол (проверено 2026-08-19)

### 6.1 Схема URL

| Страница | URL |
|---|---|
| Главная | `https://www.consultant.ru/` |
| **Результаты поиска** | `https://www.consultant.ru/search/?q={URL_ENCODED_QUERY}` — **persistent**, годится для отчёта |
| **Карточка документа** | `https://www.consultant.ru/document/cons_doc_LAW_{ID}/` — стабильный идентификатор `cons_doc_LAW_{ID}` |
| Справка о статусе/редакциях | ссылка «Подробнее см. Справку» / «Справка» на карточке |

### 6.2 Структура одного результата выдачи

Нумерованный список; в каждом элементе (проверено на тестовом запросе):
- **статус** (если применимо): «Документ утратил силу или отменен», «Проект…» и т. п.;
- **заголовок с реквизитами**: вид акта, орган, дата, номер, **редакция** («(ред. от ДД.ММ.ГГГГ)»);
- **регистрация в Минюсте** (для ведомственных актов): «(Зарегистрировано в Минюсте России ДД.ММ.ГГГГ N …)»;
- **ссылка** на карточку: `…/document/cons_doc_LAW_{ID}/`.

### 6.3 Протокол поиска (agent-browser)

```powershell
# 1. Открыть главную
agent-browser --headed --session consultant open https://www.consultant.ru/ --json

# 2. Snapshot → найти @ref поля поиска по подписи "Поиск: Кодексы, законы и другие материалы"
agent-browser --session consultant snapshot -i -c
#   (если мешает cookie-баннер — кликнуть button "Понятно")

# 3. Заполнить запрос (формулировка — по §5А.2: корни с *, без предлогов и «мусорных» слов)
agent-browser --session consultant fill "@eXX" "Приказ Минздрава России N 4н" --json

# 4. Snapshot → найти @ref кнопки "Найти"
agent-browser --session consultant snapshot -i -c
agent-browser --session consultant click "@eYY" --json
agent-browser --session consultant wait 2500

# 5. Сохранить persistent URL выдачи
agent-browser --session consultant eval "window.location.href" --json

# 6. Snapshot результатов → распарсить нумерованный список (реквизиты + ссылки cons_doc_LAW_{ID})
agent-browser --session consultant snapshot -i -c

# 7. Открыть карточку нужного документа
agent-browser --session consultant open https://www.consultant.ru/document/cons_doc_LAW_{ID}/ --json
agent-browser --session consultant wait 2000
agent-browser --session consultant snapshot -i -c
#   На карточке: статус, реквизиты, "Справка" (статус/редакции), оглавление,
#   "Открыть полный текст документа".

# 8. Cleanup по завершении
agent-browser --session consultant close
```

**Быстрый путь без браузера** (когда URL карточки уже известен и страница не за авторизацией):
```
mcp__legal-overlay__tavily_extract(urls=["https://www.consultant.ru/document/cons_doc_LAW_{ID}/"], format="markdown")
```
или `WebFetch` по тому же URL. Годится, чтобы вытащить реквизиты и оглавление; полный текст больших актов свободная версия может отдавать частями/по кнопке — тогда agent-browser.

### 6.4 Найти URL карточки по теме (Tavily как навигация)

Когда `cons_doc_LAW_{ID}` неизвестен и точный поиск на сайте не хочется гонять руками:
```
mcp__legal-overlay__tavily_search(
  query="{вид акта} {орган} {номер} {тема}",
  max_results=5,
  include_domains=["consultant.ru"]
)
```
Из результатов взять URL вида `…/document/cons_doc_LAW_{ID}/` → далее §6.3 шаг 7. **Найденный URL — навигационный лид, не готовая цитата.**

### 6.5 Границы свободной версии

- обновление с задержкой относительно коммерческой; актуальность редакции **обязательно** сверять (§9);
- часть контента (отдельные редакции, судебная практика, комментарии, «Готовые решения») в свободной версии недоступна или показывается фрагментом — тогда переход в облако (§7);
- фактический объём полного текста для конкретного документа в свободной версии **проверять на месте**, не предполагать.

## 7. Облачная (коммерческая) версия — протокол (проверено 2026-08-19)

**Вход** — по §3 (handoff, юрист вводит логин сам). После авторизации рабочая область открывается на `https://cloud.consultant.ru/cloud/cgi/online.cgi?req=home&rnd=…` — «Стартовая страница КонсультантПлюс».

### 7.1 Схема URL (облако)

| Страница | URL |
|---|---|
| Стартовая (после входа) | `…/online.cgi?req=home&rnd={RND}` |
| Выдача Быстрого поиска | `…/online.cgi?req=card&page=splus&splusFind={URL_ENCODED_QUERY}&ts={TS}&rnd={RND}` |
| Карточка документа | `…/online.cgi?req=doc&base=…&n=…` (открывается из списка) |

**`ts` и `rnd` — одноразовые параметры сессии.** В отчёт/цитату как persistent-ссылку их **не сохранять** (у другого пользователя/сессии не откроются). Для ссылки на документ фиксировать реквизиты акта, а не cloud-URL.

### 7.2 Навигация (проверенные подписи)

Верхнее меню: `link "Быстрый поиск"`, `link "Карточка поиска"` (→ `link "Законодательство"` / `link "Судебная практика"`), `link "Кодексы"`, `link "Справочная информация"`, `link "Новости"`, `link "Ещё"` (→ Спец. поиск судебной практики, Архивы судов, Архив решений ФАС/УФАС, Конструктор договоров). Слева — `link "Избранное"`, `link "Журнал"`.

Поле Быстрого поиска на стартовой/поисковой странице: `textbox "  "` (подпись пустая) + рядом `button "Найти"`.

### 7.3 Протокол Быстрого поиска (проверено)

```powershell
# 0. Вход (handoff, §3) — один раз на сессию
agent-browser --headed --session consultant open https://login.consultant.ru/ --json
#    → юрист вводит логин, галочка "Запомнить меня" (по умолчанию отмечена), "Войти", пишет "готово"

# 1. Snapshot → найти поле Быстрого поиска (textbox "  ") — ref КАЖДЫЙ раз пересниммать
agent-browser --session consultant snapshot -i -c

# 2. Заполнить (формулировка — §5А.2) и ОТПРАВИТЬ ЧЕРЕЗ Enter (проверено: focus + Enter надёжнее клика "Найти")
agent-browser --session consultant fill "@eXX" "Приказ Минздрава России 4н" --json
agent-browser --session consultant focus "@eXX" --json
agent-browser --session consultant press Enter --json
#    URL станет …req=card&page=splus&splusFind=…

# 3. Дать облаку построить список (тяжёлый SPA): пауза ~5-6 c
agent-browser --session consultant wait 6000

# 4. ПРОВЕРИТЬ модалку "Учётная запись занята" (см. §7.4) — если она есть, список пустой
#    Иначе — прочитать список результатов:
agent-browser --session consultant eval "document.body.innerText" --json
#    В списке по каждому документу: вид акта, орган, дата, N, (ред. от …), (Зарегистрировано в Минюсте …)

# 5. Открыть нужный документ (клик по его заголовку/номеру в списке — ref из snapshot)
#    На карточке: статус, ДЕЙСТВУЮЩАЯ редакция, дата актуальности, оглавление, связи, редакции, практика.

# 6. Cleanup — сессию НЕ закрывать без нужды (чтобы не терять авторизацию);
#    при завершении работы: agent-browser --session consultant close
```

**Важные проверенные нюансы (2026-08-19):**
- **сабмит — `focus` + `press Enter`**, не клик по «Найти» (клик по кнопке в этом SPA срабатывал ненадёжно);
- **refs смещаются** после заполнения/перерендера — пересниммать `snapshot` перед каждым действием (правило §4.3);
- список результатов рендерится **в самой странице** (не в iframe; единственный iframe на стартовой — чат-виджет `req=livechat`);
- список строится **асинхронно** — сразу после submit `document.body.innerText` может ещё показывать стартовую страницу; дать паузу и перечитать.

### 7.4 Модалка «Учётная запись занята» — лимит одновременных сессий (проверено)

У коммерческого доступа лимит одновременных сессий. Если аккаунт уже используется (например, юрист залогинен в КонсультантПлюс в **своём обычном Chrome**, где сохранён пароль), после поиска появляется модальное окно:

> **«Учётная запись занята. Проверьте, завершена ли работа с системой на другом компьютере или в другом браузере.»**
> кнопки: **«Попробовать ещё раз»** / **«Выйти из системы»**; область результатов — «Нет данных».

Обработка — **через юриста** (агент сам сессии не рвёт вслепую):
1. Агент распознаёт текст «Учётная запись занята» в snapshot/тексте и **останавливается**, сообщает юристу;
2. просит **завершить работу в другой сессии** (закрыть/выйти из КонсультантПлюс в обычном браузере);
3. после «готово» — **клик «Попробовать ещё раз»** и повтор поиска (§7.3 с шага 2);
4. **«Выйти из системы»** сам не нажимать — это разлогинит текущую (нужную) сессию.

Это не ошибка механизма, а поведение доступа — предупреждение об этом лимите см. также в §3.

## 8. Конфиденциальность

- В строку поиска КонсультантПлюс (свободной и облачной) **не вводить**: тексты договоров/документов клиента, ПДн, суммы, номера договоров, названия контрагентов сверх публичных реквизитов. Только правовой запрос и публичные идентификаторы (вид/орган/номер акта, тема, номер судебного дела).
- Облачная версия — авторизованная под личным пользователем; всё, что там запрашивается, привязано к его учётной записи. Это дополнительный довод не гонять через неё чувствительные формулировки.
- Логин/пароль — только в локальном `.env` (gitignored), не в отчётах, не в `workflow/`, не в коммитах. Общий разбор — `references/confidentiality-rules.md`.

## 9. Дисциплина цитирования и сверки (ключевой guardrail)

КонсультантПлюс — **Приоритет 2** (`references/source-hierarchy.md`): удобный интерфейс к первоисточникам, **не** сам первоисточник. Поэтому:

| Что нашли в КонсультантПлюс | Что делать перед выводом юристу |
|---|---|
| Федеральный ФЗ/ФКЗ/кодекс, его редакция | Вызвать `route_norm_verification(jurisdiction="RU", probe=true)`. Если КонсультантПлюс имеет `usable_now: true`, раскрыть полный текст и проверить редакцию/статус/pinpoint/provenance; иначе выбрать другой маршрут или поставить маркер |
| Подзаконный/ведомственный/региональный акт | Реквизиты (орган, дата, номер, рег. Минюста) взять из карточки; при выводе как основания — по возможности сверить с официальным опубликованием (`publication.pravo.gov.ru` / сайт органа). Не сверено — `[ПРОВЕРИТЬ ИСТОЧНИК]` |
| Судебный акт (практика) | Реквизиты **не выводить, пока первоисточник не открыт** (kad.arbitr.ru / текст акта) и позиция не сверена. КонсультантПлюс здесь — только навигационный лид (то же правило, что для агрегаторов в `references/web-research-tools.md` §3.1) |
| Комментарий, «Готовое решение», «Путеводитель», обзор | Это **навигация и аргументационный слой**, НЕ источник права. Использовать для поиска нормы/практики, цитировать — сам НПА/судебный акт после сверки |

Цитирование реквизитов — строго по `references/citation-rules.md` (акт, дата, номер, статья, часть, пункт, редакция; для практики — суд, вид акта, дата, дело, пункт, источник).

## 11. Актуализация протокола (версионирование)

Протоколы §6-7 могут устареть при смене вёрстки сайта. Признаки: `snapshot` не находит `textbox "Поиск: Кодексы, законы и другие материалы"` / `button "Найти"`; изменилась схема URL карточки.

Процедура (как в ТЗ-протоколе §15):
1. Юрист/агент открывает `agent-browser --headed open {URL}` руками;
2. делает `snapshot`, фиксирует новые подписи и ref-ы;
3. обновляет соответствующий раздел этого файла.

Пометка о верификации: **проверено вживую 2026-08-19 (agent-browser 0.27.1) — свободная версия §6; форма входа `login.consultant.ru` (`textbox "Введите логин"`, `textbox "Введите пароль"`, галочка «Запомнить меня» отмечена по умолчанию, `button "Войти"`); облако §7 — стартовая, Быстрый поиск (submit через focus+Enter), список результатов с реквизитами, модалка «Учётная запись занята» (§7.4). Тестовый запрос — «Приказ Минздрава России 4н», выдача корректна.** Подписи полей в облаке могут поменяться при обновлении интерфейса — тогда пересниммать snapshot и обновлять §7.2/§7.3.

## 12. Fallback-цепочки

| Этап | Primary | Secondary | Hard fallback |
|---|---|---|---|
| Найти документ | доступный discovery-provider | свободная `www.consultant.ru` (§6) | облако `cloud.consultant.ru` (§7, вход через юриста) |
| Открыть карточку | agent-browser `open` карточки | Tavily `/extract` / WebFetch по URL | ручной просмотр юристом, передача реквизитов в чат |

| Всё недоступно | Сообщить юристу о невозможности; **никаких выдуманных данных**; маркер `[ИНСТРУМЕНТ НЕДОСТУПЕН]` | | |
