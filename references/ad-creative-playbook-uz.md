# Рекламный плейбук РУз — индекс направлений анализа рекламного креатива (ЛП/БАД)

Плейбук проекта для проверки рекламных материалов по **лекарственным средствам и БАД на соответствие рекламному законодательству Республики Узбекистан**. Это **индекс-роутер**: краткие определения направлений + таблица триггеров. Содержательный материал (нормы, триггеры, критерии допустимого, где искать) — в карточках `references/ad-playbook-cards-uz/` (локальные `.md`, единственный содержательный источник плейбука).

**Юрисдикция — РУз, отдельный корпус `uzbek-legal-memory`.** Не смешивать с РФ. Российский плейбук `references/ad-creative-playbook.md` — **не применять** к узбекскому креативу.

**Правило подгрузки: не читать все карточки.** Классифицировать креатив по таблице триггеров ниже и открыть только сработавшие карточки (обычно 2–5). Если поиск по первой карточке дал слабую релевантность или найдены другие основания — вернуться в индекс и взять следующую карточку.

**Доступ к карточкам — локальные `.md` в `references/ad-playbook-cards-uz/`** (15 карточек). Открывать файл по таблице триггеров. UZ и KZ не смешивать. Карточка — методический слой, **не НПА**: перед правовым выводом вызвать `route_norm_verification(jurisdiction="UZ", probe=true)` и использовать только `usable_now: true`; при отсутствии маршрута открыть полный текст на lex.uz и сохранять `[ПРОВЕРИТЬ ИСТОЧНИК]` до проверки редакции, статуса и pinpoint.

**Статус.** Методологическая база проекта. Результат работы — всегда черновик для юриста. Ничего не финализировать/подавать/отправлять без проверки юристом.

**Происхождение и права.** Структура следует запретам Закона РУз «О рекламе» № ЗРУ-776 и типологии из ТЗ. Тексты норм — официальные акты lex.uz (грунт — корпус `uzbek-legal-memory`, ст. 16/18/31/34/35/47/49 извлечены из официального источника). Плейбук написан для проекта заново.

## Основной язык рекламных материалов

Реклама в РУз распространяется на **государственном (узбекском) языке** (ст. 6). Плейбук — на русском, но **обязательные формулировки предупреждений** («наличие противопоказаний / ознакомиться с инструкцией / консультация специалиста»; «не является лекарственным средством») берутся из **узбекского оригинала акта** — не выдумывать и не переводить машинно. Где текст не подтверждён — маркер `[ПРОВЕРИТЬ ИСТОЧНИК]`.

## Статусы источника в карточках

По методологии ТЗ каждое положение имеет статус:
- `[ЗАКОН]` — прямо установлено НПА (проверено в корпусе);
- `[ОФИЦИАЛЬНАЯ ПРАКТИКА]` — из официальной услуги/разъяснения/дела;
- `[РАБОЧАЯ ИНТЕРПРЕТАЦИЯ]` — вывод из совокупности норм;
- `[КОРПОРАТИВНЫЙ СТАНДАРТ]` — внутреннее правило строже закона;
- `[ОТКРЫТЫЙ ВОПРОС]` / `[ПРОВЕРИТЬ ИСТОЧНИК]` — требуется точечная проверка.

Корпоративный стандарт и рабочую интерпретацию **нельзя выдавать за прямое требование закона**.

## Алгоритм работы агента

1. **Вход**: текст/описание креатива + объект (Rx / OTC / БАД) + канал (ТВ, радио, наружная, интернет/соцсети, печать, маркетплейс, аптека, мероприятие) + аудитория (население / HCP).
2. **Gate-проверки до контента**: (а) применимость закона РУз (карточка 1); (б) регистрация продукта и статус Rx/OTC (карточка 5); (в) язык (карточка 2).
3. **Классификация**: пройти таблицу триггеров, зафиксировать сработавшие направления.
4. **Подгрузка**: открыть только карточки сработавших направлений из `references/ad-playbook-cards-uz/` (файл — по строке таблицы триггеров ниже). Отделить в карточке норму / рабочую интерпретацию / корпоративный стандарт / учебный сценарий / реальную практику; учебный сценарий не выдавать за правоприменительную практику.
5. **Грунтовка нормы**: локальные `get_uzbek_legal_card` / `search_uzbek_legal_memory` дают discovery и сохраняют `verification_status`. Затем вызвать `route_norm_verification(jurisdiction="UZ", probe=true)`; `not_verified` и отсутствие `usable_now: true` не позволяют использовать карточку как право. Наличие URL в evidence ≠ актуальность редакции.
6. **Вывод (два компонента)**: риск по `references/risk-scale.md`; **компонент 1** — правки «Было → Стало → Почему»; **компонент 2** — стоимость риска для бизнеса и принятие риска (санкция — ст. 47 Закона о рекламе + ст. 178¹ КоАО; иные последствия — непрохождение согласования канала, переделка ролика, срыв сроков; доведение суммы риска до бизнеса, запуск без устранения = принятие риска бизнесом, блокирующий риск принять нельзя). Правило — CLAUDE.md, «Блок „что поправить“». Результат — в `workflow/`.

## Ограничения (учитывать в каждом выводе)

- **Практики почти нет.** В отличие от РФ (база fas-search на ~7 770 решений УФАС), по РУз в корпусе практики нет; известен якорный кейс MO'JIZA HONEYMOON (БАД, лечебные claims). Прочие «учебные сценарии» в карточках помечены `[УЧЕБНЫЙ СЦЕНАРИЙ]` — это иллюстрация нормы, не практика.
- **Пробелы базы** (ТВ/радио ПКМ № 169; СанПиН-переход по БАД; фармнадзор) — под маркерами `[ПРОВЕРИТЬ ИСТОЧНИК]`.
- Санкции — `mcp__legal-kb` (ст. 47 ЗРУ-776; КоАО ст. 178¹). Ст. 189 КоАО — **только порнографическая продукция**, не общая рекламная ответственность.

## Типовые связки карточек

- **Публичный OTC-креатив**: 1 + 5 + 6 + 7 (+ 2 язык, + 11 если акция). Предупреждение (карточка 6) — обязательная проверка.
- **БАД**: 1 + 9 + 6(предупреждение-аналог) + 13; на стыке дат — 15.
- **Rx**: 5 (gate) + 8 (если для HCP) — блокирующие проверки до всего остального.
- **ТВ/радио ролик ЛС/БАД**: 12 (заключение Минздрава) + профильная карточка продукта.
- **Детское лекарство**: 10 + 5 (OTC-only) + 12 (если ТВ/радио).
