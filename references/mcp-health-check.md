# MCP Health Check — «настроен» vs «реально отвечает»

Протокол проверки живости MCP-коннекторов проекта. Различает три статуса («configured» vs «connected»): наличие сервера в конфиге не значит, что он отвечает; молчаливый отказ инструмента в середине задачи — худший сценарий (агент незаметно съезжает на память).

## Статусы

- **✓ connected** — probe-вызов в текущей сессии успешен;
- **⚪ configured** — сервер числится в конфиге (`.mcp.json` проекта или пользовательский уровень), но в этой сессии не проверялся; для некритичных задач допустимо, для критичных — сначала probe;
- **✗ not responding** — probe упал или инструменты сервера недоступны → работать по fallback из таблицы и **явно сообщить юристу**.

## Когда запускать

1. Юрист просит («проверь коннекторы», «почему база молчит»).
2. MCP «странно себя ведёт» — сначала `mcp__legal-overlay__overlay_status(probe=true)`, затем status затронутого provider.
3. Перед задачей, критично зависящей от конкретного коннектора: `counterparty-check` → DaData; `fas-ad-practice-search` → fas-search; проверка нормы → `route_norm_verification(jurisdiction=..., probe=true)` и только `usable_now: true`.
4. **Не гонять на каждый старт сессии** — лишние вызовы; probe только по триггерам выше.

## Таблица probe (дешёвые read-only вызовы)

| Сервер | Probe | Fallback при ✗ |
|---|---|---|
| `legal-overlay` | `overlay_status(probe=true)` + `sqlite_legal_ru_status()` / `sqlite_legal_memory_status()` | Не отвечать по памяти: явно назвать недоступный слой; для НПА перейти к официальному источнику |
| `dadata` | **Вхолостую не пробовать** (платные лимиты API): статус ⚪ до первого рабочего вызова; если задача требует DaData — первый реальный запрос по делу и есть probe | `[DADATA НЕДОСТУПНА]` + ручная проверка по egrul.nalog.ru (`references/web-research-tools.md`, раздел 3.3) |
| `fas` через Legal Overlay | `list_fas_filter_options()`; только перед задачей, не на каждый старт | Если direct provider недоступен — поиск через веб (br.fas.gov.ru, Tavily/WebSearch) с обязательным открытием первоисточника; server fallback отключён |

Внешние плагиновые коннекторы (Box, Slack, DocuSign и т. п.) требуют OAuth-авторизации юриста — **не проверять автоматически**; при необходимости сообщить, что нужна авторизация через настройки коннекторов, и работать без них.

## Формат отчёта юристу

Коротко, по строке на сервер, только по факту probe:

```
MCP: legal-overlay ✓ · FAS provider ✗ (работаю через веб-поиск br.fas.gov.ru) · dadata ⚪ (проверится первым запросом)
```

При ✗ — указать fallback и что можно сделать (перезапуск сессии; `claude mcp` в интерактивном терминале; проверить `.mcp.json` / пользовательский конфиг). **Не чинить конфиги и не перезапускать серверы молча** — только по указанию юриста (правило «Заморозка» в CLAUDE.md сохраняется).

## Ограничения

- Probe проверяет **живость канала**, а SQLite status дополнительно проверяет manifest/hash/integrity.
- ✗ одного сервера не повод переносить его задачи на другой корпус (юрисдикции и слои не смешивать).
