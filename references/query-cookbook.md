# Query Cookbook — маршрутизатор задача → база → запрос

Назначение: юрист формулирует задачу **на естественном языке**, не помня запросы каждой базы. Этот файл фиксирует, **в какую базу и каким инструментом** превращается типовая задача, и используется агентом **автоматически** в начале любой задачи, затрагивающей базы.

У каждой базы свой «язык» (набор инструментов и параметров). Агент сам подбирает нужный, при неоднозначности — задаёт 1-2 уточняющих вопроса (см. «Разрешение неоднозначности»).

## Процедура маршрутизации (выполнять в начале задачи)

**Главное правило (MVP-риск №1): не отвечать из общего знания.** Сначала маршрутизировать запрос и взять данные из базы, потом отвечать. Нельзя «примерно знать» норму и пропустить наши статусы/ограничения (verification_pending, not_verified, deferred, какая юрисдикция). Общее знание — только как обвязка вокруг данных из базы, не вместо них.

1. **Определить намерение** задачи (что юрист на самом деле ищет — см. таблицу ниже).
2. **Определить юрисдикцию — до поиска** (дерево ниже). Если не очевидна — `legal-overlay.route_legal_query(query)`.
3. **Если намерение неоднозначно** — задать 1-2 коротких уточняющих вопроса. Не больше.
4. **Подобрать базу + инструмент + форму запроса** по таблице.
5. **Выполнить родной запрос** базы; при необходимости — цепочку (например, поиск → полный текст → связи).
6. **После поиска — раскрыть релевантную карточку** (`get_uzbek_legal_card` / `get_document` / `get_legal_text`), если нужен точный ответ, а не только список.
7. Дальнейшие правила цитирования/маркеров — `references/source-hierarchy.md` (Рабочий цикл).

## Дерево маршрутизации по юрисдикции (до поиска)

1. Юрисдикция не очевидна → `route_legal_query(query)`.
2. `route = russia_eaeu` или `default_main_corpus` → НПА/практика через `search_legal_kb`; доктрина через `search_doctrine`.
3. `route = russia_doctrine` → `search_doctrine`, затем `get_doctrine_unit`; нормы и судебные акты проверяются отдельно.
4. `route = russia_labor_guidance` → `search_official_labor_guidance`, затем `get_official_labor_guidance`; параллельно найти применимую норму через `search_legal_kb` и проверить её обычным capability-маршрутом.
5. `route = uzbekistan` → `search_uzbek_legal_memory`. Если router вернул `collections` — передать подходящую в параметр `collection`: `advertising`, `medicines`, `registration`, `liability`, `permits`.
6. `route = needs_clarification` → **базы не смешивать**; уточнить юрисдикцию у юриста. Исключение — юрист явно просит сравнение РФ vs Узбекистан.
7. **Узбекистан:** `not_verified` карточки **не использовать как право**.
8. `verification_pending` — только как **указатель на необходимость проверки**, не как подтверждённую норму (маркер `[ПРОВЕРИТЬ ИСТОЧНИК]`).
9. **Санкции за рекламу в Узбекистане:** использовать **ст. 47 Закона о рекламе** (Law on Advertising, article 47 units) и **ст. 178¹ КоАО**. **Ст. 189 — только для порнографической продукции**, не как общая ответственность за рекламу.
10. После поиска всегда раскрыть нужную карточку (`get_uzbek_legal_card` / `get_document` / `get_legal_text` / `get_doctrine_unit` / `get_official_labor_guidance`), если требуется точный ответ.

## Базы — одной строкой

| База | За чем идти |
|---|---|
| **Legal Overlay** (namespace `legal-overlay`) | Единый provider-neutral вход: `legal_search`, local curated/verified knowledge, FAS tools, source profiles и прозрачные fallbacks |
| **`local-legal-ru-sqlite`** (через `legal-overlay`) | Основной локальный immutable корпус РФ/ЕАЭС: НПА, позиции/практика, обзоры и связи; legacy-доктрина исключена; snapshot status/freshness — `sqlite_legal_ru_status` |
| **`local-legal-uz-sqlite`** (через `legal-overlay`) | Право Узбекистана — **отдельный локальный корпус**; сохранять `verification_status`, `not_verified` не использовать как право |
| **`local-legal-doctrine-sqlite`** (через `legal-overlay`) | Канонический локальный корпус доктрины: `search_doctrine` → `get_doctrine_unit`; только `doctrine_only`, нормы и дела проверять отдельно |
| **`local-legal-memory-sqlite`** (через `legal-overlay`) | Opinions, reviewed Telegram, MOC и FAQ Роструда; трудовой слой имеет `administrative_guidance` и не является НПА |
| ~~`legal-pharma-memory`~~ | Отдельный MCP выведен (2026-08-31). НПА/практика/граф находятся в `legal-ru.sqlite`, доктрина — в `legal-doctrine.sqlite`, opinions/reviewed Telegram/MOC — в `legal-memory.sqlite` |
| Портал `pravo.gov.ru` | Прямой verification-provider для федеральных актов; выбирать через `route_norm_verification(..., probe=true)` (`references/web-research-tools.md`, раздел 3.2) |
| **`dadata`** | Контрагент по ИНН/ОГРН (карточка ЕГРЮЛ/ЕГРИП) |
| **FAS provider через Overlay** | Практика ФАС по рекламе; flat tools не раскрывают URL/transport и возвращают provider/fallback provenance |
| **Glossa через Overlay** | Доктринальное толкование гражданского права, supports/limits/contradicts; покрытие сначала через `glossa_stats`, норму сверять отдельно |
| **Casus: main / SIP / KAS / KUD** | Единый `casuslegal_*` connector; выбирать разрешённый corpus до поиска, snippet раскрывать через `casuslegal_get_case_details` с тем же corpus |
| **ПравоТех Консультант** | Платная вторичная консультация после OAuth; `consultation` только по явному подтверждению расхода, не источник проверки нормы |
| **КонсультантПлюс через Overlay** | **Основной внешний источник для НПА и судебной практики**: `consultant_search` → `consultant_get_text` / `consultant_get_document`; запросы только в абстрагированном виде, карточка остаётся навигацией, судебный акт и опубликование сверяются по официальному первоисточнику |
| **ГАРАНТ через Overlay** | Отключён; не вызывать и не использовать как fallback без нового явного решения юриста |
| Веб (Приоритет 1) | Подзаконка, региональное право, практика вне локального слоя, kad.arbitr.ru, сайты ведомств |

## Таблица: намерение → запрос

### Второе мнение ПравоТех

| Намерение | Маршрут |
|---|---|
| «Спроси ПравоТех по этому вопросу» | Собрать полный обезличенный вопрос по шаблону `references/external-legal-databases.md` → один `consultation(..., _confirm_paid_call=true)` → независимо проверить `sources` |
| «Предложенные варианты меня не устраивают; дай другое мнение» | Сначала показать юристу полный вопрос для ПравоТех и получить подтверждение расхода → запросить adverse/альтернативный анализ → сопоставить с исходным выводом |
| `submitted_pending_account_check` после ПравоТех | Не повторять вызов → сообщить, что результат MCP неизвестен, хотя вопрос мог быть принят → попросить открыть личный кабинет и передать появившийся ответ для независимой проверки |
| «Найди статью / проверь редакцию нормы» | **Не ПравоТех**: `route_norm_verification(probe=true)` → provider с `usable_now: true`; ПравоТех не raw-СПС |

### Судебная практика / позиции ВС РФ
| Намерение юриста | Запрос |
|---|---|
| «практика ВС по теме» | `legal-overlay.search_positions(topic="Банкротство", limit=10)` |
| «позиции по статье кодекса» | `legal-overlay.search_positions(article="ст. 404 ГК РФ", limit=10)` |
| «по ключевому слову» | `legal-overlay.search_positions(keyword="аренда", limit=10)` |
| «по номеру дела» | `legal-overlay.search_positions(case_number="305-ЭС24-13688", limit=5)` |
| «по фразе/формулировке» | `legal-overlay.search_positions(query="добросовестно и разумно", limit=10)` |
| «к каким нормам привязана позиция» | `legal-overlay.list_position_norm_links(unit_id=...)` — **до утверждения о связи** |
| «позиции с неразрешёнными связями» | `legal-overlay.search_positions(link_status="unresolved", limit=10)` |
| «практика высших судов вне локального корпуса» | Casus: `casuslegal_search_practice(corpus="main")` → `casuslegal_get_case_details(corpus="main")`; отдельно поискать контраргумент |
| «практика СИП / по IP» | Casus: `casuslegal_search_practice(corpus="sip")` → `casuslegal_get_case_details(corpus="sip")`, только если `sip` разрешён после smoke |
| «административное / уголовное дело ВС» | соответственно `casuslegal_*(corpus="kas")` или `casuslegal_*(corpus="kud")`; не смешивать corpus и case ID |

Цитировать: `case_number` + `decision_date_text` + `unit_heading`; нормы — только при `links_summary.resolved > 0`.

### Норма: найти / текст / актуальность
| Намерение | Запрос |
|---|---|
| «найди норму по теме» | `legal-overlay.legal_search(issue="реклама лекарственных средств", jurisdiction="RU", source_types=["legislation"], data_classification="public_or_abstracted")`; затем раскрыть источник |
| «найди закон по номеру» | `legal-overlay.legal_search(issue=..., jurisdiction="RU", source_types=["legislation"], act_number="61-ФЗ", act_date="2010-04-12", official_verification=true, data_classification="public_or_abstracted")` |
| «полный текст нормы/закона» | discovery: `legal-overlay.get_legal_text(document_id)`; verification: `route_norm_verification(jurisdiction=..., probe=true)` → раскрыть документ только у provider с `usable_now: true` |
| «структура документа (главы/статьи)» | `legal-overlay.get_document_outline(document_id)` |
| «действует ли норма / актуальная редакция» | `route_norm_verification(jurisdiction=..., probe=true)` → полный текст через `usable_now: true`; проверить редакцию, статус, pinpoint, provenance |
| «существует ли такая ссылка» (перед сохранением) | `find_federal_act` — только discovery; затем capability-verification полного текста. `NOT_FOUND` означает пробел покрытия; нет пригодного маршрута → `[ПРОВЕРИТЬ НОРМУ]` |
| «разобрать готовую ссылку на ФЗ/ФКЗ» | `legal-overlay.check_norm_reference(reference_text="...")` — парсит номер федерального акта и ищет его в локальном snapshot. Статусы: `FOUND`, `NOT_FOUND`, `UNPARSED`. Это discovery: `NOT_FOUND` — пробел покрытия, `UNPARSED` — номер не распознан, акт не угадывать. Редакцию этим вызовом не проверять |

Если пользователь дал точный номер акта (`61-ФЗ`, `127-ФЗ`, `N 462`, `№ 686`), не начинать с широкого `search_legal_kb`: сначала `find_by_act_number`. Широкий поиск использовать после этого только если нужен тематический контекст или номер плюс слова.

### Правовой вывод / аргументация (анализ договора, позиция для суда, ответ госоргану)

Для этих задач используется особый порядок: сначала понять толкование, потом сверить с нормой. Полный алгоритм — `references/source-hierarchy.md`, раздел «Workflow для правовых выводов».

| Намерение | Запрос |
|---|---|
| «как норму толкуют» (доктрина, вход для вывода) | **`legal-overlay.search_doctrine(query=...)` первым**, затем раскрыть нужный unit через `get_doctrine_unit(unit_id, offset, limit)`; нормы и дела из карточки проверить отдельно |
| «нужно глубокое доктринальное обоснование по гражданскому праву» | После локальной доктрины: `glossa_stats` → `glossa_support` → `glossa_get_point`; раскрыть supports/limits/contradicts и не приписывать автору чужой `voice` |
| «как суды рассуждали по теме» (обзоры практики) | `legal-overlay.search_comments(query=...)` — обзоры практики / `court_practice_item` |
| «позиции ВС по теме/статье» | `legal-overlay.search_positions(topic=...|article=...|keyword=...)` — для **уже выделенных** правовых/судебных позиций; это дополнение к `search_doctrine`, не замена доктринального входа |
| «прочитать найденную карточку» | `get_doctrine_unit(unit_id, offset, limit)` — для доктрины; `get_comment_position(unit_id)` — для судебной позиции; `get_document(document_id)` / `get_legal_text(document_id)` — для НПА и оставшихся RU-карточек |
| «к каким нормам привязана позиция» | `list_position_norm_links(unit_id)` — **только после того, как позиция найдена** |
| «поддельная/спорная подпись, ссылка на ничтожность, формальный дефект уведомления, противоречивое поведение стороны» | `search_doctrine` и `search_positions` по словам **«эстоппель», «добросовестность», «формальный дефект»**; различать исцеление сделки / утрату права на оспаривание / отказ в защите / фикцию доставки / доказательственные последствия |
| «договор уступки, цессия, покупка требования, уведомление должника, ответственность цедента» | `search_doctrine("уступка требования цессия уведомление должника")` → раскрыть релевантные positions/comments через `get_doctrine_unit`; затем проверить нормы ст. 382–390 ГК РФ и судебную практику отдельно |
| «нарушение договора, просрочка, взыскание санкций, убытки, неустойка, проценты, форс-мажор, лимит ответственности» | `search_doctrine("нарушение договора убытки неустойка проценты ответственность")`; не смешивать убытки, неустойку, проценты, возмещение потерь и договорные лимиты; связанные нормы и практику проверить отдельно |
| «недействительность сделки (любой состав)» | `search_doctrine("проверка недействительности сделки")` → определить конкретный дефект и режим; затем отдельно проверить норму, судебную практику и последствия |
| «договор аренды: анализ, спор, расторжение, возврат имущества, арендная плата, субаренда» | `search_doctrine("проверка договора аренды")` → раскрыть подходы через `get_doctrine_unit`; затем `search_positions(keyword="аренда")` и отдельная проверка применимых норм |
| «ситуация похожа, но не та же» | допустима аналогия — маркер по формуле `[ПРИМЕНЯЕТСЯ ПО АНАЛОГИИ: …]` из `references/citation-rules.md` |

### Трудовые отношения (работники): дисциплинарка, постановка задач

**Правило.** При анализе документов **в отношении работников** — дисциплинарное взыскание (приказ, объяснительная, акт, служебная записка) и постановка задач (приказ, распоряжение, должностная инструкция, KPI) — искать не только нормы трудового права и ТГ-комментарии по трудовому праву, но **дополнительно комплаенс-требования из ТГ-комментариев** (антикоррупционные политики, конфликт интересов, внутренние регламенты/кодексы, комплаенс-процедуры). Оба слоя ТГ — низкоавторитетный комментарий, не источник права; норма — из ТК РФ.

| Намерение юриста | Запрос |
|---|---|
| «норма ТК по дисциплинарке / задачам работнику» | `legal-overlay.search_legal_kb(query=...)` (ТК РФ); нет в базе → `pravo.gov.ru` |
| «официальное разъяснение Роструда по трудовому вопросу» | `legal-overlay.search_official_labor_guidance(query=...)` → `get_official_labor_guidance(path=...)`; вывести `source_url`, provenance и явную маркировку «официальное ненормативное разъяснение»; норму проверить отдельно |
| «что пишут в ТГ по трудовому праву» | `legal-overlay.search_telegram_reviewed(query="<тема>", channel="labor")`; открыть выбранную карточку через `get_telegram_reviewed`. По умолчанию выдаются только `keep_commentary` / `keep_guideline`; норму и практику проверить отдельно |
| «комплаенс-требования по теме (обязательно, не пропускать)» | `legal-overlay.search_telegram_reviewed(query="<тема>", channel="comply")` + `search_comments`; обязательность подтверждать НПА/официальной политикой, а не Telegram-карточкой |

Трудовой слой Роструда (`labor_official`) доступен через `search_official_labor_guidance` / `get_official_labor_guidance` и остаётся официальным ненормативным разъяснением. ТГ-слой (`telegram_reviewed`) доступен через `search_telegram_reviewed` / `get_telegram_reviewed`, но остаётся вторичным контекстом. Дисциплинарный порядок и сроки в любом случае — из ТК РФ (ст. 192–193), а не из этих контекстных слоёв.

### Фарма-контекст / внутреннее знание
| Намерение | Запрос |
|---|---|
| «что у нас есть по теме» (старт тематической задачи) | `legal-overlay.list_topic_maps()` → `get_topic_map(path_or_slug=...)`; дополнительно `list_relation_hubs(limit=20)` для автоматических узлов графа и `search_legal_kb(query=...)` |
| «наши заключения по вопросу» | `legal-overlay.search_legal_opinions(query=...)` → `get_legal_opinion(path=...)`; это внутренний слой согласованности, не источник права |
| «разъяснения/комментарии ведомств» | `legal-overlay.search_comments(query=...)` |
| «что пишут юристы в telegram» | `legal-overlay.search_telegram_reviewed(query=..., channel/topic/status=...)` → `get_telegram_reviewed(path=...)`; использовать как вторичный комментарий с указанием channel/status, первоисточник проверять отдельно |
| «доктрина/развёрнутые комментарии» | `legal-overlay.search_doctrine(query=...)` → `get_doctrine_unit(unit_id, offset, limit)` |
| «поиск вообще по всему» | `legal-overlay.search_all_legal_memory(query=...)` |
| «проверенная локальная заметка» | `legal-overlay.search_verified_knowledge(query=...)` → `get_verified_knowledge(knowledge_id=...)`. Только объекты со статусом human-verified; кандидаты в выдачу не попадают. Внутреннее знание, не НПА |
| «что говорит playbook или карточка методики» | `legal-overlay.search_local_curated(query=...)` → `get_local_curated(path=...)`. Allowlist канонических файлов в `references/`; методика, не источник права |

### Связи между актами
| Намерение | Запрос |
|---|---|
| «что детализирует норму / кто на неё ссылается» | `legal-overlay.get_document_relations(document_id, direction="both")` |
| «узловые акты темы» | `legal-overlay.list_relation_hubs(limit=20)` |
| «соседи документа в графе» | `legal-overlay.get_document_relations(document_id, direction="both")` / `get_legal_graph_neighbors(...)` |

Для судебных/правовых позиций связи с нормами проверяются не через `get_document_relations`, а через `list_position_norm_links(unit_id)`. `get_document_relations` относится к runtime-графу "документ -> документ"; если health показывает `document_relations = 0`, не делать вид, что документный граф построен.

## Разрешение неоднозначности (когда задавать вопрос)

Слово-концепт без контекста (например «аренда», «неустойка», «банкротство») может означать разное. Прежде чем выбирать базу — уточнить **одним вопросом**:

- **«аренда»** → нужна *практика ВС* (`search_positions`), *текст нормы* (`search_legal_kb`, при отсутствии — `pravo.gov.ru`), или *наш внутренний контекст по делу* (`case-context.md` дела в `workflow/`)?
- **«проверь …»** → если это ИНН/ОГРН — контрагент (`legal-overlay.dadata_party`); если ссылка на норму — discovery в Overlay, затем `route_norm_verification(jurisdiction=..., probe=true)` и только маршрут с `usable_now: true`; если «актуальна ли» — тот же capability-маршрут.
- **«обзор / дайджест / что изменилось»** → `skills/legal-digest/SKILL.md`, если нужен выпуск об изменениях. Вопрос «можно ли нам» остаётся заключением.
- **Тема для `search_positions`** должна совпадать со словарём тем базы (напр. «Банкротство»). Если тема неизвестна — использовать `keyword`/`query` вместо `topic`.
- Если намерение ясно из формулировки — **не переспрашивать**, действовать.

## Query expansion — словарь расширения запросов

Поиск `search_legal_kb` — **лексический** (совпадение терминов, не смысла): «образ врача» не найдёт карточку со словами «медицинский работник». Поэтому:

**Правило.** Если первый запрос дал пустую или бедную выдачу (< 2–3 релевантных результатов) — **обязательно** прогнать 2–4 расширенных варианта из словаря ниже (и своих синонимов по смыслу), прежде чем заключать «в локальной базе не найдено». Одна формулировка ≠ проверка базы. Обратное тоже верно: для поиска по vault/telegram-карточкам нормативный термин расширять бытовым (карточки часто написаны разговорным языком).

**Сочетание слов, а не одно слово.** Искать 2–3 смысловыми словами из сути вопроса («недостатки товара приемка», а не «недостатки»): одно слово тонет в выдаче, сочетание поднимает нужное наверх. Служебные слова в запрос не включать. Локальная база сама приводит русские слова к основе (поиск по основам, с 2026-10-30), К+ учитывает словоформы сам, поэтому слова пишутся в обычной форме. Исключение — беглая гласная: «недостаток» и «недостатки» основы не сводят, при пустой выдаче повторить запрос в другой форме слова.

**Словарь «бытовой/деловой термин → нормативные и судебные синонимы»** (домены практики):

| Сказано / подумалось | Искать также |
|---|---|
| образ врача (в рекламе) | медицинский работник, фармацевтический работник, образы медицинских работников |
| БАД | биологически активная добавка, не является лекарственным средством |
| лекарство | лекарственное средство, лекарственный препарат, ЛП |
| отзыв серии / отозвать препарат | изъятие из обращения, приостановление реализации, недоброкачественный, фальсифицированный |
| расторгнуть договор | односторонний отказ от исполнения, отказ от договора, существенное нарушение, расторжение по соглашению |
| не платит / задержка оплаты | просрочка оплаты, встречное исполнение, приостановление исполнения, задолженность |
| вернуть товар / деньги | отказ от товара, возврат уплаченного, неосновательное обогащение |
| штраф (договорный) | неустойка, пени, ответственность за нарушение обязательства |
| пролонгация | возобновление договора, продление срока действия, автоматическое продление |
| предоплата | аванс, предварительная оплата, коммерческий кредит |
| гарантия (в договоре) | заверения об обстоятельствах, гарантийный срок, качество товара |
| переуступка | уступка требования, цессия, перевод долга, замена стороны |
| пропустил срок (процесс) | восстановление пропущенного срока, исковая давность, уважительные причины |
| жалоба на решение суда | апелляционная жалоба, кассационная жалоба, обжалование, отмена судебного акта |
| проверка (госорган) | контрольное (надзорное) мероприятие, КНМ, выездная проверка, документарная проверка |
| предписание | предписание об устранении нарушений, представление, требование |
| субсидиарка | субсидиарная ответственность, контролирующее должника лицо, КДЛ |
| банкротство контрагента | несостоятельность, конкурсное производство, реестр требований кредиторов |
| маркировка (лекарств) | мониторинг движения лекарственных препаратов, МДЛП, средства идентификации |

**Пополнение словаря** — часть работы: если переформулировка нашла то, что исходный запрос не нашёл, — дописать пару в таблицу (техническая правка, разрешена).

## Принципы

- Кукбук — **карта запросов**, а не догма: если задача нетипичная, агент комбинирует инструменты по смыслу.
- Локальные базы — **первыми** (Приоритет 0), затем веб (Приоритет 1). Полная иерархия и правила маркеров — `references/source-hierarchy.md`.
- При добавлении нового инструмента в любую базу — дописывать строку сюда, чтобы кукбук оставался актуальным.
