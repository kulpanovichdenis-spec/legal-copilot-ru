# Court Online Resolver — определение конкретного суда, адреса и реквизитов

Надстройка над общим слоем `references/web-research-tools.md` (тот же принцип, что у `references/trademark-search-automation.md` и `references/consultant-plus-automation.md`). Применяется **после** того, как нормативная часть (`references/court-jurisdiction-playbook.md`) определила `court_system` + `court_level` + `jurisdiction_anchor`.

**Обязательный принцип Online First (ТЗ §3).** Cache ускоряет, но не является source of truth. Перед статусом `CONFIRMED` — online-проверка конкретного суда, официального сайта, территории, адреса и реквизитов, даже если те же данные уже есть в cache.

## 1. Иерархия официальных источников (ТЗ §46-48)

| Tier | Что | Источники | Использование |
|---|---|---|---|
| **Tier 0** | Нормативный официальный источник | `pravo.gov.ru`, официальные сайты ВС РФ, госорганов | Для текста норм — см. `references/web-research-tools.md` §3.2 |
| **Tier 1** | Конкретный суд | `arbitr.ru` (перечень арбитражных судов и их адреса), `sudrf.ru` (ГАС «Правосудие» — федеральные СОЮ + определение территориальной подсудности), `msudrf.ru` (мировые судьи), `mos-gorsud.ru` / `mos-sud.ru` (Москва — СОЮ и мировые судьи отдельно), `vsrf.ru` | **Основной источник** конкретного суда, адреса, территории |
| **Tier 2** | Региональные официальные ресурсы | Собственные официальные системы отдельных субъектов РФ для мировых судей (если официальный сайт суда/региона отличается от `msudrf.ru`) | Допустимо, если субъект использует свою систему |
| **Tier 3** | Discovery only | Поисковики, карты, справочники, коммерческие базы (2ГИС, Rusprofile и т. п.) | **Только** для поиска кандидата на «какой суд/участок» — не источник для `CONFIRMED`. Обязательно перейти к Tier 1 за подтверждением |

**Запрет (ТЗ §49).** Сниппет поисковика («улица X относится к суду Y») — не доказательство. Всегда переходить на официальную страницу конкретного суда/сервиса территориальной подсудности.

## 3. Алгоритм определения конкретного суда

### 3.1. Арбитражный суд (после определения субъекта РФ)

1. Официальный сайт суда субъекта — по подтверждённому паттерну `<код-региона>.arbitr.ru` (транслитерация региона, не всегда очевидная — при сомнении искать по названию суда через WebSearch/Tavily с `include_domains=["arbitr.ru"]`, **не** генерировать субдомен по шаблону вслепую, это остаётся навигационным лидом до фактического перехода — ТЗ §54).
2. Если по playbook применяется специальное правило (СИП, окружной суд как первая инстанция) — обычный resolver субъекта **не используется**, искать напрямую официальный сайт СИП/окружного суда.
3. Открыть официальную страницу найденного суда → адрес, раздел «Государственная пошлина» / «Реквизиты» (структура раздела на сайтах отдельных арбитражных судов не унифицирована с СОЮ — не тестировалась в этой сессии, требует отдельной проверки при первом реальном деле).
4. Сохранить `source_url` + `retrieved_at` для каждого извлечённого поля (ТЗ §80).

### 3.2. Районный суд СОЮ — Москва (протокол подтверждён live-recon 16.09.2026)

```bash
agent-browser open https://www.mos-gorsud.ru/territorial
agent-browser wait --load networkidle
agent-browser snapshot -i
# → textbox "Адрес или объект" (динамический ref, пере-снапшотить каждый раз)
agent-browser fill @<ref_textbox> "Москва, <улица>, дом <N>[, корпус <K>][, строение <S>]"
agent-browser click @<ref_найти>
agent-browser wait 3000
agent-browser snapshot -i -c
# → появляется: link "<Название> районный суд" + телефон + email +
#   link "Перейти к зданию суда" (javascript, карта — не URL) +
#   link "Перейти на страницу суда" (href вида "/rs/<slug>")
```

Проверено на тестовом адресе «Москва, Тверская улица, дом 13» → корректно вернуло «Тверской районный суд» с телефоном/email и ссылкой на `/rs/tverskoj`. Поле принимает адрес одной строкой и резолвит без выбора из выпадающего списка (в отличие от `sudrf.ru`, ниже) — но **номер дома обязателен** (ТЗ §43): без него сервис либо не резолвит, либо резолвит неоднозначно (не проверено намеренно — не тестировать без номера дома, это подтверждённое поведение только для полного адреса).

**Страница суда** (`https://www.mos-gorsud.ru/rs/<slug>`) содержит прямые ссылки: «Реквизиты для оплаты государственной пошлины» (`.../services/gosudarstvennaya-poshlina`), «Калькулятор госпошлины» (`.../services/calc` — независимая сверка расчёта, см. §5.3), а также отдельные реквизиты для обеспечительных мер/залога/депозита на экспертизу. Страница реквизитов пошлины показывает **дату последнего обновления** прямо на странице (`Последнее обновление выполнено ДД.ММ.ГГГГ ЧЧ:ММ:СС`) — использовать как `page_updated_at` без досчитывания.

### 3.2a. Районный суд СОЮ — остальные регионы (инструмент найден, но временно недоступен)

`sudrf.ru/index.php?id=300&var=true` — **это НЕ форма быстрого поиска суда по названию** (та отдельная, доступна с `id=300` без `#podsud`/без клика по ссылке «Поиск по территориальной подсудности» — ищет по наименованию судебного органа + субъекту, не по адресу). Настоящий адресный резолвер — по ссылке **«Поиск по территориальной подсудности»** на этой же странице (открывает `#podsud`), интерфейс идентичен московскому (textbox с автодополнением адреса + «Найти»).

**Проверено 16.09.2026 на тестовом адресе «Новосибирск, Красный проспект 34»**: сайт сам показывает баннер **«В настоящее время проводится актуализация (наполнение) информации о территориальной подсудности суда»** и возвращает «Не удалось определить подсудность для указанного адреса» независимо от корректности адреса — это подтверждённое состояние сервиса на дату проверки, не ошибка ввода. Это относится и к вкладке районных судов, и к вкладке мировых судей (баннер идентичен на обеих).

**Инструкция для агента**: перед тем как трактовать пустой результат `sudrf.ru` как «адрес не резолвится», проверить текст страницы на этот баннер (`get text body` содержит «актуализация»). Если баннер есть — сервис недоступен **для всех адресов**, не только текущего; переходить к fallback:
1. WebSearch/Tavily: `"<город>" районный суд официальный сайт` — найти кандидата, подтвердить через официальный сайт найденного суда (Tier 1), не по сниппету.
2. Если у суда есть страница «Территориальная подсудность» на собственном сайте (как у судов, подключённых к региональному ГАС-порталу) — использовать её напрямую.
3. Если ничего не подтверждает территорию — `LEGAL_CONFIRMED_OPERATIONAL_UNVERIFIED`, не гадать.

Перепроверить состояние баннера при каждом использовании — это может быть временным (актуализация может завершиться), а не постоянным ограничением.

### 3.3. Мировой судья

Недостаточный результат — «мировой судья Н-ского района» (ТЗ §52). Требуется: **судебный участок № N**, официальная страница участка.

**Москва (протокол подтверждён live-recon 16.09.2026)** — идентичен §3.2, домен `mos-sud.ru/territorial` вместо `mos-gorsud.ru`. Тот же тестовый адрес вернул «Участок №423» с телефоном/email и ссылкой на страницу участка (`href="/423"` относительно `mos-sud.ru`).

**Остальные регионы** — `msudrf.ru` не портал, а хостинг отдельных сайтов на один судебный участок (`<номер>.<регион>.msudrf.ru`, см. таблицу §2). Найти конкретный участок:
1. `sudrf.ru/index.php?id=300&var=true` → «Поиск по территориальной подсудности» на вкладке мировых судей — если недоступно (баннер §3.2a), fallback ниже.
2. Официальная система судебного департамента субъекта (Tier 2), если она есть отдельно от `msudrf.ru`.
3. WebSearch с `site:msudrf.ru "<город/район>"` — discovery only (Tier 3), подтверждение — переходом на найденный `<N>.<регион>.msudrf.ru` напрямую.

### 3.4. Суд с несколькими зданиями (ТЗ §53)

Если официальный сайт указывает несколько адресов (`postal`/`filing`/`courthouse`/`category_specific`) и невозможно однозначно определить применимый для данной категории дела — не выбирать наугад:

```
Суд определён. У суда несколько зданий.
Конкретное здание для данной категории дела автоматически не подтверждено.
MANUAL CHECK REQUIRED.
```

## 4. Official URL Verification (ТЗ §54)

URL считается official только если:
- получен через официальный каталог (`arbitr.ru`, `sudrf.ru` и т. п.), **или**
- относится к whitelisted официальному домену (таблица §2 выше), **или**
- подтверждён официальной страницей вышестоящей судебной системы.

**Запрещено** генерировать URL суда по шаблону (например, «наверное, `<город>.sudrf.ru`») и считать его проверенным без фактического перехода и подтверждения.

## 5. State Duty Payment Resolver — online only (ТЗ §73-79)

Реквизиты для оплаты пошлины **не берутся из памяти модели** ни при каких обстоятельствах — они меняются независимо от нормы (ТЗ §58) и не входят в state duty calculator (`tools/court_jurisdiction/`, который считает только сумму).

```
определён суд → официальный сайт → раздел «Государственная пошлина» / «Реквизиты»
→ извлечение полей → нормализация → validation → финальный результат
```

### 5.1. Поля (ТЗ §74)

```yaml
payment_details:
  recipient_name:
  recipient_inn:
  recipient_kpp:
  bank_name:
  bik:
  beneficiary_account:
  treasury_account:
  kbk:
  oktmo:
  payment_purpose:
  source_url:
  page_updated_at:
  checked_at:
```

### 5.2. Нормализация (ТЗ §75)

- Убрать случайные переносы строк из скопированного текста.
- **Не удалять ведущие нули** (счета, КБК, БИК, ОКТМО).
- **Не преобразовывать в number** — хранить строками (иначе ведущие нули/точность ломаются).

### 5.3. Двойная проверка и конфликт (ТЗ §76-77)

При возможности сверить официальную страницу суда и данные ФНС/Казначейства по тому же КБК. При расхождении между источниками — **не выбирать самостоятельно**:

```yaml
status: MANUAL_REVIEW_REQUIRED
warning:
  type: OFFICIAL_SOURCE_CONFLICT
```

Показать оба варианта юристу с обоими `source_url`.

### 5.3а. Живой пример (Тверской районный суд, Москва, проверено 16.09.2026)

Страница `https://www.mos-gorsud.ru/rs/tverskoj/services/gosudarstvennaya-poshlina` содержит два блока реквизитов (получатель обоих — «Казначейство России (ФНС России)», разные КБК и назначение платежа): один — для пошлины **при подаче** заявления (КБК `18210803010011050110`), второй — для пошлины, **уплачиваемой на основании судебного акта** по итогам рассмотрения дела (КБК `18210803010011060110`). Реквизиты обоих блоков (счёт, корр. счёт, банк, БИК, ИНН, КПП, ОКТМО) идентичны — это единый казначейский счёт для СОЮ/мировых судей г. Москвы, различается только КБК и назначение платежа. **Разные КБК для разных оснований платежа — не признак конфликта источников (§5.3)**: это две легитимные разные категории на одной странице, не расхождение.

Страница прямо указывает дату обновления («Последнее обновление выполнено 02.09.2026 15:33:36») — брать её как `page_updated_at`, не текущую дату сессии.

Вывод для протокола: **на одной странице реквизитов может быть несколько блоков** (по разным основаниям платежа/этапам дела) — извлекать нужный по совпадению с `payment_purpose`/категорией из state duty calculator, не первый попавшийся.

### 5.4. Verification URL — обязательное поле (ТЗ §78)

Финальный ответ юристу всегда содержит:

```
Официальный источник реквизитов: [ссылка]
```

Ссылка — по возможности прямо на страницу «Государственная пошлина» / «Реквизиты», не на главную страницу суда.

## 6. Cache (ТЗ §81-82)

| Данные | TTL | Комментарий |
|---|---|---|
| Перечень судов (`court_catalog`) | 7 дней | Ускоряет повторный поиск субъекта |
| Главная страница суда | 7 дней | — |
| Адрес суда | 7 дней | — |
| Территориальное сопоставление (адрес → суд) | 1 день | Меняется чаще (перекройка участков) |
| Реквизиты для оплаты | В рамках сессии | Не переносить между сессиями без повторной проверки |
| Ставки госпошлины | Versioned (см. `tools/court_jurisdiction/rules/`) | — |

**Критическое правило**: даже данные из действующего по TTL cache требуют online-подтверждения критических полей (территория, адрес, реквизиты) **перед** выдачей статуса `CONFIRMED` — cache сокращает число повторных запросов, но не заменяет последнюю проверку.

## 7. Offline Mode (ТЗ §83)

Если инструменты веб-поиска недоступны в среде выполнения (`[ИНСТРУМЕНТ НЕДОСТУПЕН]`, `references/web-research-tools.md`):

```
Юридически определён вероятный компетентный суд.
Территориальная принадлежность / адрес / реквизиты не перепроверены online.
Статус: LEGAL_CONFIRMED_OPERATIONAL_UNVERIFIED.
```

Запрещено выдавать старые/закэшированные банковские реквизиты как актуальные в этом режиме — реквизиты в ответе не приводятся вовсе, только ссылка на официальную страницу, где юрист должен свериться сам.

## 8. Известные пробелы (обновлено после live-recon 2026-09-16)

**Проверено для Москвы:** `mos-gorsud.ru/territorial` и `mos-sud.ru/territorial` пройдены `agent-browser`-recon на реальном адресе — рабочие протоколы §3.2, §3.3, реальные реквизиты §5.3а.

**Осталось открытым:**
- **`sudrf.ru` территориальный резолвер (районные и мировые вне Москвы) — инструмент найден, но сам сайт сообщает о недоступности** («проводится актуализация») на дату проверки 16.09.2026. Это не пробел агента, а состояние стороннего сервиса — перепроверить при следующем использовании (могло восстановиться); протокол fallback — §3.2a.
- **`arbitr.ru` — общий перечень судов субъектов не вытянут напрямую** (flyout-меню без прямых href в разметке); подтверждён только паттерн отдельных сайтов (`<код-региона>.arbitr.ru`) на одном примере (novosib.arbitr.ru). Раздел «Государственная пошлина»/«Реквизиты» на арбитражных сайтах **не проверялся** — структура может отличаться от СОЮ-порталов (`mos-gorsud.ru`), это отдельная задача при первом реальном арбитражном деле.
- **Военные суды и сеть гарнизонных судов** не имеют единого адресного сервиса в этом резолвере — точечный поиск (карточка `military`).
- **СИП и окружные арбитражные суды как первая инстанция** — официальный сайт известен (`ipc.arbitr.ru` для СИП, по данным общего перечня `arbitr.ru`), но отдельный протокол territorial-verification для этих судов не написан (обычно не требуется — подсудность не зависит от адреса сторон, а определяется категорией дела). Не проверялось live.
- **`msudrf.ru` за пределами Москвы** — подтверждена структура (`<участок>.<регион>.msudrf.ru`), но конкретный протокол «адрес → номер участка» вне Москвы упирается в тот же недоступный `sudrf.ru` (см. выше) либо в региональные Tier-2 системы, которые не инвентаризированы.
