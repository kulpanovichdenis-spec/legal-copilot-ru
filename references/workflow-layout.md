# Структура папки дела

В обычной папке дела `workflow/<дело>/` храните входные материалы и результаты для человека. Все служебные файлы нового дела сохраняйте в `workflow/<дело>/_llm/`.

| Путь внутри `_llm/` | Содержимое |
|---|---|
| `case-context.md`, `deadlines.yaml`, `matter-*.yaml` | Контекст, сроки и модель дела |
| `case-audit.jsonl`, `_audit/versions/` | Журнал и снимки версий |
| `_knowledge/`, `_analysis/` | Карточки, индекс и структурированный анализ |
| `sources/` | Извлечённый текст и метаданные вне карточек |
| `runs/<run-id>/{scripts,ops,qa,logs}/` | Разовые скрипты, задания и манифесты, рендер и логи |

Для инструментов с `--case` передавайте корень дела. Для инструментов с `--file`, `--output-dir` и аналогичными аргументами определите нужный путь перед вызовом:

```text
python -m tools.workflow_layout --case "workflow/<дело>" case-context.md
python -m tools.workflow_layout --case "workflow/<дело>" _knowledge
```

Существующий служебный файл в корне дела остаётся на своём месте до переноса. Для `_knowledge/`, `_analysis/` и `_audit/` путь выбирается для каталога целиком. При наличии обеих версий пути остановитесь и сообщите о конфликте. Примеры в skills показывают новый путь. К нему нельзя переключать запись, пока старый файл или каталог ещё используется.

При сборке DOCX задавайте каталог рендера явно: `_llm/runs/<run-id>/qa/<версия>`. Для редлайна можно указать `-LogPath` в `_llm/runs/<run-id>/logs/`; без этого аргумента внутри обычного дела инструмент сам выберет отдельный каталог запуска. Разовые скрипты должны получать путь к делу отдельно от папки скрипта. Перед завершением работы проверьте, что в корне не появились служебные файлы.

Правило касается обычных дел. Для `workflow/_anonymizer/` действуют отдельные ограничения проекта. Общие очереди и реестры, например `workflow/_claims/` и `workflow/_contracts/`, сохраняют свои контракты путей.

Перед переносом существующего дела составьте перечень исходных и целевых путей, проверьте хеши, коллизии и внутренние ссылки. Дождитесь подтверждения переноса. Не исполняйте разовые скрипты из старого дела для проверки переноса. Не редактируйте строки журнала аудита: журнал связан цепочкой хешей, а проверка версий поддерживает перемещение прежнего `_audit/` в `_llm/`. После переноса проверьте ссылки контекста и индекса, поиск документов и целостность журнала.
