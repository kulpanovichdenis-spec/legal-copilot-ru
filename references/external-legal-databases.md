# Внешние правовые базы через Legal Overlay

Проверено 14 сентября 2026 года по локальным материалам мейнтейнера и публичным
страницам провайдеров. Архивные skills использованы как исходный материал для правил,
но не установлены и не исполнялись.

## Архитектурное правило

Codex и Claude Desktop подключаются только к локальному `legal-overlay`.
Внешние базы регистрируются в
`profile/settings/connections.yaml`, а не отдельными MCP в каждом harness.
Секреты хранятся только в игнорируемом
`profile/settings/secrets.env`; в Git находятся лишь имена переменных.

На новой машине все семь учётных providers находятся в состоянии
`disabled_no_network`. `python -m tools.legal_overlay.connection_setup status`
показывает безопасный статус без значений секретов. Provider включается только
после того, как пользователь подтвердил наличие доступа и credential сохранён
локально; одного наличия записи в каталоге недостаточно.

Удалённые описания tools считаются недоверенными. Overlay принимает только
точно разрешённые endpoints, публикует только разрешённые read-only имена tools
и заменяет внешние описания нейтральным локальным текстом. Массовый экспорт
Casus заблокирован.

## Какая база для чего

| Connection ID | Для чего использовать | Не использовать как |
|---|---|---|
| `glossa` | Доктринальное толкование гражданского права, аргументы за и против тезиса, поиск связанных доктринальных положений и релевантной практики | НПА, официальный текст нормы или самостоятельный обязательный авторитет |
| `casuslegal-unified` | Единый доступ к оплаченным корпусам `main` / `sip` / `kas` / `kud`; предпочтительный Casus-маршрут | Corpus, не включённый в локальный `allowed_corpora` после живого content-smoke |
| `casuslegal-high-courts` | Практика КС РФ, ВС РФ и сохранившие силу позиции ВАС РФ | Сплошная практика нижестоящих судов или официальный первоисточник без сверки |
| `casuslegal-sip` | Практика Суда по интеллектуальным правам | Общегражданские споры вне IP |
| `casuslegal-kas` | Административное судопроизводство и материалы соответствующей коллегии ВС РФ | Арбитражные экономические или уголовные дела |
| `casuslegal-kud` | Уголовное судопроизводство, соответствующая коллегия и президиум ВС РФ | Гражданские и административные дела |
| `pravotech-consultant` | Платная внешняя юридическая консультация и навигационные ссылки на практику | Raw-поиск по СПС, полный текст/редакцию нормы или `norm_verification` provider |
| `consultant-plus` | **Основной внешний provider для поиска НПА и судебной практики** через корпоративный read-only MCP; `consultant_search` → раскрытие текста/карточки | Поисковую карточку как проверку нормы; реквизиты опубликования и судебного акта без официальной сверки |
| `garant` | Отключён в текущей установке | Любые сетевые вызовы или fallback без нового решения юриста |

Эти источники дополняют локальные SQLite-корпуса. Поисковая карточка или snippet
любого provider не заменяют раскрытый документ. При этом подключённая
профессиональная система может быть самостоятельным маршрутом проверки нормы,
если `route_norm_verification(probe=true)` возвращает для неё `usable_now: true`:
профиль уже подтверждает полный текст, редакцию, статус, pinpoint и provenance.
Иначе используется официальный источник либо ставится явный маркер непроверенности.

## Авторизация и текущая готовность

| Provider | Механизм | Локальная переменная | Состояние |
|---|---|---|---|
| Glossa | Bearer access code | `GLOSSA_ACCESS_CODE` | Текущая установка: подключён; credential хранится только в локальном gitignored secrets-файле |
| Casus: единый | OAuth login | `CASUSLEGAL_UNIFIED_ACCESS_TOKEN` | Текущая установка: подключён; разрешён только прошедший content-smoke corpus `main` |
| Casus: высшие суды | OAuth login | `CASUSLEGAL_HIGH_COURTS_ACCESS_TOKEN` | Авторизован, но отключён как дублирующий рабочий `main` единого connector |
| Casus: СИП | OAuth login | `CASUSLEGAL_SIP_ACCESS_TOKEN` | Авторизован, но отключён: живой content-search воспроизводимо возвращает 0 (`degraded_content_search`) |
| Casus: КАС | OAuth login | `CASUSLEGAL_KAS_ACCESS_TOKEN` | Авторизован, но отключён: живой content-search воспроизводимо возвращает 0 (`degraded_content_search`) |
| Casus: КУД | OAuth login | `CASUSLEGAL_KUD_ACCESS_TOKEN` | Авторизован, но отключён: живой content-search воспроизводимо возвращает 0 (`degraded_content_search`) |
| ПравоТех | OAuth Authorization Code + PKCE | `PRAVOTECH_CONSULTANT_ACCESS_TOKEN` | Текущая установка: подключён; разрешены `consultation` с paid-confirmation и `document_limits` |
| КонсультантПлюс | Корпоративная сеть или VPN; пользовательские credentials не нужны | — | Текущая установка: **подключён через Overlay, основной внешний источник** |
| ГАРАНТ | Bearer API token от обслуживающей организации | `GARANT_API_TOKEN` | Текущая установка: **отключён**; сетевые вызовы запрещены |

OAuth metadata для Casus и ПравоТех обнаруживаются самим Overlay. Команда
`connection_setup oauth-login <provider> --confirm-write` открывает системный
браузер и выполняет Authorization Code + PKCE; пароль пользователя видит только
страница провайдера. Dynamic client record, access token и refresh token хранятся
в gitignored `profile/settings/oauth/<provider>.json`; access token обновляется
по refresh token без отдельной конфигурации Codex и Claude. В tracked-файлы
секреты не копируются.

КонсультантПлюс подключается напрямую к Overlay (`remote_legal_mcp`) через
MCP-шлюз установки: адрес задаётся в `CONSULTANT_PLUS_MCP_URL` или в
`profile/settings/connections.yaml`, без токена и пользовательских HTTP-заголовков.
Доступ к шлюзу (сеть, VPN, лицензия К+) обеспечивает организация пользователя. ГАРАНТ отключён;
историческая конфигурация не активируется и не использует токен. Для нового пользователя без токена provider остаётся
выключенным (`enabled: false`) и не делает сетевых вызовов.

## Правила Glossa

1. Сначала `glossa_stats`: не предполагать покрытие томов или дату отсечения практики.
2. Искать полный правовой тезис через `glossa_support`, обычно до 4–5 результатов. Составной тезис разделять по институтам.
3. Показывать материал, который тезис поддерживает, ограничивает и опровергает. Нельзя скрывать adverse material.
4. Для контекста положения использовать `glossa_get_point(question=...)`; для карты статьи — `glossa_get_article`; для межтомных связей — `glossa_find_similar(scope="cross_volume")`.
5. Различать `voice`: норму, позицию автора и процитированное им иное мнение. Слова третьего лица нельзя приписывать автору Glossa.
6. Цитату воспроизводить точно, с условиями и модальностью; авторскую цитату снабжать ссылкой/сноской.
7. Судебную практику искать языком судов через `glossa_practice_search`; найденный акт раскрывать через `glossa_practice_case` или `glossa_practice_term` до характеристики его вывода.
8. Более позднее руководящее разъяснение отдельно ограничивает доктрину; единичный коллегиальный акт — риск, а не автоматически общее правило.
9. Для разбора судебного акта применять право на дату акта; последующие позиции отделять как материал для обжалования.
10. Пустая выдача — допустимый результат. При ошибке provider нельзя дополнять ответ «по памяти».

## Правила Casus

1. Предпочтительный маршрут — единый `casuslegal-unified`: `casuslegal_search_practice(..., corpus="main|sip|kas|kud")`. Legacy endpoints (`sip_*`, `kas_*`, `kud_*`) использовать только как явно включённый fallback; одновременно дублировать единый connector ими нельзя.
2. До поиска проверить локальный `allowed_corpora`. Corpus добавляется туда только после непустого живого поиска и успешного `casuslegal_get_case_details(case_id, corpus=...)`; непройденный corpus заблокирован до сети.
3. Для тезиса выполнять минимум два независимых поиска: поддержку и контраргумент. Результат классифицировать относительно тезиса.
4. Поиск/snippet не достаточен для цитирования. Полный текст или нужный раздел открывать через `casuslegal_get_case_details` с тем же `corpus`; точную устойчивую формулировку искать через `casuslegal_find_term` с тем же `corpus`.
5. `casuslegal_browse_practice` использовать для систематического движения вокруг пункта обзора или разъяснения, а не вместо содержательного запроса.
6. Иерархия: КС РФ → Пленум ВС/ВАС → обзоры Президиума → определения коллегий. Отказное определение не считать substantive position.
7. ВАС требует проверки сохранения силы позиции. Похожесть по фактам, forum relevance и authority оценивать раздельно.
8. Факты дела брать только из материалов пользователя. Внешняя практика — правовой ориентир, не источник фактов текущего дела.
9. Реквизиты и цитату сверять с официальной публикацией до использования как доказательства.
10. Не выполнять массовое извлечение. `casuslegal_export_cases` скрыт Overlay в соответствии с ограничениями оферты и правами на базу.

Живой smoke текущей установки 15 сентября 2026 года: `main` вернул поиск и полный
текст; `sip`, `kas`, `kud` при активной подписке и ненулевой статистике вернули
пустую выдачу и поэтому исключены из `allowed_corpora`. Это состояние
`degraded_content_search`, а не отсутствие соответствующей практики в базе.

## Правила ПравоТех

Проверенный authenticated inventory содержит девять tools. Raw-поиска по базе,
раскрытия текста НПА, редакций и статуса документа среди них нет. При этом
ПравоКонсультант использует в готовых ответах и нормы, и судебную практику со
ссылками: это не «только судебная база», но и не отдельный raw-коннектор к СПС.
`consultation`, `conclusion` и `deep_research` создают внешний продуктовый диалог
и расходуют тарифный лимит запросов; `upload_document` / `delete_document`
изменяют внешнее состояние.

Overlay публикует только:

- `consultation` — не read-only, только по явному согласию пользователя на
  конкретный платный вызов и с `_confirm_paid_call=true`;
- `document_limits` — read-only проверка условий тарифа.

`conclusion`, `comparison`, `deep_research`, `upload_document`,
`document_status`, `list_documents` и `delete_document` заблокированы. Ответ
ПравоТех является вторичной консультацией: каждую используемую норму и реквизиты
практики нужно раскрыть и проверить через другой пригодный источник. На основании
текущего inventory ПравоТех не может быть повышен до `norm_verification`.

### Когда модель обращается к ПравоТех

ПравоТех не включается автоматически в обычный discovery и не расходуется на
простой поиск статьи или проверку реквизитов. Допустимы два триггера:

1. юрист прямо просит направить **конкретный вопрос** в ПравоТех — это считается
   подтверждением одного вызова по этому вопросу;
2. модель уже провела обычное исследование, но юрист не принимает предложенные
   варианты или просит независимое второе мнение — перед вызовом модель показывает
   подготовленный вопрос и получает подтверждение расхода ещё одного запроса.

Не обращаться в ПравоТех только потому, что локальная выдача пустая: сначала
зафиксировать coverage gap и использовать обычные primary/verification-маршруты.

### Как составлять вопрос

`consultation` получает не поисковые ключевые слова, а самодостаточную постановку:

- юрисдикция и дата, на которую нужен анализ;
- обезличенные юридически значимые факты и отсутствующие факты;
- один точный основной вопрос и при необходимости под-вопросы;
- уже найденные варианты/сомнения, чтобы получить альтернативный разбор, а не
  повтор общей справки;
- требуемый результат: применимые нормы, практика, adverse-позиция, риски,
  практический вывод;
- просьба указать точные реквизиты и прямые ссылки, а недоступность полного текста,
  редакции или ссылки отметить явно.

Не отправлять персональные данные, договоры и приложения через `consultation`;
в текущем allowlist вложения и библиотека документов не используются.

### Как обрабатывать ответ

1. Сохранить `answer`, `sources`, дату получения и usage без публикации ID диалога.
2. Разложить ответ на тезисы: правило → аргумент → контраргумент → вывод.
3. Сопоставить эту линию с собственным предварительным анализом и отметить, что
   действительно новое или противоречит ему.
4. Каждую используемую норму и судебный акт раскрыть через подходящий provider
   Overlay/официальный источник; проверить текст, редакцию, статус и реквизиты.
5. Развивать мысль можно только из проверенных источников. Если независимая
   проверка не состоялась, вывод ПравоТех маркируется как неподтверждённое второе
   мнение, а не как готовое основание.

Живой smoke 2026-09-16 показал JSON-wrapper с полями `answer`, `sources`,
`tokens_used`, `conversation_id`, `conversation_url`, `assistant_message_id`,
`mode`. Первый meta-запрос не дал источников, а юридический follow-up превысил
исходный timeout; безусловный retry запрещён, поскольку запрос мог быть принят и
списан из лимита. Для следующих подтверждённых вызовов установлен timeout 180
секунд.

Личный кабинет показал, что два первоначальных юридических вопроса дошли с
кириллицей, уже заменённой на `?`; порча возникла во временном PowerShell-канале
тестирования до входа в Overlay. После исправления отдельно подтверждённый smoke
прочитал полный вопрос напрямую из UTF-8-файла, проверил 1127 кириллических
символов и отправил явные UTF-8 bytes. Примерно через 65 секунд endpoint
`consultation` вернул HTTP 502. Личный кабинет позднее показал и корректный
вопрос, и развёрнутый ответ. Это подтверждает принятие запроса и сохранение
результата в продукте, но не доказывает штатную асинхронную модель MCP. Рабочая
гипотеза — разрыв синхронной доставки на upstream gateway timeout; публичной
документации ПравоТех, подтверждающей такой контракт, не найдено. Для такого 502 Overlay
возвращает `submitted_pending_account_check`; это не готовый ответ и не основание
для retry. Модель сообщает юристу, что нужно вручную открыть кабинет. Не повторять
платный запрос без отдельного подтверждения и проверки остатка месячного лимита.

Последующий отдельно разрешённый диагностический вызов с локальным timeout 300
секунд и тем же вопросом вернул готовый результат через MCP за 1,53 секунды.
До ответа поддержки статус подключения — `intermittent_result_delivery`:
end-to-end возврат подтверждён, но предыдущий 502 и безопасное восстановление
после него не объяснены.

Первый полный ответ подтвердил практическую роль provider: структура и кандидаты
полезны, но citation accuracy смешанная. Были обнаружены неверная привязка статьи
523 ГК РФ к `51-ФЗ`, неправильная дата ПП ВС РФ № 54, пропуск ограничения
пункта 5 статьи 450.1 ГК РФ и неподтверждённые реквизиты кассации по одному делу.
Все пять номеров дел оказались реальными и тематически релевантными либо
смежными; первоначальная локальная пометка дела № А55-750/2024 как
нерелевантного была ошибочной и исправлена после раскрытия полного текста.
Поэтому каждый реквизит раскрывается и проверяется независимо; внутренние ссылки
`consultant.pravo.tech` не заменяют официальный текст или карточку дела.

## Правила КонсультантПлюс

**Статус: подключён через Legal Overlay и является основным внешним источником
для поиска НПА и судебной практики.** Порядок обращения: локальный discovery →
КонсультантПлюс → Casus / ПравоТех (по их правилам) → веб. Использовать только
`consultant_search`, затем по необходимости `consultant_get_text` и
`consultant_get_document`; `consultant_status` — для проверки доступности.
Поисковая карточка остаётся навигацией. После live-smoke 2026-10-09 раскрытый
текст К+ является маршрутом `live_professional` в пределах профиля. Дата
редакции производна из заголовка; точный статус, историческая редакция,
опубликование и реквизиты судебного акта проверяются по официальному источнику.
Подробный профиль — `references/source-profiles/consultant-plus.md`.

## Историческая справка: ГАРАНТ (отключён)

**Статус: отключён.** Не использовать `garant_*`, не включать его в fallback и
не считать результаты прежнего smoke подтверждением текущей доступности. Ниже
сохранена только справка о прежнем подключении для возможного повторного
включения по новому решению юриста.

Инструменты (18, совпадают с серверным `tools/list`): `garant_search`,
`garant_snippets`, `garant_find_hyperlinks`, `garant_document_info`,
`garant_document_redactions`, `garant_find_modified`, `garant_block_changed`,
`garant_prime_categories`, `garant_prime_news`, `garant_sutyazhnik`,
`garant_limits`; экспорт — `garant_export_rtf`, `garant_export_html`,
`garant_export_block_html`, `garant_export_image`, `garant_export_formula`,
`garant_export_odt`, `garant_export_pdf`.

- `env="internet"` — общий правовой поиск; `env="arbitr"` — судебная практика (`sort=1` — по дате).
- Проверка нормы: `garant_search` → `garant_document_info` (статус) → `garant_document_redactions` (редакция на дату) → `garant_snippets` (номер блока) → `garant_export_block_html` (текст). Блок старой редакции открывается по `topic` этой редакции.
- Практика по норме: `garant_sutyazhnik(text, kind=["301"|"302"|"303"], count)`. Реквизиты акта — после раскрытия карточки, не из строки поиска.
- Квоты по факту `garant_limits`: экспорт 30/мес. (расходуется и блочным экспортом), карточка документа 300/мес., поиск ссылок 1000, контроль изменений 1000 и блоков на контроле 1000 (счётчики выводятся отдельно, хотя описание инструмента называет их совокупными); поиск, snippets, редакции и практика счётчиком не показаны. Не открывать полные документы и не выгружать PDF/ODT/RTF без прямой просьбы юриста; перед серией вызвать `garant_limits`.
- ГАРАНТ не возвращает реквизиты опубликования акта: для них и как усиленный маршрут — pravo.gov.ru.
- Кириллицу передавать через MCP-клиент; аргументы Git Bash искажают запрос и дают 0 результатов.
- Поисковая карточка остаётся навигацией; правовой вывод опирается на раскрытый блок на нужной редакции.

## Общие правила результата

- В отчёте указывать provider, дату retrieval, тип источника и статус сверки.
- Не смешивать юрисдикции и специализированные корпуса.
- Не передавать персональные или конфиденциальные факты: запрос сначала абстрагировать.
- Не найдено — формулировать «в пределах проведённого поиска не обнаружено» и перечислять проверенные базы/формулировки.
- Доктрина и поисковые карточки помогают найти основание, но ratio юридического вывода строится на раскрытом проверенном тексте нормы и судебного акта. Для нормы использовать только source profile с `norm_verification.eligible: true` и текущим `usable_now: true`.
