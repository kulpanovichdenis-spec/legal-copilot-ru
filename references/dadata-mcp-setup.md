# DaData — проверка контрагента

**Основной путь — через локальный Legal Overlay.** Инструмент `mcp__legal-overlay__dadata_party(query=<ИНН/ОГРН/ОГРНИП>, count=1)` вызывает официальный DaData `findById/party` API напрямую. Namespace `legal-overlay` обозначает общий gateway, а не VPS. `DADATA_API_KEY`/`DADATA_SECRET_KEY` читаются общим config loader из локального secret store и не дублируются в настройках Codex/Claude. Используется skill-ом [`counterparty-check`](../skills/counterparty-check/SKILL.md).

Проверено вручную 2026-07-29 реальным запросом по ИНН 7707083893 (Сбербанк) — вернул полную карточку.

---

## Что отдаёт DaData

По одному идентификатору (ИНН / ОГРН / ОГРНИП) возвращается карточка юрлица или ИП из ЕГРЮЛ/ЕГРИП:

- полное и краткое наименование, ОПФ;
- статус (`ACTIVE` / `LIQUIDATING` / `LIQUIDATED` / `BANKRUPT` / `REORGANIZING`);
- адрес и признак недостоверности адреса по ФНС;
- руководитель, должность, ИНН/КПП/ОГРН, дата регистрации, ОКВЭД, ОКПО;
- учредители с долями и пометками о недостоверности сведений;
- уставный капитал;
- сведения о ФНС/ПФР/ФСС;
- лицензии;
- финансовая отчётность (выручка, доходы, расходы, недоимки);
- категория МСП.

Точные пути полей в ответе сервера (`suggestions[0].data.*`) — см. `skills/counterparty-check/SKILL.md`.

Этого достаточно для:
- подстановки реквизитов в шапку договора / письма / претензии (`[ПРОВЕРИТЬ РЕКВИЗИТЫ]` снимается, если данные подтверждены DaData);
- быстрой оценки статуса контрагента до подписания;
- сверки реквизитов из присланного контрагентом договора с реестром.

DaData **не** заменяет проверку по специализированным реестрам — банкротство в [bankrot.fedresurs.ru](https://bankrot.fedresurs.ru/), РНП, ФССП, kad.arbitr.ru. Для глубокой проверки см. `references/web-research-tools.md` раздел 3.3.

## Что отправляется в DaData (и что нет)

**Отправляется:** только идентификатор (ИНН / ОГРН / ОГРНИП) — публичные данные.

**НЕ отправляется:**
- текст договора / претензии / письма;
- суммы, особые условия, контактные лица;
- персональные данные сотрудников;
- коммерческая тайна.

Это правило закреплено в `references/confidentiality-rules.md`. Если Claude в ходе работы захочет передать в DaData что-то кроме идентификатора — это ошибка, остановить.

## Когда DaData использовать обязательно

- Подготовка договора, ДС, протокола разногласий — для подстановки/сверки реквизитов сторон.
- Подготовка претензии / иска / отзыва — для подтверждения текущего статуса контрагента и адреса для направления.
- Подготовка письма контрагенту — для актуальных реквизитов и проверки, не ликвидирован ли адресат.
- Запрос госоргана с упоминанием третьего лица — для сверки наименования и адреса этого лица.
- Любая работа, где в результате должен оказаться ИНН / ОГРН / наименование / адрес юрлица или ИП.

## Когда DaData не нужна

- Контрагент — физическое лицо без статуса ИП.
- Работа полностью внутри собственной компании юриста (внутренние регламенты, политики).
- Анализ нормы / судебной практики без привязки к конкретному юрлицу.

## Маркеры

Общий реестр маркеров — `references/citation-rules.md`, «Реестр маркеров неполноты». Ниже — служебные маркеры слоя DaData:

Если DaData недоступна или вернула ошибку:
- `[DADATA НЕДОСТУПНА]` — инструмент не отвечает (сервер недоступен, туннель не поднят);
- `[DADATA НЕ НАЙДЕНО]` — пустой `suggestions[]` — по идентификатору не найдено юрлицо/ИП;
- `[ПРОВЕРИТЬ РЕКВИЗИТЫ]` — данные должны быть подтверждены вручную (через [egrul.nalog.ru](https://egrul.nalog.ru/)).

Не подставлять реквизиты «по памяти» и не выдумывать. Лучше маркер, чем угаданное значение.

## Подключение через единый локальный Overlay

DaData настраивается только как provider общего Overlay; отдельную MCP-запись в Codex
или Claude создавать нельзя. Машинные секреты остаются локальными и не попадают в
репозиторий, source profile или диагностический вывод.

```
Provider ID:    dadata
Adapter:        dadata_party
Endpoint:       https://suggestions.dadata.ru/suggestions/api/4_1/rs/findById/party
Secrets:        DADATA_API_KEY, DADATA_SECRET_KEY
```

Ключи — личный кабинет DaData → [dadata.ru/profile/#info](https://dadata.ru/profile/#info) (API-ключ, Секретный ключ). Free-тариф — 10 000 запросов/сутки.

Ключи находятся в локальном secret store (`profile/settings/secrets.env` либо
legacy `.env` на время миграции). `profile/settings/connections.yaml` содержит
только имена переменных. Оба harness запускают один gateway, поэтому отдельная
загрузка переменных и отдельный lifecycle DaData им не нужны.
