# Структурный разбор судебного акта (карточка решения)

**Это метод, а не skill и не субагент.** Отдельной сущности `court-decision-analyzer` намеренно **не заводится** — разбор выполняет тот, кто и так работает с актом: основной skill (`procedural-document-drafter`, `position-critic`, `gov-response`, `legal-opinion`) или уже существующий субагент `adversarial-researcher` на этапе Adverse Case Search. Файл — единый источник структуры разбора, чтобы формат не расходился между skills.

**Разбор акта vs управление поиском.** Эта карта — про **один акт**. Как вести сам поиск практики, оценивать authority/статус практики и решать, когда остановиться — `references/case-law-search.md` (+ карты `references/case-law-cards/`); оценочные измерения найденного акта (аналогия, характер, argumentative value) — раздел J ниже, содержательно они в карте CL-6.

## Когда применять

Всегда, когда судебный акт становится **существенным источником** вывода: подбор практики под позицию, поиск практики против позиции (Adverse Case Search), оценка перспектив спора, обоснование в иске/отзыве/жалобе/объяснении.

Не применять к актам, которые упомянуты вскользь и ни на что не влияют — карточка нужна там, где на решение опирается тезис.

## Базовый принцип

**Вывод по судебному акту не делается на основании summary, если доступен сам акт.** Каждый существенный вывод должен быть связан с конкретным местом первоисточника:

```
вывод → фрагмент акта → страница/абзац/раздел → возможность открыть исходный документ
```

Нет доступа к тексту акта (только карточка из базы, аннотация, пересказ из вторичного источника) — вывод формулируется калиброванно и помечается `[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]`; реквизиты дела в документ юриста не выносятся, пока первоисточник не открыт (`references/source-hierarchy.md`, «Рабочий цикл», шаг 5).

## Структура карточки

### A. Идентификация
Суд, дата, номер дела, инстанция, стороны (роли, не только наименования), категория спора, ссылка на источник (URL/`case_number` в `legal-kb`), путь к локальному файлу, если акт есть в материалах дела.

Для акта, на котором держится тезис, дополнительно зафиксировать `dispute_id`, место в цепочке инстанций и последующую историю именно несущего тезиса: `CURRENT | PARTIALLY_REVERSED | REVERSED | UNKNOWN`, источник проверки и дату. При `PARTIALLY_REVERSED` указать подтверждённый сохранившийся scope; неизвестный scope не считать текущей позицией.

### B. Фактические обстоятельства
Только те факты, которые **были существенны для решения**. Отдельным подпунктом — **чем факты отличаются от нашего дела** (основа для будущего distinguishing).

### C. Требования и позиции сторон
Что требовал истец/заявитель; основные доводы; основные возражения другой стороны.

### D. Применённые нормы
Только нормы, на которых суд **фактически основал** вывод. Норма, упомянутая в тексте мимоходом (в пересказе доводов, в перечне), в этот раздел не попадает.

### E. Мотивировочная часть
Разложить, не пересказывать:
1. какие юридически значимые обстоятельства установил суд;
2. какую правовую квалификацию им дал;
3. какие доводы принял;
4. какие доводы отклонил и **почему**;
5. какие доказательства признал существенными;
6. какие логические переходы непосредственно привели к результату.

Отдельно выделить **основной мотив (ratio)** — насколько эта конструкция применима к конкретному российскому акту.

**Сила связи «факт → вывод суда».** Наличие факта в описательной части не доказывает, что суд на него опирался. Для каждого факта, на котором строится аналогия или distinguishing, указать: `explicit` (суд прямо назвал факт основанием вывода) / `strong_implicit` (факт непосредственно используется в мотивировке, но без прямой формулы) / `weak_inference` (наш вывод о значении факта) / `background` (только в описании обстоятельств). `weak_inference` и `background` не подаются как мотив суда; аналогия на них — с маркером аналогии и оговоркой.

### F. Резолютивная часть
Фактический результат рассмотрения. **Не смешивать с мотивировкой** — это разные разделы карточки.

### G. Извлекаемый правовой тезис
Формулировать **максимально узко**:

> При обстоятельствах X суд применил правило Y и пришёл к выводу Z.

**Запрещено формулировать тезис шире, чем позволяет конкретное решение** — это прямой источник ошибки «одно дело → универсальное правило». Расширение до общего правила возможно только при наличии линии практики (несколько актов, разъяснение высшего суда), и тогда обосновывается отдельно.

Для каждого несущего фрагмента назвать атрибуцию: `HOLDING` / `REASONING` / `PARTY_POSITION` / `SYNTHESIS` / `COMMENTARY`. `PARTY_POSITION` — довод стороны, даже если суд его пересказал. `SYNTHESIS` и `COMMENTARY` — наши выводы; их не приписывать суду. Один исход без мотивировки не даёт правового тезиса.

### H. Значение для нашей позиции
Одно из: поддерживает / противоречит / частично противоречит / нейтрально / отличается по фактам / отличается по применимому праву / не позволяет сделать надёжный вывод.

### I. Проверяемые ссылки
На каждый ключевой вывод — locator: `источник → страница/абзац → релевантный фрагмент → вывод`.

### J. Оценочные измерения (для case-law-search)
Заполнять, когда акт оценивается в подборе практики (содержательно — `references/case-law-cards/CL-6-analogy-and-character.md`, CL-2, CL-5):
- `authority_level` — A1 / A2 / A3 / A4 / B1 / B2 / B3 / X-отказное (лестница CL-2); для ВАС — статус по CL-3;
- `analogy_mode` — `DIRECT_LEGAL` (совпали факты + квалификация + issue + норма + claim/remedy) или `FACTUAL_ARGUMENTATIVE` (сходны факты, квалификация иная — тогда «что сказал суд» и «наш аргумент» разделять явно);
- `rule_character` — `GENERAL_RULE | EXCEPTION | UNCLEAR` (не выдавать исключение за обычный аналог);
- `forum_relevance` — повышено, если акт из вертикали нашего дела (CL-5); **отдельно** от authority;
- `argumentative_value` — сила мотивировки для нашей аргументации; **на authority не влияет** (CL-6).

Если акт входит в линию, добавить `citation_lineage`: корневой источник, `ORIGINAL | INDEPENDENT_APPLICATION | COPY` и объяснение. Общая ссылка на Пленум не уничтожает самостоятельность реального применения в разных спорах, но копирующий пересказ не становится новым authority. Для расхождений добавить `FACTUAL | LEGAL | MIXED | TEMPORAL | UNEXPLAINED` и обоснование по CL-7; не придумывать отличающий факт.

## Статусы проверки (для пула практики)

Когда карточки собираются в пул (например, Adverse Case Pool в `procedural-document-drafter`), каждая получает статус — **проставляет юрист, не агент**:

| Статус | Значение |
|---|---|
| `UNVERIFIED` | найдено агентом, юрист ещё не смотрел |
| `VERIFIED_RELEVANT` | юрист подтвердил релевантность |
| `VERIFIED_NOT_RELEVANT` | юрист отклонил |
| `VERIFIED_DISTINGUISHABLE` | релевантно, но отличается по фактам — есть основания для distinguishing |
| `REJECTED_SOURCE` | источник негоден (не тот акт, недостоверные реквизиты, недоступен текст) |

Агент не вправе самостоятельно переводить карточку из `UNVERIFIED` в любой `VERIFIED_*`. LLM не считает найденную практику окончательно подтверждённой — это решение юриста.

## Границы

- Карточка — **рабочий материал**, не документ для суда и не правовое основание сама по себе; в процессуальный документ идёт проверенная ссылка на акт по `references/citation-rules.md`, а не карточка.
- Никаких выдуманных реквизитов, номеров дел, цитат: не нашлось — так и писать (`references/source-hierarchy.md`).
- Практика регионального суда не обязательна для другого региона; акт старше 2 лет по быстро меняющейся теме — `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ ПРАКТИКИ]`.
