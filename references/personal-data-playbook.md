# Плейбук по персональным данным — индекс сценариев обработки ПДн

Сценарный плейбук проекта для квалификации обработки персональных данных коммерческой компанией (152-ФЗ, юрисдикция РФ). Это **индекс-роутер**: краткие маршруты и ссылки на карточки. Содержательный материал — в `references/pd-playbook-cards/` (общий слой G01–G15, реестр норм, 29 сценарных карточек S01–S29, политика источников, pharma-карта, watchlist).

**Единица анализа — не статья закона, а конкретная processing activity:** зачем компания обрабатывает данные, чьи именно данные, какие операции делает, на каком основании, кому передаёт, где хранит и когда уничтожает. Плейбук не пересказывает 152-ФЗ постатейно.

**Главный принцип: согласие — не универсальное основание.** Сначала определяется цель и применимое основание по закону (ст. 6, спец. режимы ст. 10/11/15/16), и только затем решается вопрос о необходимости согласия.

**Правило подгрузки: не читать все карточки.** Классифицировать бизнес-сценарий по таблице ниже и открыть только сработавшие карточки (обычно 2–5) плюс общий слой `_general-layer.md`. Cross-links внутри карточки указывают, какие смежные сценарии подключить.

**Статус.** Методологическая база проекта, срез права пакета — **12.09.2026**, версия 0.1. Результат работы — всегда черновик для юриста (human review), сохранять в `workflow/`. Плейбук не заменяет проверку действующей редакции НПА и фактов конкретного кейса.

**Происхождение и права.** Структура следует режиму 152-ФЗ и подзаконных актов; тексты норм — официальные документы. Экспертные материалы (`EXP-*`) использованы как источник идей и указателей на первоисточник, их текст не воспроизводится (`references/pd-playbook-cards/_source-policy.md`).

## Алгоритм работы агента

1. **Вход**: бизнес-описание процесса (зачем, чьи данные, какие операции, кому передаётся, где хранится).
2. **Маршрутизация юрисдикции**: плейбук — про РФ. Вопрос про Узбекистан/иную юрисдикцию — не смешивать (CLAUDE.md, «Где искать НПА»).
3. **Разбить сценарий на отдельные цели/processing activities** (одна система может нести несколько самостоятельных целей; каждая получает своё `legal basis / dataset / recipients / retention`).
4. **Классификация**: пройти таблицу триггеров ниже, зафиксировать сработавшие сценарии S01–S29.
5. **Подгрузка**: открыть карточки сработавших сценариев + общий слой `_general-layer.md` (G01–G15 применяется всегда).
6. **Decision tree**: выполнить дерево решений каждой карточки; подключить cross-links (SaaS, локализация, трансграница, special categories, маркетинг и т. д.).
7. **Сверка источников (обязательный шаг перед выводом)**: реестр и карточки дают discovery; для каждой нормы вызвать `route_norm_verification(jurisdiction="RU", probe=true)`, открыть полный текст только через provider с `usable_now: true` и проверить редакцию, статус, pinpoint и provenance. Подзаконку и практику раскрывать в соответствующем первоисточнике. Нет пригодного маршрута — `[ПРОВЕРИТЬ НОРМУ]`. Детали — `references/source-hierarchy.md`; реестр — `references/pd-playbook-cards/_source-registry.md`.
8. **Вывод**: риск сценария → находки → риск каждой находки по `references/risk-scale.md`; при неполноте данных — маркеры (`references/citation-rules.md`); результат — в `workflow/`.

## Важные оговорки (учитывать в каждом выводе)

- **Доступность определяется в текущей сессии**, а не датой сборки пакета: неподключённый provider не вызывать; использовать только `usable_now: true`. При отсутствии такого маршрута не подменять проверку памятью модели и ставить `[ПРОВЕРИТЬ НОРМУ]`.
- **Риск в карточке — это риск сценария (зоны обработки), а не риск конкретного пункта договора/находки.** В итоговом memo риск каждой находки выставляется по `references/risk-scale.md` (Блокирующий / Высокий / Средний / Низкий / Вопрос бизнесу). «Высокий · критическая зона» в каталоге = исходный `CRITICAL` пакета (зона максимального риска), а не автоматический «Блокирующий».
- **Зоны быстрого изменения права** (трансграница, AI/243-ФЗ, биометрия, КоАП 13.11, формы РКН) — `references/pd-playbook-cards/_update-watchlist.md`; по ним сверка редакции обязательна.
