# Локальный OCR для приёма документов (Tesseract, офлайн)

Верх воронки (`case-intake`) распознаёт сканы/фото/PDF-без-текста **локально**,
скриптом, без облака. Модель видит только извлечённый текст. Облачный LLM-OCR
(`markitdown-ocr`, заливка картинок в модель) **запрещён** — конфиденциальность.

**Исключение — дочитывание того, что не смог OCR (решение юриста 2026-10-08).**
Если watcher пометил карточку `needs_vision_read: true` (Tesseract выдал мусор:
рукопись, плохой скан), агент в сессии читает изображения страниц **моделью
своей рабочей сессии** — `tools/case_intake/vision_read.py`, порядок в
`skills/case-intake/SKILL.md`, шаг 1а. Границы:
- только модель рабочей сессии, куда текст документа уходит и так; сторонние
  облачные OCR (`markitdown-ocr`, Yandex Vision, Google и т. п.) по-прежнему
  запрещены без отдельного решения юриста;
- только страницы документов с флагом, не «для надёжности» на каждом скане;
- **никогда** для материалов конвейера pre-LLM анонимизации (`workflow/_anonymizer/`,
  любые подпапки): изображение обходит маскирование. Запрет безусловный (решение
  юриста 2026-10-08), `vision_read.py` отказывает по пути;
- временные PNG — вне `workflow/`, удаляются после записи расшифровки;
- расшифровка недословная, как и OCR: реквизиты и цитаты сверять со сканом.

## Установка (Windows)

Tesseract с языками `rus` и `eng` входит в стандартное развёртывание проекта на Windows. Skill `setup` сначала ищет существующую установку и не переустанавливает её без необходимости. Если Tesseract отсутствует, после подтверждения пользователя используется:

```powershell
winget install UB-Mannheim.TesseractOCR --source winget
```

Сборка UB Mannheim: https://github.com/UB-Mannheim/tesseract/wiki. При ручной установке отметить языковой пакет **Russian** (`rus`); `eng` также обязателен. Типовые пути — `C:\Program Files\Tesseract-OCR` и `%LOCALAPPDATA%\Programs\Tesseract-OCR`.

1. Проверить версию и языки:
   ```powershell
   & "C:\Program Files\Tesseract-OCR\tesseract.exe" --version
   & "C:\Program Files\Tesseract-OCR\tesseract.exe" --list-langs
   ```
   Если путь другой, использовать фактический путь к `tesseract.exe`. В списке должны присутствовать `rus` и `eng`.
2. **PATH не обязателен** для стандартных мест установки: `ocr_runner` сам находит
   бинарь по известным путям (`_TESSERACT_CANDIDATES`) и указывает его pytesseract.
   При нестандартном пути добавить каталог установки в локальный `PATH`; публичный
   код проекта под конкретную машину не изменять.
3. Python-зависимости:
   ```powershell
   python -m pip install -r requirements.txt
   ```
4. Проверка:
   ```powershell
   python -c "from tools.doc_ingest import ocr_runner; print(ocr_runner.tesseract_available())"
   python tools\doc_ingest\test_ocr.py
   ```
   Первая команда должна вывести `True`, smoke-тест — завершиться без ошибок.

## Как это работает

- `tools/doc_ingest/router.py` направляет изображения и PDF без текстового слоя в
  `ocr_runner.ocr_extract` (Tesseract, `lang=rus+eng`, PDF → 300 dpi постранично).
- OCR-текст **недословный**: пригоден для классификации/маршрутизации и нечёткого
  поиска, но не для дословного цитирования нормы/реквизита — дословный текст берётся
  из первоисточника (память: tesseract-local-not-in-path).
- Низкое среднее доверие (`< 0.70`, `ocr_runner.LOW_CONFIDENCE`) помечается
  `[ОЦР НЕ УВЕРЕН]`; в канале `_claims` watcher ставит `needs_vision_read`, и агент
  дочитывает страницы по изображению (исключение выше), а не отдаёт мусор классификатору.
- Нет Tesseract → backend возвращает stub `[OCR НЕДОСТУПЕН]`, конвейер не падает,
  файл помечается для юриста.
