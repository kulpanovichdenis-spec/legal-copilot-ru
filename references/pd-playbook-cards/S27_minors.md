**Риск сценария**: Высокий · критическая зона · **Cross-links**: S11, S13, S21, S29

**Назначение:** применить повышенную осторожность без механического импорта зарубежных возрастных порогов согласия.

## 1. Business triggers

- детское приложение/сайт
- семейная программа лояльности
- мероприятия для детей
- фото детей
- медицинские/фармацевтические программы
- реклама

## 2. Processing activities

- регистрация
- получение согласия/представительства
- контент/коммуникация
- фото/видео
- аналитика/профилирование
- маркетинг

## 3. Subjects / data

**Субъекты**
- несовершеннолетний
- родитель/иной законный представитель

**Типичные данные**
- идентификационные/контактные
- возраст
- данные представителя
- изображение
- поведение
- health data — при специальных программах

## 4. Purpose model

- оказание услуги/участие
- безопасность
- коммуникация с представителем
- маркетинг — особо осторожно

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 5. Нормативная карта

| Source ID | Роль | Что проверять |
|---|---|---|
| `NORM-003` | core | основание и дееспособность/представительство оцениваются с гражданским законодательством |
| `NORM-004` | conditional | согласие |
| `NORM-006` | conditional | распространение фото/данных |
| `NORM-030` | conditional | изображение |
| `NORM-028` | conditional | реклама лекарств и ограничения |

Общий слой G01–G15 из `_general-layer.md` применяется всегда, если карточка прямо не устанавливает более специальное правило.

## 6. Decision tree

1. Определить возраст и правовую способность субъекта совершить соответствующее действие; при необходимости идентифицировать законного представителя.
2. Минимизировать данные ребенка и исключить необязательные профили.
3. Для фото/публикации вызвать S13.
4. Для health data вызвать S21.
5. Для маркетинга применить S11 и специальные рекламные ограничения.
6. Не использовать иностранный GDPR-like age threshold как российскую норму без прямого основания.

## 7. MUST controls

- documented representation/consent mechanism where required
- минимизация
- раздельный учет данных ребенка и представителя
- строгая проверка контента/маркетинга

## 8. Recommended controls

- privacy-by-default без behavioral advertising детям
- повышенный human review любых AI decisions

## 9. Evidence / документы

- age/representative flow
- consent record
- content/marketing review
- photo release where applicable

## 10. Red flags

- самостоятельная регистрация маленького ребенка с широким consent
- таргетинг по чувствительным признакам
- публикация фото без S13
- реклама рецептурных/иных ограниченных препаратов детям

## 11. Regulator / expert layer

- Специальная экспертная позиция для этой карточки не требуется; приоритет первичным источникам.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- 152-ФЗ не следует упрощать до одного универсального возрастного порога; способность дать конкретное согласие/заключить сделку оценивается вместе с гражданским и специальным законодательством.
