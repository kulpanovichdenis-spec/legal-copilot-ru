**Риск сценария**: Высокий · **Cross-links**: S01, S19, S21, S29

**Назначение:** ограничить проверку конкретной законной целью, допустимыми источниками и релевантными данными.

## 1. Business triggers

- проверка кандидата
- конфликт интересов
- проверка директора/бенефициара
- sanctions/compliance screening физлица
- внутреннее расследование

## 2. Processing activities

- поиск в реестрах/интернете
- сбор сведений
- сопоставление идентичности
- оценка риска
- принятие решения

## 3. Subjects / data

**Субъекты**
- кандидат
- работник
- директор/представитель/бенефициар контрагента

**Типичные данные**
- профессиональные/корпоративные сведения
- судебные/исполнительные сведения в допустимом объеме
- санкционные списки
- публичные сведения
- чувствительные данные — только при специальной необходимости и основании

## 4. Purpose model

- проверка полномочий/конфликта
- compliance/risk management
- требование специального закона
- безопасность

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 5. Нормативная карта

| Source ID | Роль | Что проверять |
|---|---|---|
| `NORM-003` | core | основание |
| `NORM-012` | core | данные не от субъекта |
| `NORM-005` | conditional | если затронуты специальные категории |
| `NORM-011` | conditional | автоматизированное решение |
| `NORM-029` | conditional | работники |

Общий слой G01–G15 из `_general-layer.md` применяется всегда, если карточка прямо не устанавливает более специальное правило.

## 6. Decision tree

1. Определить конкретный риск и правовую/деловую необходимость проверки.
2. Составить закрытый перечень источников и данных.
3. Исключить признаки, не относящиеся к цели.
4. Проверить ст.18(3)–(4).
5. Если автоматический score влияет на человека — проверить S29/ст.16.
6. Обеспечить проверку совпадения личности и возможность исправить ошибочные данные.

## 7. MUST controls

- documented scope of check
- source provenance
- human review негативного результата
- ограниченный доступ/retention

## 8. Recommended controls

- разделять факт из первичного источника и аналитический вывод
- не сохранять весь исходный web-content, если достаточно зафиксировать проверенный факт

## 9. Evidence / документы

- check protocol
- source links/date
- decision rationale
- notice/exemption record

## 10. Red flags

- поиск политических/религиозных/медицинских сведений без специального основания
- отказ кандидату на основе невалидированного автоматического score
- сохранение скриншотов соцсетей без необходимости

## 11. Regulator / expert layer

- Специальная экспертная позиция для этой карточки не требуется; приоритет первичным источникам.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- Сведения о судимости требуют проверки специальных норм применительно к должности; не использовать карточку как универсальное разрешение на такой screening.
