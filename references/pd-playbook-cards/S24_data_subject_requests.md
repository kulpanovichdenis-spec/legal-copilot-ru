**Риск сценария**: Высокий · **Cross-links**: S16, S17, S25

**Назначение:** превратить права субъекта в воспроизводимый workflow с корректными сроками и учетом иных оснований обработки.

## 1. Business triggers

- запрос доступа
- требование исправить данные
- отзыв согласия
- требование прекратить обработку
- требование удалить данные
- жалоба о незаконной обработке

## 2. Processing activities

- прием/идентификация запроса
- поиск данных
- правовая квалификация
- ответ
- исправление/блокирование/удаление
- доведение действий до процессоров

## 3. Subjects / data

**Субъекты**
- любой субъект ПД

**Типичные данные**
- все данные и метаданные, необходимые для идентификации запроса и исполнения требования

## 4. Purpose model

- исполнение прав субъекта
- доказательство выполнения обязанности

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 6. Decision tree

1. Классифицировать запрос: access/correction/withdrawal/cessation/deletion/complaint.
2. Надежно идентифицировать субъекта, не собирая избыточных данных.
3. Определить применимый срок; для доступа — 10 рабочих дней + возможное мотивированное продление до 5, для подтвержденного исправления — 7 рабочих дней.
4. При отзыве согласия проверить, есть ли иное законное основание продолжать конкретные операции.
5. Найти копии у процессоров/в активных системах и применить требуемые действия.
6. Разделить удаление из активной системы и законное архивное хранение.
7. Сохранить доказательство ответа/действия.

## 7. MUST controls

- единый intake channel и owner
- deadline tracking
- поиск по связанным системам/процессорам
- мотивированный ответ при отказе/ограничении
- evidence of correction/deletion

## 8. Recommended controls

- DSAR register с типом требования и системами
- периодические тестовые прогоны поиска данных

## 9. Evidence / документы

- request ticket
- identity verification record
- response
- system actions/logs
- destruction confirmation where required

## 10. Red flags

- автоматическое «удалим всё» при отзыве согласия без проверки иных оснований
- автоматическое «не удаляем, потому что договор» для всех данных
- ответ позже срока из-за долгого SaaS-поставщика

## 11. Regulator / expert layer

- Если консультантский материал указывает иной срок, приоритет всегда у текущих ст.20–21; карточка сознательно опирается на закон.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- Конкретный результат зависит от цели и иных законных оснований; одно требование субъекта может давать разные последствия по разным processing activities.
