## 1. Business triggers

- офлайн-конференция/семинар
- вебинар
- выставка
- HCP scientific/educational event
- мероприятие по фармаконадзору
- спонсорство/финансирование мероприятия

## 2. Processing activities

- регистрация
- ведение списка участников
- обязательное раскрытие/уведомление Росздравнадзора при применимости
- бейджи/networking
- вебинарная платформа
- фото/видео
- передача партнерам/спонсорам
- post-event marketing
- AI summary/Q&A

## 3. Subjects / data

**Субъекты**
- участники
- медицинские/фармацевтические работники
- спикеры/модераторы
- сотрудники/представители партнеров

**Типичные данные**
- ФИО/контакты
- организация/должность/специальность
- сведения об участии/выступлении
- фото/видео
- онлайн-identifiers
- профессиональный статус

## 4. Purpose model

- организация участия
- исполнение фармацевтической обязанности раскрытия — если применима ст.67.2
- профессиональная коммуникация
- networking
- публикация/PR
- маркетинг
- аналитика

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 6. Decision tree

1. Классифицировать событие: обычное мероприятие или подпадает под специальный pharma/HCP режим.
2. Разбить минимум на: registration, statutory disclosure, platform, networking/list, photo/video, sponsor sharing, follow-up marketing, AI use.
3. Для pharma event проверить ст.67.1/67.2 61-ФЗ и ст.74 323-ФЗ; проверить актуальный сервис/форму Росздравнадзора непосредственно перед мероприятием.
4. Если ст.67.2 требует раскрытия/направления состава участников, обрабатывать только необходимый обязательный объем; не считать норму разрешением опубликовать всю анкету HCP.
5. Передачу sponsor/partner attendee list квалифицировать отдельно; спонсорство само по себе не создает legal basis.
6. Публичный список/фото проверить S13.
7. Post-event marketing проверить S11.
8. Вебинарный SaaS проверить S16/S22/S23.
9. Если AI делает summary/transcript, вызвать S29; если в Q&A появляются health cases — S21.
10. Для рекламы лекарств проверить аудиторию/препарат/контекст по ст.24 38-ФЗ.

## 7. MUST controls

- event processing map
- раздельные основания по целям
- актуальная проверка обязательных полей/срока Росздравнадзора
- контроль HCP-only audience там, где это важно для pharma advertising
- отдельная квалификация sponsor sharing
- evidence рекламного consent для follow-up
- vendor/localization/cross-border assessment для онлайн-платформ

## 8. Recommended controls

- не публиковать participant list шире обязательного объема
- для networking использовать opt-in и ограниченный доступ
- разделять registration DB и marketing DB
- для HCP мероприятий хранить compliance pack мероприятия

## 9. Evidence / документы

- registration form/version
- participant list
- Roszdravnadzor notification/receipt and current-form screenshot/reference
- program/agenda
- HCP audience evidence
- sponsor/vendor agreements
- photo permissions where needed
- marketing consent logs
- platform data-flow assessment

## 10. Red flags

- регистрация автоматически включает маркетинг
- спонсор получает базу участников как стандартный бонус
- публикуется вся анкета HCP под видом ст.67.2
- Rx-реклама доступна неопределенному кругу без проверки специального режима
- зарубежная webinar platform без S22/S23
- AI получает Q&A с health data без S21/S29

## 11. Regulator / expert layer

- VERBA применяется как selective pharma/health экспертный источник для поиска отраслевых рисков, а не как источник обязательного права.
- Б-152/Denuo/Kept могут использоваться для operational/site/vendor controls; текст и выводы перепроверяются по НПА.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- Содержание актуальных полей формы Росздравнадзора является внешним изменяемым implementation detail: проверять online, не хранить как неизменную норму.
- Применимость ст.67.2 зависит от вида мероприятия, организатора/финансирования и состава участников; требуется factual classification.
