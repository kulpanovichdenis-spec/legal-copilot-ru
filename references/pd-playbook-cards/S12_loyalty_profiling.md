**Назначение:** отделить исполнение программы лояльности от маркетингового профилирования и автоматизированных решений.

## 1. Business triggers

- карта лояльности
- баллы/скидки
- сегментация клиентов
- персональные предложения
- рекомендации на сайте
- scoring propensity/churn

## 2. Processing activities

- регистрация в программе
- учет покупок/баллов
- сегментация
- построение профиля
- выдача рекомендации
- автоматическое изменение условий

## 3. Subjects / data

**Субъекты**
- клиенты/пользователи

**Типичные данные**
- контакты/ID
- история покупок
- баллы
- поведение
- сегменты/предикторы
- выводы о предпочтениях

## 4. Purpose model

- ведение программы
- персонализация
- маркетинг
- аналитика
- предотвращение злоупотреблений

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 6. Decision tree

1. Разделить механический учет баллов и построение профиля.
2. Определить, какие исходные данные и выводы включены в профиль.
3. Если технология формирует рекомендации на информационном ресурсе, проверить 149-ФЗ.
4. Если решение исключительно автоматическое и юридически/существенно затрагивает субъекта, применить ст. 16.
5. Для коммуникации предложения применить S11.
6. Для AI-модели применить S29.

## 7. MUST controls

- прозрачно описать цели программы
- не использовать чувствительные признаки без специального основания
- обеспечить права субъекта и корректность исходных данных
- не маскировать значимое автоматическое решение как обычную рекомендацию

## 8. Recommended controls

- проводить отдельную assessment новых моделей сегментации
- фиксировать features и бизнес-правила для воспроизводимости

## 9. Evidence / документы

- rules of loyalty program
- profile feature register
- recommendation-tech rules
- model/decision record
- marketing consent evidence

## 10. Red flags

- вывод о здоровье/беременности/религии из покупок для таргетинга без S21
- динамическое ухудшение условий полностью автоматизированно без S16 assessment
- необъяснимый профиль из данных партнеров

## 11. Regulator / expert layer

- Специальная экспертная позиция для этой карточки не требуется; приоритет первичным источникам.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- Не всякая персонализация подпадает под ст.16: нужны одновременно исключительная автоматизация и юридические последствия/существенное затрагивание прав.
