## 1. Business triggers

- парсинг сайтов/соцсетей
- покупка базы
- получение контактов от партнера
- открытые реестры
- data broker
- рекомендация/lead list

## 2. Processing activities

- получение
- обогащение
- сопоставление
- профилирование
- коммуникация
- передача дальше

## 3. Subjects / data

**Субъекты**
- кандидаты
- B2B-контакты
- клиенты/лиды
- директора/учредители и др.

**Типичные данные**
- идентификационные/контактные
- профессиональные
- публично доступные факты
- выводы/профили

## 4. Purpose model

- проверка/комплаенс
- деловая коммуникация
- рекрутинг
- маркетинг
- аналитика

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 5. Нормативная карта

| Source ID | Роль | Что проверять |
|---|---|---|
| `NORM-012` | core | информирование при получении не от субъекта |
| `NORM-003` | core | основание |
| `NORM-006` | conditional | режим данных, разрешенных для распространения |
| `NORM-002` | core | совместимость/минимизация |

Общий слой G01–G15 из `_general-layer.md` применяется всегда, если карточка прямо не устанавливает более специальное правило.

## 6. Decision tree

1. Зафиксировать точный источник и дату получения.
2. Определить, правомерно ли получатель использует данные для своей конкретной цели; публичность источника не заменяет legal basis.
3. Проверить обязанность информирования субъекта по ст.18(3)–(4).
4. Проверить ограничения/условия распространения по ст.10.1, если релевантно.
5. Для маркетинга вызвать S11; для background check — S20.
6. Проверить надежность/актуальность данных и механизм исправления.

## 7. MUST controls

- source provenance
- legal-basis memo
- информирование субъекта или документированное исключение
- срок пересмотра/актуализации

## 8. Recommended controls

- для массового сбора проводить отдельную assessment необходимости и воздействия

## 9. Evidence / документы

- source log
- vendor/data-license docs
- notice record
- correction workflow

## 10. Red flags

- «найдено в интернете = общедоступные ПД без ограничений»
- купленная база без происхождения
- профиль человека из многих источников без purpose/basis assessment

## 11. Regulator / expert layer

- Специальная экспертная позиция для этой карточки не требуется; приоритет первичным источникам.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- Правовой статус конкретного публичного реестра определяется также специальным законодательством и условиями доступа.
