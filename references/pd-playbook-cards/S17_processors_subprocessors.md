**Назначение:** построить сквозную цепочку передачи данных и обеспечить flow-down требований оператора.

## 1. Business triggers

- аутсорсинг бухгалтерии/HR
- call-center
- доставка
- маркетинговое агентство
- IT-support
- subcontractor поставщика

## 2. Processing activities

- передача/доступ
- хранение/обработка по инструкции
- дальнейшее привлечение субподрядчика
- возврат/удаление

## 3. Subjects / data

**Субъекты**
- любые категории, чьи данные передаются подрядчику

**Типичные данные**
- набор зависит от порученной функции; должен быть ограничен необходимым

## 4. Purpose model

- исполнение функции по поручению
- самостоятельные цели подрядчика — выделяются отдельно

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 5. Нормативная карта

| Source ID | Роль | Что проверять |

Общий слой G01–G15 из `_general-layer.md` применяется всегда, если карточка прямо не устанавливает более специальное правило.

## 6. Decision tree

1. Для каждого получателя определить фактическую роль.
2. Ограничить предмет поручения конкретными целями/данными/операциями.
3. Проверить возможность/условия subprocessors.
4. Проверить flow-down confidentiality/security/incident/deletion.
5. Отдельно квалифицировать собственные цели подрядчика.
6. Включить всю цепочку в S22/S23 assessment при зарубежной инфраструктуре.

## 7. MUST controls

- описание поручения
- обязательство соблюдать конфиденциальность и безопасность
- уведомление об инциденте
- подтверждение мер по запросу оператора
- возврат/уничтожение
- контроль дальнейшего привлечения лиц

## 8. Recommended controls

- риск-ориентированный due diligence поставщиков
- реестр subprocessors и дат изменений

## 9. Evidence / документы

- processor agreement
- subprocessor register
- audit/security evidence
- deletion certificate
- incident contacts

## 10. Red flags

- передача «всем партнерам» без перечня/роли
- подрядчик определяет собственный маркетинг на данных оператора
- цепочка неизвестна оператору

## 11. Regulator / expert layer

- Privacy Advocates third-party assessment и Б-152 использованы как идейная сверка полноты, без копирования методик.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- Один контрагент может быть processor по одной операции и самостоятельным оператором по другой.
