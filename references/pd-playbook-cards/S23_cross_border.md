## 1. Business triggers

- иностранный SaaS/облако
- иностранная компания группы
- зарубежный support/admin access
- международный webinar/marketing provider
- передача данных иностранному контрагенту
- foreign AI API

## 2. Processing activities

- передача/предоставление/доступ иностранному лицу
- хранение/обработка за рубежом
- remote support
- репликация/backup

## 3. Subjects / data

**Субъекты**
- любые субъекты, чьи данные уходят иностранному получателю

**Типичные данные**
- конкретные категории по каждому получателю/стране

## 4. Purpose model

- цель основной обработки + цель передачи конкретному получателю

**Правило:** одна техническая система или один бизнес-процесс могут включать несколько самостоятельных целей. Каждая цель получает собственные `legal basis / dataset / recipients / retention`.

## 6. Decision tree

1. Подтвердить факт трансграничной передачи и конкретного иностранного получателя/страну.
2. Проверить актуальный на сегодня перечень государств с адекватной защитой; не полагаться на сохраненную копию.
3. Собрать сведения о получателе и мерах защиты в объеме, требуемом ст.12.
4. Проверить/направить отдельное уведомление Роскомнадзора до начала соответствующей деятельности.
5. Проверить, нет ли решения РКН о запрете/ограничении.
6. Отдельно убедиться, что S22 localization выполнен; одно не заменяет другое.
7. При изменении страны/получателя/цели повторить assessment и проверить необходимость обновления сведений.

## 7. MUST controls

- recipient/country inventory
- current-list online check
- специальная cross-border assessment
- уведомление РКН до старта в предусмотренном законом порядке
- договорные меры и security evidence

## 8. Recommended controls

- вести одну централизованную cross-border register со связью с vendor register
- не проектировать долгосрочную архитектуру только на статусе страны; учитывать возможное изменение перечня

## 9. Evidence / документы

- копия/ID уведомления
- country-list verification date
- recipient questionnaire
- contract/security docs
- data-flow map

## 10. Red flags

- «страна дружественная, значит передача разрешена»
- обычное уведомление оператора принимается за специальное уведомление о ТГП
- зарубежный админ-доступ не отражен в карте
- перечень стран проверялся год назад

## 11. Regulator / expert layer

- Denuo используется как свежий индикатор практического статуса перечня после июльских изменений 2026 года; финальный ответ всегда проверяет действующий приказ РКН.
- Privacy Advocates может использоваться для анализа спорных архитектур, но не как нормативный источник.

**Правило веса:** экспертный материал используется только как аналитический ориентир. Формулировки консультантов не воспроизводятся и не превращаются в `MUST` без подтверждения первичным источником.

## 12. Uncertainty / границы вывода

- После изменений 26.07.2026 этот блок является P0 в watchlist. Перед каждой новой передачей обязательна online verification ст.12 и действующего перечня.
- На дату сборки в реестре источников указан приказ РКН №128; его статус должен проверяться перед применением.
