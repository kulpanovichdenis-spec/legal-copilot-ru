# Протокол прямого точечного поиска НПА на pravo.gov.ru

Точный порядок поиска федерального акта в legacy-ИПС «Законодательство России» портала `pravo.gov.ru`. Это provider-specific протокол над `references/web-research-tools.md` (раздел 3.2), а не цепочка после локальной базы.

## Когда применяется (место в порядке)

1. Сначала вызвать `route_norm_verification(jurisdiction="RU", probe=true)`. Этот протокол применять, когда direct provider pravo.gov.ru возвращён с `usable_now: true`, либо для ручной диагностики портала.
2. Автоматический путь: `pravo_resolve_act(act_number, act_date)` → `pravo_get_document(nd)` / `pravo_get_article`; ручной путь воспроизводит то же разрешение identity через `WebFetch` / `agent-browser`. Путь не ограничен законами: указы Президента и постановления Правительства разрешаются так же, по номеру и дате (`1203` / `1995-11-30`, `644` / `2013-07-29`).
3. Поисковая карточка и snippet не подтверждают норму. Не раскрыт полный текст или не подтверждены редакция/статус/pinpoint/provenance — `[ПРОВЕРИТЬ НОРМУ]`; можно выбрать другой `usable_now: true` provider.

Происхождение: адаптировано из технической инструкции серверного агента (проверка действующей серверной реализации 03.09.2026). Серверная реализация делает это через raw-HTTP с полным набором защит (allowlist redirect, лимит размера, SHA-256, строгий charset). Наш агент делает то же через свои инструменты (`WebFetch`/`agent-browser`) и применяет **эквивалентную дисциплину проверки**, а не доверяет сниппету выдачи.

## Минимальный вход

- **номер акта** в официальном написании: `61-ФЗ`, `152-ФЗ`, `100н`, `681`;
- **дата акта** (не дата публикации), `YYYY-MM-DD`.

Номер/дата неизвестны — сначала установить реквизиты по названию/теме; **не подставлять предполагаемые номер/дату молча** (иначе `[ПРОВЕРИТЬ РЕКВИЗИТЫ]`). Перед запросом: обрезать пробелы, запретить переносы/табуляцию, номер должен быть представим в CP1251.

## Шаг 1. URL точного поиска

Базовый адрес — `http://pravo.gov.ru/proxy/ips/` (legacy работает по **HTTP**, не HTTPS). Шаблон:

```text
http://pravo.gov.ru/proxy/ips/?list_itself=&bpas=cd00000&a7type=1&a7date=<DD.MM.YYYY>&a8=<НОМЕР_CP1251_URLENCODED>&a8type=2&textpres=yes&sort=7&page=firstlast
```

| Параметр | Значение | Назначение |
|---|---|---|
| `list_itself` | пусто | режим списка результатов |
| `bpas` | `cd00000` | фиксированный параметр IPS |
| `a7type` / `a7date` | `1` / `DD.MM.YYYY` | поиск по точной дате акта |
| `a8` / `a8type` | номер (CP1251, percent-encoded) / `2` | точный поиск по номеру |
| `textpres` | `yes` | только результаты с текстом |
| `sort` / `page` | `7` / `firstlast` | фиксированная сортировка и страница |

Параметры и их порядок сохранять как есть; произвольные не добавлять.

### Ключевая ловушка — кодирование номера в CP1251

Кириллический номер кодируется **не как UTF-8**, а: строка → байты Windows-1251 → строгий percent-encoding каждого байта (`safe=""`). Пример: `61-ФЗ` → `61-%D4%C7`. UTF-8-кодирование номера ломает legacy-поиск.

Собрать URL можно готовым билдером (запустить через Bash, затем скормить URL в `WebFetch`/`agent-browser`):

```python
from datetime import date
from urllib.parse import quote_from_bytes

PRAVO_BASE = "http://pravo.gov.ru/proxy/ips/"

def cp1251_quote(value: str) -> str:
    return quote_from_bytes(value.encode("cp1251", errors="strict"), safe="")

def build_pravo_search_url(act_number: str, act_date: date) -> str:
    number = act_number.strip()
    if not number or number != act_number or len(number) > 120 or any(c in number for c in "\r\n\t"):
        raise ValueError("invalid act_number")
    query = "&".join((
        "list_itself=", "bpas=cd00000", "a7type=1",
        f"a7date={act_date.strftime('%d.%m.%Y')}",
        f"a8={cp1251_quote(number)}", "a8type=2",
        "textpres=yes", "sort=7", "page=firstlast",
    ))
    return f"{PRAVO_BASE}?{query}"

def build_pravo_document_url(nd: str) -> str:
    if not nd.isdecimal() or not 6 <= len(nd) <= 30:
        raise ValueError("nd must be 6-30 digits")
    return f"{PRAVO_BASE}?doc_itself=&nd={nd}&fulltext=1"
```

Проверенный пример: `61-ФЗ` от `2010-04-12` →
`http://pravo.gov.ru/proxy/ips/?list_itself=&bpas=cd00000&a7type=1&a7date=12.04.2010&a8=61-%D4%C7&a8type=2&textpres=yes&sort=7&page=firstlast` (подтверждён с production 03.09.2026: `nd=102137440`).

## Шаг 2. Разбор выдачи и определение `nd`

В HTML выдачи разбирать только ссылки `<a href="...">` вида (host строго `pravo.gov.ru`, path `/proxy/ips/`):

- тело документа: `?docbody=&link_id=<1-6 цифр>&nd=<6-30 цифр>`; live-выдача также может добавлять строго `firstDoc=1` (у `<a>` — `id="link_<LINK_ID>"`, значение `link_id` может быть `0`);
- полный текст: `?doc_itself=&nd=<6-30 цифр>&fulltext=1`.

Ссылки с лишними/неизвестными параметрами, дублями ключей, userinfo, fragment, нестандартным портом — игнорировать. `nd` собирать в множество (убрать повторы). **Не искать `nd` произвольным regex по всему HTML.**

Исход:

| Кандидатов `nd` | Статус | Действие |
|---|---|---|
| 0 | `NOT_FOUND` | акта по этим реквизитам нет — не достраивать |
| 1 | `RESOLVED` | перейти к шагу 3 |
| >1 | `AMBIGUOUS` | **не брать первый**; открыть каждого и сверить вид/орган/дату/номер/название; не свёлся к одному — считать не найденным для авто-применения |
| проверки не прошли | `FAILED` | контролируемая ошибка, не выдумывать |
| портал вернул страницу без текста | `FAILED` (`empty_search_response` / `empty_document_text`) | сбой получения, а не отсутствие акта или статьи; адаптер повторяет запрос один раз, затем — повторить позже |

`NOT_FOUND` означает только одно: страница с текстом получена, а акта или статьи в ней нет. Пустая страница так не трактуется (то же для `pravo_get_document` и `pravo_get_article`).

## Шаг 3. Полный текст по `nd`

```text
http://pravo.gov.ru/proxy/ips/?doc_itself=&nd=<ND>&fulltext=1
```

`nd` точно равен найденному кандидату. Пример: `...?doc_itself=&nd=102137440&fulltext=1`.

## Шаг 4. Проверка идентичности (обязательно перед использованием)

Совпадения `nd` **недостаточно**. Из текста/метаданных подтвердить: (1) вид акта; (2) номер; (3) дату принятия; (4) орган издания; (5) название (или устойчивые фрагменты). Нужна конкретная норма — проверить наличие статьи/части/пункта. Не подтверждается — `[ПРОВЕРИТЬ РЕКВИЗИТЫ]` / `[ПРОВЕРИТЬ НОРМУ]`, а не «похоже, оно».

**Ловушка структуры:** надстрочные номера статей `Статья 8<sup>1</sup>` нормализовать как `Статья 8.1` — но только когда `<sup>` действительно внутри структурного номера, не в произвольном месте.

Провенанс при использовании/сохранении: исходный URL, `nd`, реквизиты, время получения; при сохранении текста — SHA-256 канонического текста (для последующей сверки).

## Запрещённые упрощения

- кодировать кириллический номер как UTF-8 (нужен CP1251);
- искать `nd` regex по всему HTML;
- при нескольких `nd` брать первый;
- следовать redirect без повторной проверки URL; принимать зеркало/похожий домен/другой path;
- считать `nd` достаточным подтверждением идентичности;
- **цитировать сниппет выдачи вместо открытия и проверки полного текста** (общее правило `references/source-hierarchy.md`);
- достраивать результат по догадке вместо контролируемой ошибки/маркера.

## Критерий успеха

`RESOLVED` + подтверждённые `act_number`/`act_date` + единственный `nd` + `document_url` прошёл проверку + сверены вид/орган/название + требуемая норма найдена (или явно отмечено, что её нет) + зафиксировано время получения (+ SHA-256, если текст сохраняется). Иначе — контролируемая ошибка или маркер ручной проверки.
