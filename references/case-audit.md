# История работы и стоимость задачи

Сводка принадлежит конкретной задаче: `workflow/<задача>/_llm/case-context.md`.
`_knowledge/` — карточки документов внутри дела; они не заменяют историю работы.
Технический журнал `case-audit.jsonl` и архив `_audit/versions/` для новых дел находятся в `_llm/`. Старые пути поддерживаются по `references/workflow-layout.md`. Внешних отправок инструмент не делает.

## Порядок работы агента

1. При начале содержательной работы прочитать карточку. В Codex сразу привязать
   текущий turn: `python -m tools.case_audit bind-codex --case "workflow/<задача>"`.
   Для других раннеров выбрать постоянный `task_id` и новый `run_id`, затем зарегистрировать `run`: `runner`, `provider`, точный `model`,
   `usage_status` (`available`, `partial`, `unavailable`), настройки в `settings`,
   commit проекта и версии skills в `implementation`. Если ID модели не раскрыт,
   указать `unknown` и событие `gap`. Не подставлять API-модель по похожему имени.
2. Записать существенные вводные и изменения задания как `request`, сохраняя
   источник реплики и её краткое содержание. Для каждого использованного документа
   зарегистрировать версию командой `document`: сохраняются SHA-256 и точная копия.
   Для внешних правовых источников — `document` через `event`: URL/provider,
   дата доступа, редакция, locator и ссылка на локально сохранённый текст.
3. Сохранять промежуточные результаты и итог как `result`, изменения как `revision`.
   `refs` — ID событий источников/предыдущих версий; `locator` — страница/пункт.
   `conclusion` содержит тезис, refs на основания, locator, ограничения проверки.
   Это проверяемое обоснование, а не скрытые рассуждения модели.
4. `approval` содержит точные refs версий, `decision`, `authority_source`
   (ID сообщения/письма юриста), дату и actor согласовавшего. Агент не создаёт
   согласование из своего предположения. `action` содержит описание, status
   (`planned`, `attempted`, `completed`, `failed`), основание разрешения и результат.
5. В Codex Stop-hook после завершения привязанного turn импортирует локальные
   `token_count`. У разных генераций разные `request_id`; повторный импорт не
   увеличивает сумму. Для других раннеров импортировать фактический расход каждого
   запроса, включая повторные попытки и субагентов. Если usage недоступен — `gap`,
   а не оценка по длине текста. После этапа обновить сводку, проверить `validate`.

Каждое событие: `summary`, при необходимости `task_id`, `refs`, `locator` и
содержательные поля. История дополняется; исправление — новое событие со ссылкой
на прежнее. Цепочка хешей выявляет изменение записей, но не является электронной
подписью и не защищает от полной подмены журнала. Одновременные записи блокируются;
после аварии оставшийся `.case-audit.lock` разбирается вручную.

## Команды

Подготовить JSON события внутри папки задачи, например `run.json`:

```json
{
  "summary": "Анализ новой редакции договора",
  "task_id": "review-1",
  "runner": "codex",
  "provider": "openai",
  "model": "unknown",
  "usage_status": "unavailable",
  "settings": {},
  "implementation": {"commit": "unknown", "skills": []}
}
```

```powershell
python -m tools.case_audit event --case "workflow/<задача>" --run-id session-1 --kind run --data "workflow/<задача>/run.json"
python -m tools.case_audit bind-codex --case "workflow/<задача>"
python -m tools.case_audit document --case "workflow/<задача>" --run-id session-1 --file "договор.docx" --version "получен от контрагента 2026-10-21" --summary "Исходная редакция"
python -m tools.case_audit report --case "workflow/<задача>"
python -m tools.case_audit validate --case "workflow/<задача>"
```

`event` и `document` автоматически обновляют выделенный блок в case-context;
остальной текст карточки сохраняется. Существующие дела массово не мигрируются;
отдельное дело по указанию юриста восстанавливается задним числом: в каждом
событии `"reconstructed": true` и `"occurred_on"` (дата по case-context или
файлам), `run` — `usage_status: unavailable`, источник восстановления в `summary`.

## Опора на нормы и практику

Каждая норма, судебный акт или официальное разъяснение, на которые опирается
правка, комментарий или вывод для человека, — отдельное событие `document`
с полями:

```json
{
  "summary": "Гарантия качества без оговорки о неизвестности",
  "source_kind": "norm",
  "ref": "ГК РФ ст. 476 п. 2",
  "route": "pravo.gov.ru",
  "checked": true,
  "used_in": "rev1, п. 6.3"
}
```

`source_kind` — `norm`, `practice` или `guidance`. `route` — инструмент, через
который текст открыт (локальная база, КонсультантПлюс, pravo.gov.ru, kad.arbitr.ru);
если текст не открывался — `"память модели"` и `"checked": false`. Без `ref`,
`route` и `checked` событие не записывается. Сводка в case-context показывает
таблицу «Опора на нормы и практику»: юрист видит, что проверено и чем, а что
взято из памяти модели. Комментарии в документе для контрагента этих пометок
не содержат.

```powershell
python -m tools.case_audit event --case "workflow/<задача>" --run-id session-1 --kind document --data norm.json
```
Для проектов анонимайзера текущий CLI запрещён: правила доступа к ним не расширены.
При необходимости создать отдельную задачу с обезличенными материалами вне
`_anonymizer`; перенос оригиналов/mappings запрещён.

## Расход и тарифы

Команда `import-openai` читает явно переданный локальный ответ Responses API:

```powershell
python -m tools.case_audit import-openai --case "workflow/<задача>" --run-id session-1 --file response.json --pricing pricing.json
```

Без `--pricing` сохраняются токены, цена остаётся неизвестной. Импорт выделяет
cached input из общего input; reasoning уже включён в output и второй раз не
прибавляется. Ответы с cache-write требуют явных категорий через `event --kind usage`.
В ответе без `service_tier` режим `unknown`: стандартный тариф не подставляется.

Контракт нормализованного `usage` для остальных раннеров/провайдеров:

```json
{
  "summary": "Расход одного запроса",
  "provider": "provider-id",
  "model": "exact-model-id",
  "request_id": "unique-request-id",
  "service_tier": "default",
  "usage_source": "локальный файл/событие счётчика с хешем",
  "tokens": {"input_uncached": 1000, "input_cached": 200, "output": 100},
  "pricing": {
    "provider": "provider-id",
    "model": "exact-model-id",
    "service_tier": "default",
    "currency": "USD",
    "checked_at": "2026-10-21T00:00:00Z",
    "source_url": "URL открытого официального тарифа",
    "per_million": {"input_uncached": "0", "input_cached": "0", "output": "0"}
  }
}
```

Нулевые ставки в примере — заполнители, не действующие цены. Агент обязан открыть
официальный тариф и заменить их проверенными ставками до использования.
В snapshot также сохранять условия применимости (длина контекста, регион,
batch/flex/priority, границы периода действия), если они влияют на цену.
API-эквивалент = сумма отдельных категорий × их ставка / 1 000 000.
Ставки сохраняются внутри события и задним числом не меняются. Если точному
ID/режиму тариф не сопоставлен, цену не рассчитывать. Скидки, налоги, комиссии,
OCR, поиск и другие платные инструменты не входят в токенную сумму.
`actual_charge_usd` допускается только с `charge_source` провайдера; это отдельный
показатель. Подписка раннера не является фактическим API-списанием.

Источник правил расчёта OpenAI: [официальные API-тарифы](https://developers.openai.com/api/docs/pricing).
Для автоматического Codex-импорта в коде хранится датированный снимок Standard-тарифа
для поддержанных точных model ID. Иные тарифы передаются отдельным JSON-снимком.

## Границы сбора

Сейчас доступны ручная/агентная регистрация событий, импорт Responses API и
автоматический постфактум-импорт Codex Desktop для явно привязанного turn.
Автоматический импорт нативных
транскриптов Claude/Cursor не подключён. Глобальные лимиты аккаунта не
заменяют usage конкретного дела. Не сканировать домашний каталог и не относить
целую сессию к делу, если в ней решались разные задачи.

Codex сохраняет `token_count` локально; Stop-hook берёт только счётчики указанного
session/turn и не сохраняет сырой транскрипт. API-эквивалент считается по точному
model ID и снимку публичного Standard-тарифа на дату реализации. Reasoning входит
в output и отдельно не прибавляется. Cache-write без известного TTL сохраняется
в токенах, но не получает цену. Сводка показывает только зарегистрированный расход.
Журналы могут содержать конфиденциальные данные: хранить только внутри workflow,
не коммитить, не включать секреты, mappings и полные сырые транскрипты.
