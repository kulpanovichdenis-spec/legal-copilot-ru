# Фирменный стиль и письма на бланке

Единый источник правил для писем на фирменном бланке компании пользователя. Код — `tools/brand_kit/` (`letterhead.py` — сборка письма, `scan.py` — разбор бланков). Параметры оформления (шрифт, поля, колонтитулы, логотип, реквизиты) задаёт сам бланк, а не профили `references/document-formatting.md`.

## 1. Где лежит фирменный стиль

`profile/knowledge/brand/` — личный слой профиля. В git только скелет (`README.md`, `_inbox/.gitkeep`); бланки, манифест и превью в `.gitignore` и переезжают вместе с профилем (`tools/profile/portable.py`).

| Путь | Что там |
|---|---|
| `_inbox/` | сюда пользователь копирует папку фирменного стиля целиком, как её выдал работодатель (бланки, логотипы, визитки, подписи) |
| `originals/` | та же папка после разбора; структура подпапок сохраняется |
| `brand.yaml` | манифест: бланки, назначение, слоты (схема `brand_kit.v1`) |
| `brand.draft.yaml` | результат повторного разбора, если `brand.yaml` уже есть: сверить и перенести изменения вручную |
| `previews/` | PNG первой страницы бланка (если рядом с .docx лежит одноимённый .pdf) |

Бланком считается `.docx` или `.dotx`. Остальные файлы (`.ai`, `.png`, `.svg`, `.html`) учитываются в манифесте как `other_assets` и в письма не попадают.

## 2. Подключение фирменного стиля

1. Пользователь кладёт папку в `profile/knowledge/brand/_inbox/`.
2. Агент запускает `python -m tools.brand_kit scan`: папка переезжает в `originals/`, для каждого .docx/.dotx определяется вид (`letterhead` — бланк письма, `form` — фирменная форма другого назначения, например оффер; не бланки уходят в `other_documents`) и предлагаются слоты.
3. Агент сверяет черновик манифеста с превью (`previews/`) и демо-письмом: `python -m tools.brand_kit demo <blank_id> <путь>.docx`. Проверить: каждый слот находит своё место, назначение `use_for` разумно, `default_blank` — основной бланк писем.
4. Юристу — коротко: какие бланки найдены, для чего предложены, что осталось неясным. Подтверждение юриста фиксируется в `brand.yaml`: `status: confirmed`. До подтверждения бланк можно использовать, но каждый раз говорить одной строкой, что манифест не подтверждён.

Если шаг 2 не нашёл ни одного слота `body`, бланк не годится для автоматической сборки: сказать юристу, не верстать бланк «по картинке».

## 3. Манифест `brand.yaml`

```yaml
schema: brand_kit.v1
status: draft                # draft | confirmed (confirmed ставится по решению юриста)
company: <наименование из колонтитула бланка>
default_blank: <id>
blanks:
  - id: <id>
    kind: letterhead         # letterhead | form
    file: originals/<путь к .docx/.dotx>
    use_for: [counterparty_letter, business_letter]
    slots:
      date: {field: "[Дата]"}                       # поле MACROBUTTON / элемент управления содержимым
      addressee: {text: "Указание адресата", in: first_page_header, drop_next: 1}
      executor: {text: "Исполнитель:", prefix: "Исполнитель: "}
      reply_to: {text: "На № ____", in: first_page_header, optional: true}
      body: {field: "[Текст]", mode: replace, align: justify, after_pt: 6, keep_empty: 1}
```

Ключи слота: `field` (подпись поля) или `text` (подстрока абзаца-подсказки); `nth` — какое по счёту совпадение; `in` — часть документа (`body`, `first_page_header`, `header`, `footer`…); `drop_next` — удалить столько абзацев-подсказок после найденного; `prefix` — подпись строки, которая остаётся перед значением; `optional` — не считать незаполненным. Слот `body`: `mode: replace` (абзац-заполнитель заменяется текстом письма) или `after` (текст идёт после найденного абзаца, например после обращения); `align`, `first_line_cm`, `size_pt`, `after_pt`, `keep_empty`.

Назначения `use_for`: `counterparty_letter` (письма контрагентам), `business_letter` (короткие деловые), `official_letter` (официальное исходящее, ГОСТ-оформление), `gov_response` (ответы госорганам), `claim` (претензии, только если юрист так решил), `landscape` (альбомный).

Словарь слотов: `date`, `out_number`, `reg_line`, `reply_to`, `addressee`, `addressee_name`, `addressee_position`, `addressee_org`, `addressee_address`, `title`, `salutation`, `salutation_name`, `body`, `signer_name`, `signer_position`, `executor`, `executor_phone`, `executor_email`. Неизвестное поле разбор называет `field_N`: агент переименовывает его по смыслу.

## 4. Когда письмо собирается на бланке

- **Письмо контрагенту** (`counterparty-letter`) и **ответ госоргану / официальное исходящее** (`gov-response`): на бланке по умолчанию, если в манифесте есть бланк с подходящим `use_for` (иначе `default_blank` для писем контрагентам; для госоргана без `gov_response`/`official_letter` — `ProceduralDoc`). Юрист может сказать «без бланка».
- **Претензия** — на бланке только по слову юриста или если у бланка есть `use_for: claim`.
- **Не на бланке**: документы в суд, договоры и ДС, записки юристу, анализы. Записка юристу к письму всегда собирается отдельно (`NoteDoc`).
- Манифеста нет — работать как раньше (профили `document-formatting.md`) и не спрашивать про бланк каждый раз. Если `_inbox/` не пуст — сначала разбор по разделу 2.

## 5. Сборка

```python
import sys; sys.path.insert(0, r"<корень legal-copilot>")
from tools.brand_kit.letterhead import LetterheadDoc
d = LetterheadDoc(purpose="counterparty_letter")   # или LetterheadDoc("<blank_id>")
d.fill("addressee", ["Генеральному директору", "ООО «…»", "И. О. Фамилии", "<адрес из ЕГРЮЛ>"])
d.fill("title", "О предоставлении документов")
d.fill("salutation", "Уважаемый Иван Иванович!")
d.para("…"); d.point("1.", "…"); d.heading("…"); d.table([...], [[...]], [см, …])
d.signature(["Генеральный директор", "________________ / И. О. Фамилия"])  # если подписанта в бланке нет
report = d.save(r"…\workflow\<дело>\Письмо.docx")
```

- Текст письма пишется методами `para / point / bullet / heading / table / signature`; разметка `**полужирный**`, маркеры неполноты подсвечиваются, как в остальных профилях.
- `report` после сохранения: `unfilled_slots` (не заполнены), `placeholders_left` (поля бланка остались), `slots_not_found` (манифест не совпал с бланком), `manifest_status`. Всё, что осталось незаполненным, назвать юристу; не прятать пустой слот выдуманным значением.
- **Регистрационные данные** (исходящий номер, дата регистрации, `reg_line`) заполняет канцелярия: агент оставляет их как в бланке. Дату и номер письма, на которое отвечаем (`reply_to`), заполнять только из документа дела.
- Реквизиты адресата берутся из проверенного источника (ЕГРЮЛ через `counterparty-check`, письмо органа), подписант и исполнитель — от юриста или из `case-context.md`; иначе маркер `[ПРОВЕРИТЬ РЕКВИЗИТЫ]`.
- Подпись: если в бланке есть слоты `signer_*`, заполнять их; иначе `signature()`. Изображение подписи на бланк не ставится.
- После сборки — визуальная проверка: `python tools/docx_render/render_docx.py <файл> --output-dir <папка> --dpi 96`. Если Word COM не открывает бланк (бывает с EMF-графикой в колонтитуле), проверить текст через python-docx и сказать юристу, что визуально документ не проверен.

## 6. Ограничения

- Бланк не правится и не перерисовывается: логотип, реквизиты компании в колонтитуле и шрифт берутся из файла как есть. Если реквизиты в бланке устарели — сказать юристу, не исправлять.
- Название компании и реквизиты из бланка — данные пользователя: в git, публичную сборку, тесты и `references/` не переносить.
- Разбор детерминированный и предлагает черновик; решение о назначении бланков и `status: confirmed` — за юристом.
