# Judge Analytics — статистика по судье арбитражного суда

**Архитектурный паттерн:** sequential pipeline, low freedom — сбор, фильтрация состава суда, классификация резолютивок и подсчёт выполняет скрипт `tools/judge_stats/judge_stats.py`; модель отвечает за подготовку входов, ручной разбор неоднозначных актов и юридическую интерпретацию.

## Назначение

По ФИО судьи, суду и периоду skill готовит:
- статистику постановлений, где судья входил в состав суда: оставлено без изменения / отменено (полностью, в части, с направлением на новое рассмотрение) / изменено / прекращено по жалобе / без рассмотрения / мировое / процедурное;
- количество уникальных дел отдельно от количества постановлений;
- CSV + JSON по каждому акту (номер дела, категория, роль судьи в составе) и Markdown-отчёт;
- заметку для юриста: ограничения данных и что перепроверить.

## Принципы

1. **Все цифры — нижняя оценка по доступному корпусу зеркала, не официальная статистика суда и не «профиль личности» судьи.** Дисклеймер об этом обязателен в каждом отчёте; скрипт вставляет его сам — не удалять.
2. **Детерминированный подсчёт — только скриптом.** Не считать акты «на глаз» по выдаче поиска и не классифицировать резолютивки пересказом: цифры, полученные без скрипта, невоспроизводимы и в отчёт не идут.
3. **Не угадывать неоднозначное.** Категории `ambiguous` / `unclassified` из `classification.csv` разбираются вручную: модель читает резолютивку, предлагает категорию с цитатой, решение — за юристом.
4. **Судья считается только по блоку состава суда.** Упоминания вида «произведена замена судьи…» или ссылка на судью первой инстанции — не участие (это делает скрипт; при ручном разборе — то же правило).
5. **Иерархия источников:** первичен kad.arbitr.ru (Приоритет 1); fallback-цепочка: зеркало `sudrf.cntd.ru` / `api.docs.cntd.ru` → агрегатор `sudact.ru` (фильтр «Судья» в разделе арбитража). Капчи, 451 и иные ограничения не обходить — зафиксировать и перейти к следующему источнику с пометкой в отчёте. Известные по прогону 2026-07-07 ограничения: КАД в автоматизированном браузере не выполняет XHR (анти-бот — симптом: «Укажите атрибуты дела для поиска» при заполненной форме и пустой network-лог); корпус cntd не покрывает АС Московской области и слаб по 2025+; sudact работает через agent-browser (список — целиком, полные тексты — только точечной выборкой с паузами, массовая выгрузка упрётся в лимиты).
6. **Результат — черновик.** Перед использованием цифр в процессуальном документе — выборочная сверка 3–5 дел с kad.arbitr.ru (`[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]`); статистика прошлых дел — не прогноз исхода и не основание правовой позиции.

## Входные данные

Уточнить или извлечь из запроса: ФИО судьи (`Фамилия И.О.` — инициалы обязательны из-за однофамильцев), суд (например, `18 ААС`), период (`01.01.2025–30.06.2026`). Чего-то нет — спросить, не подставлять по умолчанию.

## Алгоритм

1. **Подпапка результатов:** `workflow/<судья-суд-период>/` (сообщить юристу одной строкой).
2. **department_id суда:** открыть страницу суда на `sudrf.cntd.ru` (agent-browser / WebFetch по `references/web-research-tools.md`) либо сделать пробный поиск через API и взять `registrations[].department` из выдачи. Найденный id записать в отчёт.
3. **id типа «постановление»** (опционально, сужает выборку): в пробной выдаче поиска это `registrations[].doctype.id` у документов с именем «Постановление …». Без него скрипт возьмёт все типы, а фильтрация произойдёт по составу суда и резолютивке.
4. **Запуск пайплайна:**
   ```powershell
   python tools\judge_stats\judge_stats.py --insecure run --judge "Иванов И.И." --department <код_подразделения> --date-from 2025-01-01 --date-to 2026-06-30 --workdir "workflow\judge-ivanov-2025-2026"
   ```
   `--insecure` нужен из-за сертификата российского УЦ у cntd.ru (в запросах только публичные данные: ФИО судьи и период). Повторная классификация без перекачивания: подкоманды `classify` + `report` на том же `--workdir` (тексты кэшируются).
5. **Ручной разбор:** открыть `classification.csv`, просмотреть строки `ambiguous` / `unclassified` (и `composition_block_not_found`), для каждой предложить категорию с цитатой резолютивки. После правок юриста — поправить `classification.json` и перезапустить `report`.
6. **Интерпретация (high freedom, только здесь):** доля отмен по интересующей категории споров, примеры дел с номерами для цитирования по `references/citation-rules.md`. Не выдумывать дела и мотивы — только то, что есть в кэше текстов.

## Ограничения (обязательно указывать в отчёте)

- Покрыты **постановления** (апелляция/кассация). Решения судьи первой инстанции — другой тип документов, вне текущего скоупа.
- Зеркало cntd может содержать не все акты суда → занижение возможно; полнота корпуса не гарантируется.
- Роль в составе (председательствующий/член состава) определяется эвристикой — при использовании в документе перепроверить.
- Судья мог сменить фамилию в периоде — скрипт этого не знает.

## Маркеры

`[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]` — перед использованием цифр; `[ДАННЫЕ НЕПОЛНЫ]` — зеркало вернуло подозрительно мало актов за период; `[ИНСТРУМЕНТ НЕДОСТУПЕН]` — и KAD/RAS, и зеркало недоступны (работа останавливается, не выдумывать); `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]` — любые выводы о тактике на основе статистики.

## Связанные файлы

- `tools/judge_stats/judge_stats.py` — пайплайн (`selftest` — оффлайн-проверка классификатора, запускать после правок скрипта).
- `references/web-research-tools.md` — agent-browser/WebFetch для kad.arbitr.ru и sudrf.cntd.ru.
- `references/source-hierarchy.md` — статус зеркала как вспомогательного источника.
- `references/citation-rules.md` — как цитировать найденные дела.
