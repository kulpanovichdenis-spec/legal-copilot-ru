# Реестр типовых клауз договоров

Архитектурный паттерн: context-aware + domain-intelligence, Medium freedom — skill маршрутизирует запрос к карточке-клаузе в личном слое профиля; формулировки и правовые основания не дублируются в SKILL.md.

## Назначение

Подборка одобренных юристом формулировок отдельных условий договоров и дополнительных соглашений. Используется как **готовый материал для замены** проблемного условия в анализируемом договоре (`contract-review`) или как **сборник заготовок** при подготовке нового договора (`contract-drafter`) и при составлении ДС (`amendment-drafter`). Формулировки реестра **приоритетнее** формулировок из образцов (реестр выверен юристом, образцы — форма).

## Доступ через личный слой профиля (рабочий слой)

Клаузы лежат в `profile/knowledge/clauses/cards/<slug>.md`. Порядок:

1. **Найти подходящую клаузу** — выбрать `<slug>` по таблице-навигатору ниже (применимость), либо перечислить карточки через **Glob** `profile/knowledge/clauses/cards/*.md`. Полнотекстовый поиск по телу — `rg --no-ignore` через Bash (⚠️ карточки в `.gitignore`, поэтому обычный **Grep-инструмент их не видит** — использовать Glob+Read или `rg --no-ignore`).
2. **Открыть текст** — прочитать (**Read**) `profile/knowledge/clauses/cards/<slug>.md`. Тело карточки содержит готовую формулировку + строки «Применимо» и «Тактическая ценность».
3. **Адаптировать** под анализируемый/готовящийся договор (правила ниже) — дословно не подставлять.

`<slug>` совпадает со stem прежней карточки (напр. `12-fors-mazhor`, `01-edo`). **Профиля или карточки нет** → честно сообщить «в личном слое профиля нет клаузы этого типа», **не выдумывать** формулировку и не брать её из общего знания.

## Как пользоваться

> **Тексты клауз — из конкретных договоров. При предложении к замене их необходимо адаптировать под анализируемый договор: менять наименования сторон (как в анализируемом договоре), нумерацию пунктов и наименования работ / услуг / товаров (если применимо).**

Это правило автора реестра. Skill **не подставляет** клаузы дословно — обязательно адаптирует:

1. **Наименование сторон** — заменить «Заказчик / Исполнитель / Покупатель / Продавец / Поставщик / Подрядчик / Учреждение» на роли, применённые в анализируемом договоре.
2. **Нумерация пунктов** — пересобрать под структуру анализируемого договора (нумерация в реестре — из исходных договоров, не сквозная).
3. **Наименования предмета** — «Товар / Услуги / Работы / Продукция / Исследование / Мероприятие» — на терминологию анализируемого договора.
4. **Реквизиты и плейсхолдеры** — заполнить из анализируемого договора (адреса, контакты, email).
5. **Срок действия** в клаузе срока / автопролонгации — обновить дату на актуальную для готовящегося договора.
6. **Применимое право** — для двуязычных клауз сверить с юрисдикцией анализируемого договора.

При несоответствии терминологии — `[ПРОВЕРИТЬ ТЕРМИНОЛОГИЮ]`. При сомнениях в применимости клаузы — `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`.

## Проверка применимости перед предложением клаузы

Клаузы реестра применимы **не к любому договору**. Перед тем как предложить клаузу, сверить её поле `applies_to` (frontmatter карточки и указатель ниже) с типом готовящегося/анализируемого договора. Не предлагать клаузу, не подходящую по типу (например, HSE-допуски или сдача-приёмка работ — в чисто денежный договор поставки без работ). Если применимость под вопросом — не подставлять «на всякий случай», а отметить `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`.

## Клаузы, требующие сверки с первоисточником (не только адаптации)

Отдельные условия нельзя брать даже после адаптации — их формулировка должна сверяться с внешним первоисточником при каждой подготовке:

- **Арбитражная оговорка (институциональный арбитраж)** — точный текст берётся только из актуальной типовой (рекомендованной) оговорки на **официальном сайте соответствующего арбитражного института** (ICC, LCIA, SIAC, HKIAC, SCC, VIAC, МКАС при ТПП РФ и др.), не из образца/старого договора/по памяти. Правило постоянное (институты меняют редакцию); неточность делает оговорку патологической. Не сверено — `[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]` (источник — сайт арбитража). Подробнее — `references/contract-playbook.md` 2.10. Отдельной карточки арбитражной оговорки в реестре **нет намеренно**: статичный образец здесь противопоказан, текст всегда живой с сайта института.

- **Подряд / монтаж / пуско-наладка**: 7 (недостатки работ), 8 (HSE / допуски), 9 (сдача-приёмка), 10 (исключительные права при создании ИС).

- **Поставка нерегистрированных ЛС**: 15.
- **Договоры с переменной ценой**: 16 (индексация на ИПЦ).
- **Клинические исследования**: 19 (обязанности Учреждения).
- **Соглашения о конфиденциальности (NDA)**: 20–26 (полный двуязычный конструктор — преамбула/термины, обязательства, ответственность, исключения/срок, прочие положения, споры/язык/уведомления, контакты/подписи; развилка mutual / own_side_only внутри карточек 20–22). NDA — самостоятельный тип документа, а не точечная клауза для вставки в другой договор; карточки 20–26 собираются вместе, а не выбираются по одной.
