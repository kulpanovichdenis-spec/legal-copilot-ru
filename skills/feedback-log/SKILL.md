# Feedback Log

Архитектурный паттерн: context-aware, Medium freedom — модель классифицирует обратную связь, но записывает её только в установленную JSONL-схему пользовательского профиля.

## Назначение

Skill быстро фиксирует обратную связь юриста о работе legal-copilot в файл `profile/feedback/YYYY-MM.jsonl`. Эти записи — материал для доработки skills/templates/references.

Фидбэк живёт в пользовательском профиле (`profile/feedback/`): он переносится между машинами и переживает обновление; в общий git не попадает.

## Принципы

1. **Низкий порог.** Skill срабатывает на короткую фразу юриста — не требует заполнения форм.
2. **Structured JSONL.** Одна правка = одна строка JSON. Удобно парсить и группировать.
3. **Не редактирует продукт.** Skill только пишет в лог. Реальные правки skills/templates/references делаются отдельно.
4. **Привязка к контексту.** Если правка связана с конкретным skill/файлом/документом — фиксирует это явно.

## Когда использовать

- Юрист правит сгенерированный документ и хочет, чтобы шаблон в следующий раз был ближе к финальной версии.
- Юрист заметил, что skill использовал устаревшую норму или плохую формулировку.
- Юрист хочет предложить новый блок в reference или template.
- Юрист видит повторяющуюся ошибку в категории документов.

## Алгоритм работы

1. Распознать обращение юриста как feedback-сигнал.
2. Если в сообщении мало деталей — задать **не более 1-2** уточняющих вопросов (что именно skill сделал не так / какой документ / какой файл правился). Если деталей достаточно — не задавать ничего.
3. Собрать запись:
   - `date` — текущая дата в ISO (YYYY-MM-DD).
   - `time` — HH:MM.
   - `skill` — имя skill, к которому относится правка (если ясно). Иначе `null`.
   - `category` — одно из: `template-gap` (шаблон не покрыл случай), `wrong-norm` (устаревшая/неверная норма), `bad-wording` (плохая формулировка), `missing-reference` (нет нужного reference), `wrong-structure` (неверная структура документа), `idea` (предложение нового), `other`.
   - `severity` — `low` / `medium` / `high` (high = пошло бы в боевой документ с проблемой).
   - `text` — формулировка юриста, дословно, без перефраза.
   - `related_files` — список путей или идентификаторов (skills/contract-review/SKILL.md, slug клаузы из profile/knowledge/clauses/, файл образца из profile/knowledge/document-samples/ и т.п.). Пусто, если не указано.
   - `proposed_fix` — если юрист сразу предложил конкретную правку. Иначе `null`.
4. Определить целевой файл лога: `profile/feedback/YYYY-MM.jsonl` (год-месяц текущей даты). Если файла нет — создать.
5. Дописать одну строку JSON в конец файла. Использовать `ensure_ascii=False`, чтобы кириллица читалась.
6. Кратко подтвердить юристу: "Записал. Категория: X. Файл: profile/feedback/YYYY-MM.jsonl, запись #N." — без воды.

## Формат записи

Одна строка JSONL:

```json
{"date":"2026-06-03","time":"14:32","skill":"contract-review","category":"template-gap","severity":"medium","text":"шаблон не учёл валютную оговорку для договоров с нерезидентами","related_files":["skills/contract-review/SKILL.md","skills/clause-library/SKILL.md"],"proposed_fix":"добавить клаузу валютной оговорки в profile/knowledge/clauses/cards/ с триггером 'есть нерезидент в сторонах'"}
```

## Примеры обращений и реакций

**Пример 1 — есть всё:**
> "Запиши правку: contract-review снова забыл блок валютной оговорки для нерезидента. Это medium, надо в clause-library добавить."

→ Пишет запись напрямую, без вопросов. Подтверждает.

**Пример 2 — мало деталей:**
> "У меня замечание по последней генерации"

→ Уточняет: "По какому skill / документу? И в чём проблема?" — одним вопросом, не списком.

**Пример 3 — слитный текст:**
> "зафиксируй: gov-response в ответе на представление неправильно сослался на ст. 28.5 КоАП — там должна быть 29.5"

→ Распознаёт skill (`gov-response`), категорию (`wrong-norm`), severity (`high` — норма!), пишет. Подтверждает.

## Что писать в `related_files`

- Если юрист назвал файл — взять как есть.
- Если юрист сказал "шаблон X" — найти glob по `templates/`, добавить найденное.
- Если юрист сказал "skill Y" — добавить `skills/Y/SKILL.md`.
- Если правка про конкретный образец — добавить его путь из слоя `profile/knowledge/document-samples/` (например, `profile/knowledge/document-samples/cards/litigation/otzyv-9l.md`).
- Не выдумывать пути. Лучше пустой список, чем неверный.

## Технические детали

- Файл `profile/feedback/YYYY-MM.jsonl` — append-only.
- Кодировка UTF-8, БЕЗ BOM. На Windows при использовании PowerShell — обязательно `-Encoding utf8NoBOM` или через `Set-Content -Encoding utf8` (PS 5.1 пишет с BOM — использовать .NET `[System.IO.File]::AppendAllText` с `[System.Text.UTF8Encoding]::new($false)`).
- Перевод строки — `\n` (LF), чтобы парсер на любой платформе ел.
- Каталог `profile/feedback/` уже существует. Если нет — создать.
