# Россия (RU) — адаптер проверки контрагента

Назначение: country-адаптер для российского ЮЛ/ИП, выбираемый country-router'ом `SKILL.md` на шаге COUNTRY ROUTER (`skills/counterparty-verification/SKILL.md`). Это единственный **глубокий** адаптер первой версии skill'а (§30 ТЗ, acceptance-тест — на российском ЮЛ); остальные юрисдикции — тонкие стабы (`skills/counterparty-verification/countries/CN.md`, `US.md`, `EU.md`, `KR.md`, `OTHER.md`).

Формат файла — общий для всех country-адаптеров: **Официальные реестры → Что извлечь → Специфические red flags → Границы/ограничения**. Общая методология (evidence-first, FACT/ANALYSIS/RISK/RECOMMENDATION, дозапрос) и risk-engine — не здесь: `skills/counterparty-verification/references/methodology.md`, `skills/counterparty-verification/references/risk-rules.md`. Проверка полномочий подписанта — отдельный sub-workflow `skills/counterparty-verification/references/authority-check.md` (не дублируется в этом файле). Санкционная проверка — `skills/counterparty-verification/references/sanctions-check.md` (раздел 4).

## 2. Что извлечь

### 2.1 Реестр — ЕГРЮЛ/DaData (§8 ТЗ)

Registry-шаг **не переизобретается** в этом файле — используется существующий пайплайн: `mcp__legal-overlay__dadata_party(ИНН)` → `tools/counterparty_verification/registry_extract.py` (`extract(dadata_response)`). Актуальную выписку ЕГРЮЛ (PDF/скриншот) сохранить в `01_Реестр/` с именем по `tools/counterparty_verification/case_folder.py` (`file_name(name, date, doc_type, ext)`).

Поля, подлежащие проверке по §8 ТЗ:

- статус ЮЛ (действующий / в процессе ликвидации / ликвидирован / реорганизуется / банкрот);
- дата регистрации;
- ОГРН, ИНН, КПП;
- юридический адрес и признак его недостоверности;
- сведения о ЕИО (ФИО, должность, признак недостоверности);
- участники/учредители (доли, признак недостоверности);
- размер уставного капитала;
- ОКВЭД (основной и дополнительные);
- лицензии (если отражены в выписке/DaData);
- сведения о филиалах/представительствах;
- сведения о реорганизации (если проводилась/проводится);
- сведения о ликвидации / предстоящем исключении из ЕГРЮЛ как недействующего лица (сверка — `vestnik-gosreg.ru`, раздел 1);
- признаки недостоверности (адрес/ЕИО/участник) по данным ФНС;
- последние изменения в реестре (дата и характер последнего изменения — особенно значимо, если изменение произошло незадолго до сделки, см. §9).

`tools/counterparty_verification/registry_extract.py` нормализует базовый набор этих полей в `card` (наименование, ИНН/КПП/ОГРН, статус, дата регистрации, возраст, адрес, ЕИО, капитал, ОКВЭД, филиалы, категория МСП) и считает объективные red-flag флаги — см. раздел 3. Поля, которые скрипт не нормализует в `card` напрямую (состав участников/учредителей, лицензии, факт реорганизации, история изменений) — берутся из полного ответа DaData/сохранённой выписки ЕГРЮЛ и оцениваются вручную по тексту документа; парсинг этих полей не переизобретается здесь — при необходимости расширения нормализации это доработка `registry_extract.py`, а не текст этого файла.

При недоступности DaData (`[DADATA НЕДОСТУПНА]`) или отсутствии результата (`[DADATA НЕ НАЙДЕНО]`) — fallback на `egrul.nalog.ru` через agent-browser (`references/web-research-tools.md`, раздел 3.3).

**Лист записи ≠ выписка.** Предоставленный контрагентом «Лист записи ЕГРЮЛ» (тем более о создании ЮЛ) фиксирует конкретное событие на свою дату и быстро устаревает (может не отражать текущие состав участников, адрес, размер УК, ЕИО). Для актуального состояния — **самостоятельно получить свежую выписку** с `egrul.nalog.ru` и **сохранить PDF в `01_Реестр/`**; расхождения листа записи с текущей выпиской — отметить. Не выдавать лист записи за текущую выписку и не заменять его молча данными агрегатора: агрегатор (checko, rusprofile, zachestnyibiznes и т. п.) — навигационный лид для быстрой ориентации, официальное подтверждение — свежая выписка.

### 2.2 Финансы (§11 ТЗ)

Показатели: выручка, прибыль (убыток), активы, обязательства, чистые активы, динамика, налоговая задолженность/недоимка, факт непредставления отчётности, признаки прекращения деятельности. Норму и точную формулировку признаков проверять через `route_norm_verification(jurisdiction="RU", probe=true)` и `usable_now: true`, не постулировать по памяти.

Источники: официальная бухгалтерская отчётность — ФНС ГИР БО (`bo.nalog.ru`, раздел 1); налоговая задолженность/непредставление отчётности — «Прозрачный бизнес» (`pb.nalog.ru`); капитал — уже в карточке реестра (раздел 2.1).

Малая прибыль, минимальный уставный капитал или убыток **сами по себе не создают high risk** — оцениваются в связке с параметрами сделки (сумма, аванс, отсрочка, длительность отношений — `skills/counterparty-verification/references/risk-rules.md`, раздел 3 «Transaction-weighted»). Материалы — в `03_Финансы/`.

### 2.3 Суды — Картотека арбитражных дел (§12 ТЗ)

Источник — `kad.arbitr.ru`. Глубина поиска — **не менее 3 лет** до даты проверки; значимые более ранние дела (крупные суммы, банкротные/корпоративные споры) — учитывать шире трёхлетнего окна, если они всё ещё релевантны (например, дело не завершено или напрямую связано с текущим финансовым состоянием контрагента).

По каждому релевантному делу фиксировать: роль контрагента (истец/ответчик/третье лицо), предмет и сумму иска, исход (в пользу контрагента / против контрагента / прекращено / на рассмотрении), категорию (банкротное, корпоративное, налоговое, о взыскании задолженности, об интеллектуальной собственности и т. п.).

Отдельно — **динамика за последние 6–12 месяцев**: рост числа исков против контрагента, рост сумм требований, появление новых категорий споров (например, первые налоговые/банкротные дела там, где их раньше не было) — это самостоятельный сигнал, отдельный от общего количества дел.

Материалы — в `04_Суды/`. Большое число дел **не является автоматическим негативом** (см. red flags, раздел 3, и анти-паттерн в `skills/counterparty-verification/references/risk-rules.md`, раздел 5) — оценивается роль/предмет/исход/динамика, а не голое количество.

### 2.4 Банкротство / Федресурс (§13 ТЗ)

Источники: ЕФРСБ/Федресурс (`bankrot.fedresurs.ru`), дополнительно — банкротные дела на `kad.arbitr.ru` (раздел 2.3). Проверяются не только уже открытые процедуры банкротства, но и **предбанкротные сигналы**:

- сообщения о намерении кредитора или самого должника обратиться с заявлением о банкротстве;
- сообщения должника (о снижении стоимости чистых активов, о существенных фактах хозяйственной деятельности);
- начатые, но ещё не завершённые процедуры (наблюдение, финансовое оздоровление, внешнее управление, конкурсное производство);
- существенные факты, публикуемые на Федресурсе (залоги имущества, изменение уставного капитала, приостановление операций и т. п.), если они указывают на ухудшение финансового состояния.

Материалы — в `05_Банкротство_Федресурс/`. Возбуждённое дело о банкротстве — как правило блокирующий фактор при длящихся отношениях (`skills/counterparty-verification/references/risk-rules.md`, раздел 4, пример RED); предбанкротные сигналы без возбуждённого дела оцениваются по совокупности, не автоматически как RED.

### 2.5 Исполнительные производства — ФССП (§14 ТЗ)

Источник — Банк данных исполнительных производств ФССП (`fssp.gov.ru/iss/ip`). Извлекается: наличие открытых исполнительных производств, сумма задолженности, категория взыскания (налоги, гражданско-правовые долги, штрафы и т. п.), давность.

**Правило (жёсткое, из hard gates `SKILL.md`): сначала попытаться, обход защиты запрещён.** Банк данных ФССП часто защищён CAPTCHA, но «CAPTCHA» не презюмируется — источник сначала **реально открывается**; обход CAPTCHA (и любой иной защиты) **запрещён** — автоматизированный проход формы не предпринимается никаким инструментом (agent-browser в т. ч.). Действие при незавершённости:

1. статус строки «ФССП» в таблице проверки — `⚪ MANUAL CHECK REQUIRED`, а не `N/A` и не «риска нет»;
2. в раздел «Ограничения проверки» отчёта — внести **фактическую** причину незавершённости (сработала CAPTCHA / инструмент/браузер недоступен в сессии / сайт не отвечает), а не предполагаемую, и что требуется ручная проверка на `fssp.gov.ru/iss/ip`;
3. если юрист впоследствии проводит проверку вручную и передаёт результат — он добавляется в досье (`06_Исполнительные_производства/`) и в отчёт как обычный источник (дата ручной проверки указывается);
4. непроведённая проверка ФССП — это **ограничение процесса**, а не риск контрагента: в «Выявленные риски» не выносится.

Материалы — в `06_Исполнительные_производства/`.

### 2.6 Лицензии / регуляторика (§15 ТЗ)

Проверка **контекстная** — не выполняется по умолчанию для любой сделки, а только когда предмет сделки требует лицензии, разрешения, аккредитации или иной регистрации (например, поставка лекарственных средств — лицензия на фармацевтическую деятельность; строительные работы — членство в СРО; охранная деятельность — лицензия на частную охранную деятельность). Шаги:

1. определить по предмету сделки, требуется ли лицензия/разрешение/аккредитация/регистрация; неочевидное правовое основание проверить через `route_norm_verification(jurisdiction="RU", probe=true)` и `usable_now: true`, не постулировать;
2. найти официальный реестр конкретного регулятора (например, Росздравнадзор — реестр лицензий на фармацевтическую деятельность/производство ЛС, ФСТЭК/ФСБ — для деятельности, связанной с гостайной/шифрованием, СРО — реестр членов);
3. проверить наличие, статус (действует/приостановлена/аннулирована), срок действия и соответствие вида лицензии предмету конкретной сделки (лицензия на один вид деятельности не покрывает другой);
4. дополнительно — Реестр недобросовестных поставщиков (РНП, `zakupki.gov.ru`, раздел 1), если сделка связана с закупками/госконтрактами.

Материалы — в `08_Лицензии_Регуляторика/`. Если лицензия предмету сделки не требуется — строка таблицы отчёта помечается `N/A`, а не пропускается молча.

## 3. Специфические red flags (§9 ТЗ)

Полный список факторов, которые проверяются в ходе RU-адаптера (детерминированная часть — статус/возраст/капитал — уже флагуется `tools/counterparty_verification/registry_extract.py`; остальное определяется вручную по источникам разделов 2.1–2.6):

- ликвидация — статус `LIQUIDATING`/`LIQUIDATED` в ЕГРЮЛ, решение о ликвидации принято;
- реорганизация (слияние, присоединение, разделение, выделение, преобразование) — в процессе или недавно завершена;
- предстоящее исключение из ЕГРЮЛ как недействующего юридического лица (`vestnik-gosreg.ru`);
- недостоверность сведений об адресе;
- недостоверность сведений о ЕИО;
- недостоверность сведений об участнике;
- признак массового адреса (адрес зарегистрирован для множества юридических лиц);
- признак массового руководителя (то же лицо — ЕИО во множестве юридических лиц);
- дисквалификация действующего ЕИО;
- иные ограничения (например, ограничение на регистрационные действия, наложенное регистрирующим органом);
- частая смена ЕИО за короткий период;
- частая смена участников/учредителей за короткий период;
- частая смена юридического адреса за короткий период;
- недавнее создание компании (молодая компания — детерминированный флаг `young_company` в `registry_extract.py`, порог см. в самом скрипте);
- изменения в реестре (ЕИО, адрес, участники), произошедшие незадолго до даты сделки — отдельно значимый сигнал независимо от прочих флагов.

**Red flag ≠ автоматический отказ.** Каждый выявленный флаг оценивается по методологии `skills/counterparty-verification/references/methodology.md` (FACT → ANALYSIS → RISK → RECOMMENDATION) и складывается в итоговый вердикт по правилам совокупности и transaction-weighting `skills/counterparty-verification/references/risk-rules.md` — не автоматическим маппингом «флаг → RED».

## 4. Санкции — маршрутизация

Санкционная проверка контрагента, его ЕИО, участников и (если идентифицированы) бенефициаров ведётся по единой методологии `skills/counterparty-verification/references/sanctions-check.md` (минимальный набор перечней — OFAC, EU, UK, применимые российские перечни Росфинмониторинга) — этот файл её не дублирует. Материалы — в `07_Санкции/`.

## 5. Границы / ограничения

- **CAPTCHA на ФССП не обходится** — раздел 2.5. Это правило, а не рекомендация; исключений по срочности сделки нет.
- **«Не найдено» ≠ «риска нет»** и **«недоступно» ≠ «риска нет»** — общее правило fault tolerance (`skills/counterparty-verification/references/methodology.md`, раздел 5) применяется к каждому источнику этого адаптера: если КАД/Федресурс/ФССП/ГИР БО технически не отвечают на момент проверки — статус строки отчёта отражает именно недоступность источника, а не отсутствие риска.
- **Платный/ограниченный доступ.** Отдельные сведения (например, расширенная аналитика по некоторым коммерческим агрегаторам) могут требовать платной подписки — при отсутствии доступа это отмечается как ограничение, официальный бесплатный источник (разделы 1–2) не заменяется платным агрегатором молча.
- **Динамика требует даты предыдущей проверки.** Раздел 2.3 (динамика 6–12 мес.) и recheck/compare (§25 ТЗ, `skills/counterparty-verification/SKILL.md`) технически возможны только при наличии более раннего досье или зафиксированной даты предыдущего среза; без неё динамика не выводится, а фиксируется срез на текущую дату.
- Правовое основание для контекстных требований не выводится по памяти модели: выполнить discovery, затем `route_norm_verification(jurisdiction="RU", probe=true)` и раскрыть норму у provider с `usable_now: true`; при отсутствии подтверждения — `[ПРОВЕРИТЬ НОРМУ]`.
