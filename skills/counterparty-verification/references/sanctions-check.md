# Проверка по санкционным перечням

Назначение: методология санкционной проверки контрагента внутри `counterparty-verification`. Вызывается основным workflow (`skills/counterparty-verification/SKILL.md`, шаг SANCTIONS) после регистрового и корпоративного блока проверки. Материалы этой проверки (скриншоты/выгрузки поиска по перечням, зафиксированный статус проверки) сохраняются в подпапку досье `07_Санкции/` (см. `SUBFOLDERS["sanctions"]` в `tools/counterparty_verification/case_folder.py`).

## 1. Минимальный набор перечней

Для любой проверки — независимо от страны контрагента — проверяется минимум:

| Перечень | Официальный источник |
|---|---|
| **OFAC SDN и консолидированный список (США)** | https://sanctionssearch.ofac.treas.gov/ (поиск), https://ofac.treasury.gov/sanctions-list-service (списки целиком) |
| **EU — консолидированный санкционный список** | https://webgate.ec.europa.eu/fsd/fsf/index.html (Financial Sanctions Database), справочно — https://www.sanctionsmap.eu/ |
| **UK — OFSI Consolidated List** | https://www.gov.uk/government/publications/financial-sanctions-consolidated-list-of-targets |
| **Применимые российские перечни** | Росфинмониторинг — перечень организаций и физических лиц, причастных к экстремизму/терроризму и к финансированию распространения оружия массового уничтожения: http://www.fedsfm.ru/ (раздел «Перечни») |

Плюс — **иные перечни по сделке/стране**, если применимо: отраслевые ограничительные меры (экспортный контроль, секторальные санкции конкретной юрисдикции — например, BIS Entity List США при поставках технологий), санкционные перечни третьих стран, если контрагент или сделка имеют связь с их юрисдикцией (например, платежи в валюте этой страны, контрагент зарегистрирован там же).

URL и наборы перечней меняются (появляются новые режимы, обновляются домены) — при работе сверять текущий адрес непосредственно на сайте органа; если официальный адрес не открывается или изменился, это отмечается как ограничение проверки (`skills/counterparty-verification/references/methodology.md`, раздел «Fault tolerance»), а не молчаливо пропускается.

## 2. Кого проверять

Проверка по каждому перечню проводится не только по названию юридического лица, а по всему кругу связанных с ним лиц:

- юридическое лицо — контрагент (полное и сокращённое наименование);
- **альтернативные наименования** — прежние наименования (после переименования/реорганизации), написание на других языках, распространённые сокращения;
- ЕИО и члены органов управления (directors) — по данным, полученным на шаге проверки полномочий (`skills/counterparty-verification/references/authority-check.md`);
- участники/акционеры (собственники), включая данные из ЕГРЮЛ, если они раскрыты;
- **конечные бенефициарные владельцы (UBO)**, если идентифицированы (по декларации контрагента, дозапросу или открытым источникам) — при значимости сделки идентификация UBO может входить в список дозапроса (`skills/counterparty-verification/references/methodology.md`, раздел 6).

Отсутствие данных об UBO само по себе — не санкционный риск, но ограничивает полноту проверки и отражается в разделе «Ограничения проверки» отчёта.

## 3. Совпадение имени ≠ санкционное лицо

Ключевое правило раздела. Поисковые системы санкционных перечней находят совпадения по строке — это **не** означает, что найденное лицо в перечне и проверяемый контрагент (или связанное с ним физлицо) — один и тот же субъект. Особенно часто ложные совпадения дают:

- распространённые ФИО (директор с обычным именем/фамилией);
- частично совпадающие названия компаний из разных стран;
- совпадения по транслитерации, не подтверждённые дополнительными идентификаторами (дата рождения, гражданство, регистрационный номер).

Действие при любом текстовом совпадении, которое не подкреплено совпадением дополнительных идентифицирующих признаков (дата рождения, паспортные данные, адрес, регистрационный номер компании) — присваивать статус:

```
POTENTIAL MATCH / MANUAL REVIEW REQUIRED
```

Это **не** равнозначно выводу «контрагент под санкциями» и не равнозначно выводу «риска нет» — это статус, требующий предметной ручной проверки (сверка дополнительных идентификаторов записи в перечне против данных контрагента) прежде, чем можно сформулировать окончательный вывод. Прямой санкционный вывод («контрагент находится под санкциями») допустим только после того, как совпадение подтверждено по дополнительным идентифицирующим признакам, а не по одному лишь названию/ФИО.

Итоговая формулировка в отчёте (`skills/counterparty-verification/references/report-rules.md`) при непроверенном совпадении:

```
FACT: по поисковому запросу «[наименование/ФИО]» в [перечень] обнаружена
запись с совпадающим/близким названием (запись [идентификатор записи в
перечне], источник: [официальный URL], дата проверки [дата]).

ANALYSIS: дополнительные идентифицирующие признаки (дата рождения /
регистрационный номер / адрес) в найденной записи [совпадают частично /
не совпадают / не позволяют сделать вывод] с данными проверяемого лица.

RISK: ⚪ POTENTIAL MATCH / MANUAL REVIEW REQUIRED — совпадение по названию/
ФИО не подтверждено по дополнительным идентификаторам, окончательный вывод
не может быть сделан автоматически.

RECOMMENDATION: ручная сверка (дата рождения, гражданство, полный
регистрационный номер) перед продолжением сделки; при сохранении
неопределённости — [СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА] / [ВОПРОС БИЗНЕСУ].
```

## 4. Что запрещено

- Выдавать вывод о санкционном статусе по одному совпадению названия/ФИО без сверки дополнительных идентификаторов.
- Пропускать проверку UBO/директоров, ограничиваясь только юридическим лицом, если данные о них доступны.
- Формулировать «санкций не выявлено» на основании проверки только части применимого минимального набора перечней (раздел 1) без указания, какие перечни не проверялись и почему.
- Использовать неофициальный агрегатор как единственный источник санкционного статуса — официальные URL перечней (раздел 1) обязательны; агрегатор допустим только как навигационная подсказка перед проверкой на официальном источнике (тот же принцип иерархии, что в `skills/counterparty-verification/references/methodology.md`, раздел 4).

## Связанные файлы

- `skills/counterparty-verification/references/methodology.md` — общая методология, evidence-first, дозапрос (в т. ч. UBO).
- `skills/counterparty-verification/references/authority-check.md` — источник данных о ЕИО/директорах для санкционной сверки.
- `skills/counterparty-verification/references/risk-rules.md` — как `POTENTIAL MATCH` и подтверждённое санкционное совпадение влияют на вердикт (подтверждённое совпадение — блокирующий фактор, RED).
- `skills/counterparty-verification/references/report-rules.md` — оформление раздела «Источники» и строки «Санкции» таблицы проверки.
- `references/web-research-tools.md` — общий слой веб-инструментов (agent-browser/Tavily/WebFetch) для поиска по перечням, если требуется автоматизированный проход формы.
- `references/citation-rules.md` — маркер `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]` при сохраняющейся неопределённости.
- `tools/counterparty_verification/case_folder.py` — подпапка `07_Санкции/` (`SUBFOLDERS["sanctions"]`).
