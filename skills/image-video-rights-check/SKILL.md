# Image/Video Rights Check

Архитектурный паттерн: **sequential + domain-intelligence** (registry-navigator → verification-first). Модель классифицирует материал (сток/AI-generated/агрегатор), ищет сервис в `references/media-sources-legal-registry.yaml`, обязательно открывает официальный источник и делает юридический вывод по чек-листу `references/media-rights-methodology.md`; детерминированного расчёта в этом skill нет.

## Назначение

Skill готовит черновик заключения о том, можно ли использовать конкретную фотографию, иллюстрацию, векторную графику или видео в конкретном бизнес-сценарии — материал куплен на фотостоке/видеостоке, сгенерирован AI-сервисом, создан через reference image/video или получен через платформу-агрегатор стороннего AI (HeyGen→Kling, Adobe→Veo и т. п.). Вопрос всегда о конкретном asset, не о сервисе вообще: один provider может иметь разные условия для разных продуктов/функций/моделей, тарифов, каналов доступа и дат получения материала — общая формулировка «сервис X разрешает коммерческое использование» ведёт к ошибке.

Это буквальное применение **MVP-риска №1** из CLAUDE.md («ГЛАВНОЕ ПРАВИЛО»: не начинать ответ с общего знания). Вывод о правах на изображение/видео нельзя строить на общем впечатлении о том, «как обычно работают» стоки и AI-сервисы — только на факте, что применимый официальный документ (Terms of Service / License / AI Terms) **открыт и прочитан** в этой сессии на дату, актуальную для конкретного материала.

Skill не заменяет анализ охраноспособности AI-сгенерированного результата как самостоятельного правового вопроса (это отдельное «заключение по вопросу», см. `references/source-hierarchy.md` → жанр legal-opinion) и не покрывает договоры об отчуждении/лицензировании прав между компаниями — там работает `skills/contract-review/SKILL.md`.

## Что готовит skill

1. Intake-факты по конкретному материалу (provider, product/feature, asset URL/ID, underlying AI model, access channel, тариф, дата получения, user, intended use, territory);
2. Роутинг материала — сток / AI-generated / платформа-агрегатор;
3. Результат поиска сервиса в `references/media-sources-legal-registry.yaml`;
4. Факт открытия и прочтения официального источника (Terms/License/AI Terms), действовавшего на дату получения материала;
5. Юридический вывод по чек-листу методички — commercial use по способам использования, attribution, AI disclosure/provenance, права третьих лиц, применимые нормы РФ;
6. `.docx`-отчёт в `workflow/` по каноническому формату методички (профиль «Аналитическая заметка»);
7. Заметку юристу — что проверено / не проверено / маркеры / стратегические и бизнес-развилки.

## Принципы

1. Verification-first — обязательно открыть официальный источник по ссылке из реестра, не отвечать по памяти LLM (MVP-риск №1, CLAUDE.md).
2. Реестр `references/media-sources-legal-registry.yaml` — навигация, не заключение; окончательный вывод — только после открытия текущей редакции источника.
3. Методология — строго по `references/media-rights-methodology.md` (единый источник истины, не дублировать).
4. Attribution и AI disclosure/provenance — разные вопросы, проверяются и указываются отдельно.
5. Права на Output ≠ права на Input; лицензия сервиса ≠ очистка прав третьих лиц (person/ТЗ/логотип и т. п.) — cross-link `references/pd-playbook-cards/S13_photos_video_publication.md` / `references/pd-playbook-cards/S27_minors.md` при узнаваемом человеке/несовершеннолетнем.
6. Никакой категоричности сверх того, что подтверждено источником; юрист утверждает финал (human review).
7. Результат — `.docx` в `workflow/` (профиль «Аналитическая заметка»), маркеры неполноты обязательны при неопределённости.

## Когда использовать

Триггеры:
- «можно ли использовать это изображение/видео», «чисто ли по правам это фото/видео»;
- «нужна ли атрибуция», «как правильно указать источник/автора»;
- «чьи права на AI-generated контент», «кому принадлежит сгенерированное изображение»;
- «можно ли убрать watermark», «нужно ли раскрывать, что контент сделан ИИ»;
- «можно ли использовать в рекламе/на упаковке/как товарный знак/как мерч» — применительно к конкретному купленному/сгенерированному материалу;
- материал получен через reference image/video (пользователь загрузил чужое фото как Input в AI-генератор);
- материал получен через платформу-агрегатор стороннего AI (HeyGen→Kling, Adobe Firefly Generate Video→Runway/Kling/Luma, Canva Magic Media и т. п.);
- истёк / сменился тариф подписки на сток/AI-сервис, и нужно понять, что это меняет для уже полученных ранее материалов.

## Когда не использовать

- Договоры об отчуждении/лицензировании товарного знака или прав между юрлицами (там — `skills/contract-review/SKILL.md`, реестр клауз «Исключительные права» через `skills/clause-library/SKILL.md`);
- Судебный спор о нарушении авторских прав на изображение/видео (там — `skills/procedural-document-drafter/SKILL.md`);
- Вопрос об охраноспособности AI-output как таковой, вне контекста конкретного материала и его использования (отдельное «заключение по вопросу» — `skills/legal-opinion/SKILL.md` по циклу `references/source-hierarchy.md`);
- Реклама, где права на материал уже подтверждены, а вопрос — в содержании самого креатива (сравнения, гарантии, образ врача и т. п.) — основной skill `skills/fas-ad-practice-search/SKILL.md` / `references/ad-creative-playbook.md`; этот skill подключается только к вопросу прав на сам материал, не к содержанию рекламы.

## Алгоритм работы

**Прогрессивный поиск прошлого опыта (в начале, как в `skills/trademark-search/SKILL.md` Шаг 1).** Если тот же asset/сервис/дело уже проверялись — дёшево и послойно проверить `workflow/`: имена папок → frontmatter `case-context.md` найденных дел → при совпадении прочитать `case-context.md`. Одна строка юристу о связи с прошлым делом. Опыт ≠ правовое основание — право проверяется заново.

1. **Intake** — собрать обязательные факты по конкретному asset (см. раздел «Intake» `media-rights-methodology.md`). При недостатке вводных — точные вопросы юристу, не предположения.
2. **Реестр** — найти provider/продукт в `references/media-sources-legal-registry.yaml`; записи нет → раздел «Процедура для сервиса не из реестра» методички.
3. **Роутинг** — сток / AI-generated / агрегатор, по разделам «Алгоритм: сток», «Алгоритм: AI-generated», «Платформы-агрегаторы» методички (у агрегатора условия платформы проверяются отдельно от условий underlying-модели).
4. **Официальный источник** — открыть актуальную на дату получения материала редакцию, по приоритету из раздела «Работа с официальными источниками»; ссылка реестра не работает — искать новый официальный документ на том же домене, не считать документ отсутствующим.
5. **Commercial use** — по каждому способу использования отдельно (раздел «Commercial use — детализация»), не единым статусом да/нет.
6. **Attribution и AI disclosure/provenance** — два отдельных статуса и блока (разделы «Attribution», «AI disclosure и provenance»); `not_identified` не подменяется на `not_required`.
7. **Права третьих лиц и editorial-статус** — чек-лист Input rights/третьих лиц и проверка editorial-ограничения (разделы «Input rights и права третьих лиц», «Editorial content»).
8. **Применимое законодательство РФ** — реклама, ПДн, несовершеннолетние, deepfake/likeness, законодательная маркировка AI-контента (раздел «Применимое законодательство»); при прямом вопросе об охраноспособности AI-output — отдельно (раздел «Охраноспособность AI-output»).
9. **Вывод и отчёт** — сборка `.docx` по разделу «Канонический формат отчёта» методички.
10. **Заметка юристу и close-out** — что проверено/не проверено, маркеры, `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`/`[ВОПРОС БИЗНЕСУ]`; сохранив `.docx` в `workflow/<дело>/` — завести/обновить там `case-context.md`, если работа по продолжающемуся делу (правило CLAUDE.md «Контекст дела»).

## Hard gates

1. Не отвечать по памяти LLM — обязательно открыть официальный источник (MVP-риск №1, CLAUDE.md).
2. Search-сниппет — не основание вывода; нужна открытая карточка/страница.
3. «Commercial use allowed» в маркетинговой формулировке — не полноценный анализ; маркетинговая страница не имеет приоритета над договорными условиями.
4. Отсутствие найденного требования атрибуции ≠ доказательство, что она не нужна → `not_identified`, не `not_required`.
5. Текущая редакция Terms не применяется автоматически к материалу, полученному раньше, без проверки даты.
6. Агрегатор: условия платформы не заменяют автоматически условия underlying-модели.
7. Права на Output ≠ права на Input; наличие лицензии сервиса ≠ очистка прав третьих лиц.
8. Human review — весь вывод черновик, юрист утверждает.
9. Никаких выдуманных URL, номеров редакций, дат вступления в силу.

## Обязательная структура ответа

Каноническая структура отчёта — **единственный источник**, раздел «Канонический формат отчёта» `references/media-rights-methodology.md` (не дублируется здесь второй раз).

Отчёт сохраняется как **`.docx` в `workflow/`** (в worktree-сессии — в основную `workflow/` по абсолютному пути, не в копию worktree). Если есть релевантная папка дела `workflow/<дело>/` — сохранять туда.

**Close-out.** Сохранив `.docx`, если работа велась по продолжающемуся делу/контрагенту — завести или обновить `workflow/<дело>/case-context.md` (шаблон `templates/agent-notes/case-context-template.md`): что проверено, итоговый статус (можно/можно при условиях/нельзя/недостаточно данных), открытые вопросы. Разовая проверка вне дела — необязательно.

## Маркеры

Четыре новых доменных маркера (определены в `references/media-rights-methodology.md`, раздел «Маркеры»):

- `[АТРИБУЦИЯ НЕ УСТАНОВЛЕНА]` — статус `not_identified`: источник прочитан, но вопрос атрибуции в нём не поднят.
- `[ИСТОРИЧЕСКАЯ РЕДАКЦИЯ НЕ НАЙДЕНА]` — дата получения материала существенна, но архивную редакцию Terms/License на эту дату найти не удалось.
- `[ТАРИФ/ДАТА НЕ ПОДТВЕРЖДЕНЫ]` — условия зависят от тарифа/даты (`tariff_dependent`/`date_dependent` в реестре), но конкретное значение не установлено из фактов юриста.
- `[РЕЕСТР ТРЕБУЕТ ПОПОЛНЕНИЯ]` — сервиса нет в `references/media-sources-legal-registry.yaml`.

Общий реестр маркеров неполноты (`[ПРОВЕРИТЬ ИСТОЧНИК]`, `[СВЕРИТЬ С ПЕРВОИСТОЧНИКОМ]`, `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ РЕДАКЦИИ]`, `[ПРОВЕРИТЬ ФАКТ]`, `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`, `[ВОПРОС БИЗНЕСУ]`, `[ИНСТРУМЕНТ НЕДОСТУПЕН]` и др.) — `references/citation-rules.md`, раздел «Реестр маркеров неполноты».

## Связанные файлы

- `references/media-rights-methodology.md` — единый источник истины: intake, оба алгоритма (сток/AI-generated), агрегаторы, commercial use, attribution/AI disclosure, третьи лица, законодательный слой, канонический формат отчёта, маркеры.
- `references/media-sources-legal-registry.yaml` — навигационный реестр сервисов, к которому применяется методология.
- `references/web-research-tools.md` — общий слой веб-инструментов для открытия официальных источников.
- `references/risk-scale.md` — шкала рисков для `[ВОПРОС БИЗНЕСУ]` и оценки последствий неполной проверки.
- `references/citation-rules.md` — базовый реестр маркеров неполноты и правила цитирования.
- `references/confidentiality-rules.md` — обращение с данными при проверке условий provider.
- `references/document-formatting.md` — профиль «Аналитическая заметка» (`NoteDoc`) для оформления отчёта.
- `references/docx-generation.md` — техника сборки `.docx`-отчёта.
- `references/ad-creative-playbook.md` — точка входа для проверки норм о рекламе (раздел «Применимое законодательство» методички).
- `references/personal-data-playbook.md` — точка входа для вопросов персональных данных в материале.
- `skills/contract-review/SKILL.md` — для анализа договоров об отчуждении/лицензировании прав.
- `skills/fas-ad-practice-search/SKILL.md` — для анализа содержания рекламного креатива (после того как права на материал подтверждены).
