# FAS Ad Practice Search

Архитектурный паттерн: sequential + provider-neutral MCP + domain-intelligence, High freedom — Overlay выбирает provider и фиксирует fallback, а модель отбирает практику и формирует юридическую оценку по методике.

## Назначение

Skill готовит **аналитический материал и черновики** по вопросам соответствия рекламы требованиям ФЗ от 13.03.2006 № 38-ФЗ «О рекламе» с опорой на практику ФАС.

Основные сценарии:
- **Pre-flight проверка креатива** — до публикации;
- **Memo бизнесу** о рисковых формулировках с рекомендациями;
- **Обоснование позиции** для ответа на запрос ФАС в рамках КНМ;
- **Подбор практики** для процессуальных документов по делу об АП по ст. 14.3 КоАП;
- **Подбор контр-практики** для критики собственной позиции.

**Источник данных** — provider-neutral инструменты локального Legal Overlay: `search_fas_ad_practice`, `get_fas_case`, `list_fas_filter_options`. Skill не знает URL, transport и provider-native JSON-RPC. Overlay сам выбирает provider и при необходимости явно возвращает `DEGRADED` + provenance fallback. Поисковый корпус производный: ключевые реквизиты и ссылки сверять с официальной публикацией ФАС.

## Что готовит skill

1. Квалификация запроса (категория продукта / канал / спорные формулировки / применимые нормы);
2. План поисковых гипотез (2-4 варианта запроса);
3. Поиск через `search_fas_ad_practice` (при необходимости `list_fas_filter_options`);
4. Отбор релевантных дел (3-7 из выдачи);
5. Раскрытие полных карточек (`get_fas_case`) для топ-кандидатов;
6. Анализ: что ФАС считала нарушением, ключевые факты, риски;
7. Совокупная оценка риска;
8. **Один из черновиков** (в зависимости от сценария):
   - memo бизнесу;
   - блок IRAC для ответа ФАС;
   - аргументационный раздел для процессуального документа;
   - правки текста креатива;
9. Заметка юристу с маркерами неопределённости.

## Принципы

1. Источники, поиск НПА, полный текст и проверка связей — строго по `references/source-hierarchy.md`, раздел «Рабочий цикл», **до формирования правовой позиции**. Для provider-neutral поиска использовать `legal_search`; для дословной нормы — раскрыть и сверить официальный текст. Telegram-позиции, opinions, comments — навигация и контекст, не источник права.
2. Методология — строго по `references/fas-ad-practice-methodology.md`; практику искать через provider-neutral FAS tools Overlay. Не выдумывать docId, даты и нарушителей; поисковую карточку не выдавать за официальный первоисточник.
3. Выполнить минимум 2–4 поисковых запроса с разными гипотезами; вывод по одному поиску недопустим.
4. Отделять актуальную практику от устаревшей: для дел старше двух лет ставить `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ ПРАКТИКИ]`; фиксировать регион УФАС и не экстраполировать его подход на всю РФ без оговорки.
5. Не давать категоричный вывод «можно»: финальное решение принимает юрист.
6. Аргументационные блоки строить по `references/irac-rules.md`, нормы цитировать по `references/citation-rules.md`.
7. Риск оценивать по `references/risk-scale.md` с рекламными поправками из методологии.

## Когда использовать

Триггеры:
- «проверь креатив», «реклама», «рекламный текст», «креатив рискованный», «можно ли так в рекламе»;
- «ФАС», «нарушение закона о рекламе», «штраф ФАС», «ст. 14.3 КоАП»;
- «БАД реклама», «реклама лекарства», «реклама медуслуг», «реклама медизделия»;
- «вводящая в заблуждение», «недостоверная реклама», «недобросовестная реклама»;
- ключевые слова-маркеры: «лучший», «№1», «гарантированный», «без противопоказаний», «единственный», «уникальный», «лидер», «эталон»;
- «memo по рекламе», «позиция по рекламному делу», «возражение ФАС»;
- «практика ФАС», «решения ФАС».

## Когда не использовать

- **Договорный спор с рекламным агентством** (нарушение договора подряда / услуг) — `contract-review` + procedural-document-drafter;
- **Защита товарных знаков, использованных в рекламе** — `trademark-search` + `procedural-document-drafter`;
- **Запрос ФАС в рамках КНМ** по рекламе — основной skill `gov-response`, подключающий `fas-ad-practice-search` для содержательной части;
- **Уже идёт дело об АП по ст. 14.3 КоАП**, нужно подготовить процессуальный документ — основной skill `procedural-document-drafter`, подключающий `fas-ad-practice-search`;
- **Иск об оспаривании решения ФАС в АС** (гл. 24 АПК) — основной `procedural-document-drafter`, подключающий `fas-ad-practice-search`;
- **Налоговые вопросы по расходам на рекламу** — не покрыто проектом;
- **Защита репутации (диффамация)** — отдельный жанр.

## Когда вызывается из других skill-ов

| Вызывающий skill | Триггер | Что отдаёт `fas-ad-practice-search` |
|---|---|---|
| `gov-response` | Запрос ФАС касается рекламы (упоминание ст. 5, 24, 25 ФЗ-38, текст креатива в материалах запроса) | Блок IRAC по каждому пункту запроса с привязкой к практике ФАС, контр-практика, разъяснения ФАС |
| `procedural-document-drafter` | Дело по ст. 14.3 КоАП (объяснение / возражение на протокол / жалоба на постановление) | Аргументационный раздел с практикой ФАС в свою пользу, демонстрация различия фактов с делами, где ФАС нашла нарушение |
| `procedural-document-drafter` | Иск в АС об оспаривании решения ФАС (гл. 24 АПК) | Раздел «практика» с подборкой судебных решений, отменивших аналогичные решения ФАС |
| `position-critic` | Критика собственной позиции по рекламному делу | Контр-практика — поиск решений ФАС, поддерживающих противоположную позицию |

В этих сценариях `fas-ad-practice-search` **не делает финального документа** — отдаёт **аналитический блок** вызывающему skill-у, тот вшивает его в свой шаблон.

## Подготовка входа

На вход — материалы по рекламному делу: решения / постановления ФАС (PDF, нередко **сканы со штампами**), креатив (макет рекламы — изображение или PDF), запрос ФАС.

1. Прогнать через `tools/doc_ingest/router.py` — для решений ФАС в PDF и креативов router обычно рекомендует docling (сложный layout, штампы, иногда сканы).
2. Получить `markdown` + `metadata` по протоколу `references/document-ingestion.md`.
3. Для распознавания текста на креативе (макете рекламы) — обязательно docling MCP (markitdown сам не извлекает текст из изображения). Если docling MCP не активирован — попросить юриста активировать по `references/docling-mcp-setup.md`.
4. **Конфиденциальность**: материалы клиента — без cloud-OCR.
5. Если ингестия в текущей сессии недоступна — `[ИНСТРУМЕНТ НЕДОСТУПЕН]` и попросить юриста дать нормализованный Markdown.

Извлечённые из решения ФАС реквизиты (дата, номер дела, нарушитель, формулировка) — сверять через `get_fas_case`, затем по `fas_url` в официальной публикации. При несовпадении — `[ПРОВЕРИТЬ ИСТОЧНИК]`.

## Алгоритм работы (7 шагов)

**Шаг 0 — Контекст дела.** Если креатив, продукт или запрос относится к делу с папкой в `workflow/` — прочитать `case-context.md`. Одна строка юристу. Правило — CLAUDE.md «Контекст дела».

### Шаг 1 — Квалификация вопроса

Получить или запросить у юриста:
- **продукт / услуга** — БАД, ЛП, медизделие, медуслуга, косметика, иное;
- **рекламный канал** — ТВ, наружная, интернет (контекст / нативка / соцсети), упаковка, POS;
- **спорная формулировка** — конкретный текст или фраза;
- **подозреваемая статья** — ст. 5 / 7 / 24 / 25 ФЗ-38 (skill может предположить);
- **цель** — pre-flight / ответ ФАС / процессуальный документ / контр-практика;
- **дата** — особенно для определения года, в котором искать практику;
- **регион** (опционально) — если есть подозрение на территориальную специфику.

**Свойства продукта — из слоя знаний профиля.** Прежде чем опираться на свойства/состав/показания продукта, найти его карточку в `profile/knowledge/products/cards/` (Grep по `name`/`aliases`). Есть карточка со `status: enriched` — брать свойства и провенанс оттуда. Есть файлы в `profile/knowledge/products/_inbox/`, но карточки нет (или она `needs_enrichment`) — предложить юристу собрать её через skill `knowledge-intake`. Нет данных ни там, ни там — ставить `[ПРОВЕРИТЬ ХАРАКТЕРИСТИКИ]`, а не выдумывать. Соглашение — `references/profile-knowledge-layer.md`.

При недостатке вводных — задать **точные вопросы** юристу. Не делать предположений.

После квалификации — вызвать `search_local_curated` по спорной формулировке/категории и через `get_local_curated` раскрыть **только 2–5 сработавших карточек**. Возвращённый exact path ведёт к каноническому файлу в `references/`; это методика, не источник права. Если Overlay недоступен, допустим read-only fallback к индексу `references/ad-creative-playbook.md` и соответствующим карточкам `references/ad-playbook-cards/`. **Итеративный цикл**: если поиск по карточке дал слабую релевантность или в найденных решениях ФАС фигурируют другие основания — вернуться к индексу и взять следующую карточку/основание.

### Шаг 2 — Поисковые гипотезы

Сформировать **2-4 разных запроса** к `search_fas_ad_practice` для покрытия (готовые формулировки по каждому направлению — в карточках рекламного плейбука):

- **точная фраза** (если есть характерная формулировка): «лучший БАД», «№1 в продаже»;
- **юридическая категория**: «утверждение превосходства», «недостоверные сведения о свойствах»;
- **синонимы**: «лидер», «эталон», «непревзойдённый»;
- **отрасль**: «реклама БАД», «реклама медуслуг»;
- **тип канала**: «реклама в интернете», «нативная реклама».

При необходимости — `list_fas_filter_options` для уточнения доступных годов и регионов.

### Шаг 3 — Provider-neutral поиск через Legal Overlay

Вызывать плоский инструмент gateway; namespace `legal-overlay` в Codex/Claude — имя единой локальной точки, а не указание идти на сервер:

```text
search_fas_ad_practice(
  query="<абстрагированная гипотеза>",
  filters={"year": [2024, 2025], "region": ["<УФАС>"], "article": ["ст. 5"]},
  limit=10,
  data_classification="public_or_abstracted"
)
```

Все filters необязательны и принимают одно значение либо список. `limit` — от 1 до 15, по умолчанию 5. Overlay сам переводит flat contract в операцию выбранного provider и передаёт поиск, фильтры и limit на сторону поискового сервиса; фильтрация уже урезанной локальной выдачи запрещена. Возвращаются:

- `results[]` с `docId`, датой, подразделением ФАС, нормами, excerpt и `fas_url`;
- `provider_used`, `sources_attempted`, `sources_succeeded`;
- `fallbacks_used`, `warnings`, `status=OK|DEGRADED`.

Выполнить 2–4 вызова с разными абстрагированными гипотезами. Не передавать имена сторон, текст документа клиента, ПДн или коммерческую тайну. Учитывать общий для исходящего IP лимит provider: не более 20 вызовов в минуту и 300 в сутки; не делать холостые probes и объединять раскрытие до 5 дел в один вызов. При `DEGRADED` результаты допустимы для навигации, и это отмечается в журнале. Если прямой provider недоступен — поставить `[АВТОМАТИЗАЦИЯ НЕ СРАБОТАЛА: поиск ФАС недоступен]` и перейти к ручному поиску на fas.gov.ru; внешний поисковый интерфейс использовать только как навигацию.

Для одной карточки вызывать `get_fas_case(case_id="<docId>")`, для пакета — `get_fas_case(case_ids=["<docId-1>", "<docId-2>"])` (не более 5). Для допустимых фильтров — `list_fas_filter_options()`. Skill не собирает JSON-RPC envelope и не вызывает provider-specific proxy напрямую.

### Шаг 4 — Отбор дел

Из совокупной выдачи (обычно 10-30 дел):
- **Отбросить** заведомо нерелевантные (другая отрасль без аналогии, давно отменённые, другая правовая категория);
- **Выбрать 3-7 наиболее близких** по критериям:
  - совпадение формулировки / категории нарушения;
  - близость отрасли;
  - свежесть (приоритет — последние 2 года, но не отбрасывать резонансные старшие);
  - сила обоснования (ключевые правовые позиции).
- Для топ-кандидатов — один или несколько пакетных `get_fas_case(case_ids=[...])`, не более 5 идентификаторов за вызов; ключевые реквизиты сверить по официальному `fas_url`.

### Шаг 5 — Анализ

Для каждого отобранного дела зафиксировать:

| Параметр | Описание |
|---|---|
| docId | идентификатор в базе |
| УФАС / ФАС | регион / федеральный уровень |
| Год | для оценки актуальности |
| Норма-основание | какая статья ФЗ-38 / ст. 14.3 КоАП |
| Что ФАС квалифицировала как нарушение | конкретная формулировка/факт |
| Ключевой факт-критерий | что было решающим для вывода |
| Штраф / предписание | размер и тип санкции |
| Похожесть на наш кейс | высокая / средняя / низкая, с обоснованием |
| Использовать «за» / «против» нас | поддерживает позицию или нет |

### Шаг 6 — Совокупный вывод

- **Уровень риска** по шкале из `fas-ad-practice-methodology.md` (блокирующий / высокий / средний / низкий / вопрос бизнесу);
- **Применимые нормы** — конкретные статьи;
- **Главные риски** — 2-3 ключевых;
- **Рекомендация**:
  - запускать без правок (низкий риск);
  - запускать с правками (средний);
  - переделать (высокий);
  - снять / не запускать (блокирующий);
  - вопрос бизнесу — описать trade-off.

### Шаг 7 — Черновик документа

В зависимости от сценария (см. раздел «Когда вызывается»):

#### 7а. Pre-flight / memo бизнесу — самостоятельный режим

Готовить **memo** по шаблону из `references/fas-ad-practice-methodology.md` раздел «Шаблон memo бизнесу».

#### 7б. Ответ ФАС — отдать gov-response

Готовить **аналитический блок IRAC** для каждого пункта запроса:
- Issue: какой вопрос задаёт ФАС / что вменяет;
- Rule: какие нормы применимы (с цитированием);
- Analysis: применение к нашему случаю с привязкой к практике;
- Conclusion: позиция компании.

Отдать `gov-response` для вшивания в финальный ответ по структуре gov-response.

#### 7в. Дело об АП по ст. 14.3 КоАП — отдать procedural-document-drafter

Готовить **аргументационный раздел**:
- Привязка к практике ФАС, где аналогичные обстоятельства не привели к штрафу;
- Демонстрация различия фактов с делами, где ФАС нашла нарушение;
- Критика правовой квалификации;
- Ходатайство о применении смягчающих обстоятельств (если применимо).

Отдать `procedural-document-drafter` для вшивания в объяснение / возражение / жалобу.

#### 7г. Иск в АС об оспаривании ФАС — отдать procedural-document-drafter

Готовить **раздел «правовые основания и судебная практика»**:
- Подборка судебных актов, отменивших аналогичные решения ФАС;
- Критика мотивировки оспариваемого решения;
- Применимые позиции ВС РФ / Президиума ВАС.

#### 7д. Контр-практика для position-critic — отдать position-critic

Готовить **критический блок**:
- 3-5 решений ФАС, поддерживающих противоположную позицию;
- Слабые места собственной аргументации;
- Что усилить.

## 8. Рекомендованные правки
По каждому риску — конкретная правка в формате **«было → стало»**, а не только «что не так». Юрист должен увидеть готовый черновик формулировки, а не задачу. Порядок — от блокирующих/высоких рисков к средним. **Формат — обычный текст, не таблица** (таблицы плохо копируются из чата). По каждому пункту:

```
N. [Элемент / место] — [норма], риск: [уровень]
   Было: «[текущая формулировка]»
   Стало: «[готовый черновик под требование нормы]»
   Почему: [что это снимает или смягчает]
```

Правила для строки «Стало»:
- это **черновик формы**, помечается как требующий утверждения юристом (решение и финальный текст — за юристом);
- **не выдумывать свойства, показания, состав или эффект продукта** — правка меняет только *подачу* под требования рекламы; фактические утверждения сверять с инструкцией/регистрацией продукта (`[ПРОВЕРИТЬ ИСТОЧНИК]`, при физ./тех. параметрах — `[ПРОВЕРИТЬ ХАРАКТЕРИСТИКИ]`); первоисточник свойств — карточка продукта в `profile/knowledge/products/cards/` и исходники в `originals/`, а не память модели;
- если для правильной формулировки не хватает данных — ставить маркер вместо выдуманного текста, а не «додумывать»;
- если правок несколько на один элемент — каждую отдельным пунктом.

После пунктов — отдельная строка: какой элемент остаётся **блокирующим** до устранения (например, неподтверждённая госрегистрация), чтобы юрист видел, что распространять нельзя даже после косметических правок.

## 9. Стоимость риска для бизнеса и принятие риска
Компонент 2 заключения (компонент 1 — раздел 8). Адресован бизнесу: не «уровень риска», а конкретная **цена вопроса** и развилка о принятии. По каждому существенному нарушению:

- **Штраф** — размер и норма-основание. По ст. 14.3 КоАП РФ для юрлиц: ч. 1 — от 100 000 до 500 000 ₽; за рекламу ЛП/БАД с нарушением ст. 24–25 ФЗ-38 — повышенные размеры по ч. 5 (от 200 000 до 500 000 ₽). Точную сумму и редакцию проверять через `route_norm_verification(jurisdiction="RU", probe=true)` и `usable_now: true`; при сомнении — `[ПРОВЕРИТЬ АКТУАЛЬНОСТЬ РЕДАКЦИИ]`.
- **Иные последствия** (не только штраф) — назвать применимые: непрохождение согласования канала/площадки (для ТВ — **НРА**), снятие / переделка и пересъёмка ролика с её стоимостью и сроками, срыв сроков рекламной кампании, предписание ФАС об устранении/прекращении, репутационные риски, риск повторности.
- **Совокупная оценка** — свести «цену вопроса» (штраф + переделка + сорванные сроки) в одну строку для бизнеса.
- **Принятие риска** — прямо зафиксировать: запуск/распространение без устранения = **решение бизнеса о принятии риска** (`[ВОПРОС БИЗНЕСУ]`; при выборе стратегии — `[СТРАТЕГИЧЕСКОЕ РЕШЕНИЕ ЮРИСТА]`). Юрист озвучивает риск и необходимость его принять, но не решает за бизнес.

Если риск **блокирующий** — указать прямо, что принять его нельзя без устранения (не «вопрос бизнесу»).

Суммы штрафов и последствия не выдумывать: диапазоны — из раскрытой нормы по capability-маршруту, стоимость/сроки переделки — со слов бизнеса или `[ПРОВЕРИТЬ ФАКТ]`.

## Что запрещено

- **Не выдумывать** docId, даты, регионы, нарушителей. Если коннектор не дал результата — так и пишется.
- **Не делать вывод по одному запросу** — минимум 2-4 разные гипотезы.
- **Не маркировать риск «низкий»** без обоснованного покрытия отрасли в поиске.
- **Не подменять решение бизнеса** в категории «вопрос бизнесу».
- **Не экстраполировать практику одного УФАС на всю РФ** без оговорки.
- **Не игнорировать дела «против нас»** — даже если они невыгодны, фиксировать и анализировать.
- **Не маркировать практику без указания года** — обязательная фиксация для оценки актуальности.
