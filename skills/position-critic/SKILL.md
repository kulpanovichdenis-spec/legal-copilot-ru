# Position Critic

Архитектурный паттерн: iterative + domain-intelligence, High freedom — модель проводит независимый adverse-pass по готовой позиции и возвращает замечания, не изменяя исходный документ.

## Назначение

Skill смотрит на готовый материал глазами оппонента и суда. Ищет слабые факты, недоказанные утверждения, противоречия, пропущенные сроки, процессуальные риски, риск признания обстоятельств, недостающие доказательства, аргументы оппонента и рискованные формулировки.

## Принципы

1. Источники до позиции — `references/skill-shared-steps.md`. Норму подтверждать через `route_norm_verification(..., probe=true)` только по маршруту `usable_now: true`.
2. Skill не переписывает документ. Skill даёт критику и приоритеты для правок.
3. Skill не «защищает» текст. Skill ищет, где он сломается.
4. **Проверка против требования, а не против объёма.** Если документ оценивается на соответствие регламенту/НПА — сначала установить, что регламент **реально требует** (состав, обязательные элементы, лимиты), и проверять наличие именно этого. Нельзя считать дефектом то, что из документа убрали текст, который регламентом не требуется: краткость и отсутствие лишнего — норма, а не слабость. Удалённый/отсутствующий блок — риск только если он обязателен по регламенту или несёт довод, без которого позиция не держится.
5. **Сканировать на выдуманную конкретику.** Отдельно проверять физические/технические характеристики и фактические утверждения на предмет сочинённой правдоподобной детали без источника и без маркера (см. CLAUDE.md «Запрет на выдумывание»). Несогласованность маркировки (одно помечено, соседнее сочинено) — отдельно выносить как риск.
6. Цитирование — по `references/citation-rules.md`. Никаких выдуманных позиций.
7. Skill не подменяет юриста. Решение об учёте критики — за юристом.

## Когда использовать

- Готов проект иска / отзыва / возражений / претензии — нужно протестировать перед отправкой.
- Готов проект ответа госоргану — нужно проверить риски.
- Сформулирована переговорная позиция — нужно проверить, что скажет другая сторона.
- Готов проект ДС или письма контрагенту — нужна вторая пара глаз.

## Когда не использовать

- Документа ещё нет — нужны другие skills.
- Нужен первичный анализ — это `contract-review` или `procedural-document-drafter`.

## Алгоритм работы

0. **Контекст дела.** Если материал относится к делу с папкой в `workflow/` — прочитать `case-context.md` до критики. Одна строка юристу. Правило — CLAUDE.md «Контекст дела».
0a. **Проверенные анти-паттерны практики.** По типу позиции и стадии найти через `search_verified_knowledge` (либо `legal_search` с `source_types=["internal"]`) только `human_verified` объекты, особенно `pattern_kind: risk_antipattern`, `evidence` и `procedure`. Использовать их как дополнительные гипотезы проверки, а не как норму или судебную практику; candidates исключить. Границы — `references/case-knowledge-layer.md`.
1. Прочитать материал целиком.
2. Восстановить логическую цепочку: факт → норма → вывод.
3. Найти разрывы в цепочке.
4. Найти места, где факт не доказан или доказан слабо.
5. Найти места, где норма применена спорно или практика неоднозначна.
6. Сформулировать контрпозицию оппонента.
7. Сформулировать вопросы, которые может задать суд / орган.
8. Выделить рискованные формулировки.
9. Назначить приоритеты правок: блокирующее / высокое / среднее / низкое.

## Обязательная структура ответа

Это канон этапа применения из `references/adverse-review.md`. Второй шаблон для тех же рубрик не заводить.

```markdown
# Критика позиции

## 1. Краткий вывод
Одной фразой: позиция устойчива / устойчива с правками / уязвима. 3–5 ключевых проблем.

## 2. Сильные стороны позиции
Что работает и почему. Без приукрашивания.

## 3. Слабые стороны позиции
Список конкретных проблем со ссылкой на абзац / пункт документа.

## 4. Что может сказать оппонент
Контраргументы, которые с высокой вероятностью прозвучат. Со ссылкой на нормы и/или практику по `citation-rules.md`. Если практика противоречива — указать обе стороны.

## 5. Что может не принять суд / орган
Доводы, которые с высокой вероятностью не пройдут или вызовут вопросы.

## 6. Недостающие доказательства
По каждой слабой точке — какое доказательство закрыло бы её и откуда его можно получить.

## 7. Рискованные формулировки
Конкретные фразы из документа, которые могут быть истолкованы как:
- признание долга / нарушения / вины;
- признание обстоятельств;
- отказ от права;
- готовность к компромиссу, которая ослабит позицию.

## 8. Что усилить
Конкретные предложения: добавить ссылку, добавить расчёт, добавить документ, перестроить аргумент по IRAC.

## 9. Что убрать или переформулировать
По каждой рискованной формулировке — что предлагается вместо неё.

## 10. Приоритетные действия юриста
Список 3–7 пунктов с уровнями: блокирующее / высокое / среднее / низкое. Без блокирующих — отдельно сказать.
```

## Поиск информации

Для качественной критики позиции обязательно искать **контр-практику** — судебные акты с противоположным выводом, разъяснения госорганов в пользу оппонента, аналитические обзоры. Без поиска контр-практики критика часто остаётся «теоретической». Как вести подбор и оценивать вес/статус найденного (authority ≠ forum ≠ argumentative value, ВАС survival, счёт округов) — `references/case-law-search.md` (+ карты `references/case-law-cards/`); разбор конкретного акта — `references/court-decision-analysis.md`.

Использовать инструменты по `references/web-research-tools.md`: agent-browser для kad.arbitr.ru / ras.arbitr.ru; Tavily /search с include_domains=vsrf.ru/consultant.ru/pravo.ru; для рекламной практики — `search_fas_ad_practice` / `get_fas_case` через `legal-overlay`.

Не выдумывать контр-аргументы и судебные позиции — все ссылки должны быть на конкретные акты с реквизитами. При недоступности инструментов — `[ИНСТРУМЕНТ НЕДОСТУПЕН]` и отметка о необходимости юристу самостоятельно проверить контр-практику.

## Что запрещено

- Переписывать документ целиком.
- Давать «новую правовую позицию» вместо критики.
- Выдумывать практику и нормы в подтверждение контрпозиции.
- Применять оценочные характеристики автора документа.
