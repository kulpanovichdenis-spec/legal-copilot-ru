# Playbook Builder

Архитектурный паттерн: sequential + domain-intelligence, High freedom (извлечение стандартов и черновик — суждение модели; детерминированного ядра нет).

## Назначение

Ускоряет создание отраслевых и жанровых playbook'ов (roadmap 3.1–3.7): вместо написания «с нуля по памяти» домашние стандарты **извлекаются из собственных обезличенных образцов** (`legal-document-samples`), а юристу задаются вопросы только о том, чего в образцах и references нет (пороги, эскалация, стратегические позиции).

## Принципы

1. **Только по поручению юриста.** Запрет CLAUDE.md на самостоятельное изменение playbook'ов сохраняется: skill запускается поручением, финал утверждает юрист.
2. **Образцы учат форме, проверенный опыт — практике, ни один из них не учит праву.** Из образцов извлекаются структура, формулировки, тактика, реквизитный состав — с указанием `sample_id` у каждого элемента. Из `human_verified practice_pattern` допустимы evidence checklist, drafting-приём и риск с `knowledge_id`; candidates не используются как стандарт. Каждый **правовой** тезис черновика проходит обычный рабочий цикл (`references/source-hierarchy.md`) или получает маркер. Правила слоёв — `references/legal-document-samples-usage.md` и `references/case-knowledge-layer.md`.
3. **Формат — по существующим playbook'ам.** Перед черновиком прочитать 1–2 ближайших по типу: жанровый → `references/procedural-playbook.md` (карточки жанров), отраслевой → `references/fz248-knm-rospotrebnadzor.md` / `references/fz184-technical-regulation.md` (нормы + сроки + тактика + «что запрещено»). Новый playbook должен выглядеть как родной.
4. **Gap-интервью батчами.** Вопросы юристу — по 2–3 за раз, только о пробелах, которые нельзя закрыть образцами, references или базой. Не спрашивать то, что уже есть в источниках.
5. **Черновик — в `workflow/playbooks/`, в `references/` — только после утверждения.** До утверждения файл называется `<тема>-playbook-draft.md` и несёт в шапке статус черновика. После утверждения юристом — перенос в `references/` + строка в CLAUDE.md «Куда смотреть» + при необходимости триггер-строка в затрагиваемых skills.
6. **Один источник истины.** Общие правила (стиль, риски, цитирование, источники) не копировать в новый playbook — ссылаться на существующие references.

## Порядок работы

1. **Scope.** Зафиксировать тему и жанры, которые покрывает playbook (какие документы, какие ситуации). Неясно — уточнить у юриста до сбора материала.
2. **Harvest.** Собрать инвентарь источников:
   - образцы: **Glob** по `profile/knowledge/document-samples/cards/<категория>/` (contracts / amendments / litigation / koap / gov-responses) + **Read** по теме и смежным категориям; зафиксировать статусы качества (frontmatter); ⚠️ карточки в `.gitignore` — обычный Grep-инструмент их не видит, для контент-поиска `rg --no-ignore`;
   - проверенный опыт прошлых дел: `search_verified_knowledge` (либо `legal_search` с `source_types=["internal"]`) по теме и жанру; брать только `verification.status: human_verified`, фиксировать `knowledge_id`, `pattern_kind`, `support_level` и границы применимости; case study открывать по provenance только для контекста;
   - правовой слой темы: `search_legal_kb` + `search_positions` (нет акта в локальной базе → `references/source-hierarchy.md`, шаг 5);
   - существующие references и клаузы реестра (личный слой `profile/knowledge/clauses/`, навигатор `skills/clause-library/SKILL.md`), чтобы не дублировать.
3. **Extract.** По каждому жанру выписать из образцов: структуру разделов, повторяющиеся формулировки (вводные, просительные, защитные оговорки), тактические ходы (что включается/опускается и почему), реквизитный состав. Каждый элемент — с `sample_id`. Единичный образец — помечать «единичный пример, не подтверждённый стандарт».
4. **Draft.** Собрать черновик в целевом формате (принцип 3). Правовые тезисы — только проверенные по шагу 2 или с маркерами (`[ПРОВЕРИТЬ НОРМУ]`, `[ПРОВЕРИТЬ СРОК]` и т. д.). Перед сохранением — existence-check ссылок на НПА (`references/source-hierarchy.md`, шаг 6).
5. **Gap-интервью.** Составить список пробелов (пороги эскалации, стратегические позиции, отраслевая специфика, спорные развилки) → задать юристу батчами по 2–3 вопроса; ответы внести с пометкой «позиция юриста, [дата]».
6. **Finalize.** Отдать черновик юристу на утверждение с сопроводительной сводкой: что извлечено из образцов (сколько, каких), что подтверждено базой, что осталось под маркерами, что решено в интервью. Перенос в `references/` — только после явного «утверждаю».

## Что запрещено

- **Не выдавать содержимое образца за норму или судебную практику** (образец — источник формы и тактики; правовое основание проверяется отдельно).
- Не переносить черновик в `references/` и не править существующие playbook'и без явного утверждения юриста.
- Не выдумывать пороги, ставки, сроки, позиции «по отраслевой логике» — пробел закрывается интервью или маркером.
- Не копировать в новый playbook общие правила из других references (ссылаться).

## Связанные файлы

- `references/legal-document-samples-usage.md` — правила слоя образцов и статусы качества
- `references/source-hierarchy.md` — рабочий цикл проверки правового слоя
- `references/procedural-playbook.md`, `references/fz248-knm-rospotrebnadzor.md`, `references/fz184-technical-regulation.md` — образцы целевого формата
- `references/template-filling-rules.md` — граница «форма vs объективные данные»
- `references/anonymization-procedure.md` — если для playbook нужны новые образцы из живых документов
