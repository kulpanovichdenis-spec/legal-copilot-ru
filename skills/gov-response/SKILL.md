# Gov Response

Архитектурный паттерн: sequential + context-aware + domain-intelligence, High freedom — модель разбирает запрос, определяет границы раскрытия и готовит проект ответа по проверенным источникам.

## Назначение

Skill готовит:
- summary запроса;
- матрицу запроса (что спрошено / нужно ли отвечать / что предоставить / источник / риск);
- вопросы бизнесу;
- список документов, которые нужно запросить внутри;
- оценку рисков ответа;
- проект ответа с IRAC, если требуется аргументация;
- список приложений;
- заметку для юриста.

## Принципы

1. Источники, поиск НПА, полный текст и проверка связей — строго по `references/source-hierarchy.md`, раздел «Рабочий цикл», **до формирования правовой позиции**. Перед сохранением выполнить предусмотренный там existence-check каждой ссылки; не найдено — маркер `[ПРОВЕРИТЬ НОРМУ]`. Telegram-позиции, opinions и comments — контекст, не источник права.
2. Отвечать только на то, что спрошено. Лишнего не раскрывать.
3. Не признавать обстоятельства, факты, нарушения, вину без необходимости.
4. При правовой аргументации использовать IRAC; цитирование — по `references/citation-rules.md`, уровни риска — по `references/risk-scale.md`.
5. Не выдумывать факты, нормы, реквизиты и документы.
6. Результат — черновик; финальное решение принимает юрист.

## Когда использовать

- Получен запрос / требование о предоставлении документов и сведений.
- Получен запрос в рамках проверки (выездной, камеральной, документарной, надзорной).
- Получено уведомление о вызове должностного лица / законного представителя.
- Получен запрос о предоставлении пояснений.

## Когда не использовать

- Это документ по делу, уже находящемуся в суде, жалоба в порядке досудебного обжалования по ФЗ-248 или заявление по гл. 24 АПК — `procedural-document-drafter`.
- Это требование о предоставлении документов от контрагента — это деловая переписка, не gov-response.
- Это запрос аудитора / контрагента / банка по KYC — это деловой запрос.

## Подготовка входа

На вход — запрос госоргана (PDF — часто сканы с печатями), акт КНМ, предписание, представление. Критично — исходящий номер, дата, ФИО подписанта, орган. Порядок файла — `references/skill-shared-steps.md`, «Подготовка файла». Для скана со штампом docling обязателен.

Любой реквизит госоргана (исходящий №, дата, ФИО), который извлечён OCR с пометкой `[ОЦР НЕ УВЕРЕН]`, в ответе должен сопровождаться маркером `[ПРОВЕРИТЬ РЕКВИЗИТЫ]`. Не пересказывать «по памяти» — только из распознанного источника.

## Алгоритм работы

0. **Контекст дела.** Если орган или дело опознаётся и в `workflow/` есть его папка — прочитать `case-context.md` (и `deadlines.yaml`, если есть) до разбора запроса. Одна строка юристу. Правило — CLAUDE.md «Контекст дела». Если в папке дела документов не меньше порога, а `_knowledge/index.md` нет (`python tools/case_intake/knowledge_gate.py "workflow/<дело>"` вернул `required`) — сначала `skills/matter-knowledge/SKILL.md`, затем документ: фактура берётся из слоя, а не из памяти сессии.
1. Прочитать запрос целиком, включая приложения и шапку.
2. Установить ключевые параметры: отправитель, дата запроса, дата получения, способ направления (на руки, почтой, через личный кабинет, по ТКС), срок ответа, нормы, на которые ссылается орган.
3. Разобрать каждый пункт запроса по матрице.
4. Определить, какие документы и сведения у компании есть, какие нужно получить внутри.
5. Оценить риски: самопризнание, раскрытие лишнего, утрата доказательственной позиции, ПДн, коммерческая тайна.
6. Подготовить проект ответа.
7. Подготовить список приложений.
8. Подготовить заметку для юриста.

## Обязательная структура ответа

```markdown
# Ответ государственному органу

## 1. Краткое summary запроса
Кто направил, дата, основание (норма), что хочет получить, в какой срок, кому адресован, способ направления.

## 2. Матрица запроса

| № | Что запрошено | Нужно ли отвечать | Что предоставить | Источник информации | Риск |
|---|---------------|-------------------|------------------|---------------------|------|

- «Нужно ли отвечать» — да / частично / нет с обоснованием.
- «Что предоставить» — конкретный документ / сведения / пояснение / отказ с обоснованием.
- «Источник информации» — внутреннее подразделение / система / архив.
- «Риск» — по `risk-scale.md`.

## 3. Вопросы бизнесу
Что нужно получить от подразделений: факты, документы, пояснения.

## 4. Документы, которые нужно запросить
Конкретный перечень с указанием подразделений и сроков.

## 5. Риски ответа
- риск самопризнания (что написанное может быть использовано против компании);
- риск раскрытия лишнего (за пределами запроса);
- риск раскрытия ПДн и коммерческой тайны;
- риск противоречия ранее данным пояснениям / документам;
- риск пропуска срока ответа;
- риск отказа без основания.

## 6. Проект ответа
- шапка: адресат, наш исх. номер, дата, ссылка на входящий запрос;
- вступительная часть: на какой запрос отвечаем;
- по существу: ответы по пунктам матрицы;
- IRAC — там, где есть правовая аргументация (по `irac-rules.md`);
- ссылки на нормы и судебную практику только по `citation-rules.md`;
- перечень приложений;
- подпись уполномоченного лица.

## 7. Список приложений
Нумерованный список с количеством листов.

## 8. Заметка для юриста
По шаблону `templates/agent-notes/review-note-template.md`.
```

## Обязательные проверки

- кто направил запрос и его компетенция;
- основание запроса (норма);
- срок ответа и способ исчисления;
- кому адресован;
- что именно запрошено;
- надо ли вообще отвечать (компетенция, пределы полномочий, относимость);
- риск самопризнания;
- риск раскрытия лишнего;
- ПДн и порядок передачи;
- коммерческая тайна и порядок передачи (98-ФЗ);
- необходимость IRAC.

## Отраслевые playbook-и (обязательно подключать при соответствующих триггерах)

- **Запрос Роспотребнадзора или иного органа контроля в рамках КНМ, акта КНМ, предписания** → **обязательно подключить `skills/fz248-knm-rospotrebnadzor/SKILL.md`**. Скилл содержит процедурные таблицы статей, сроки и форму подачи (10 рабочих дней на жалобу на предписание, 15 рабочих дней на её рассмотрение, подача через ЕПГУ с УКЭП); `gov-response` вшивает его выводы в финальный ответ по своей структуре.
- **Письмо по ст. 37 / ст. 38 ФЗ-184, информация о несоответствии техническим регламентам, угроза предписания о приостановке реализации, угроза иска о принудительном отзыве** → **обязательно подключить `skills/fz184-technical-regulation/SKILL.md`**. Скилл содержит полную процедурную логику: программа мероприятий, отзыв продукции, обжалование предписания. Не разрабатывать программу мероприятий до подтверждения достоверности; не соглашаться на устное требование об утилизации без судебного решения по ст. 40 ФЗ-184; обжалование предписания о приостановке реализации — только в судебном порядке (ст. 39 ч. 4 ФЗ-184).
- **Запрос ФАС по рекламе** (ссылки на ст. 5, 7, 24, 25 ФЗ «О рекламе» в запросе; материалы креатива в приложениях; вопросы о соответствии формулировок; угроза возбуждения дела по ст. 14.3 КоАП) → **обязательно подключить `skills/fas-ad-practice-search/SKILL.md`** для подбора практики ФАС и обоснования позиции. `fas-ad-practice-search` отдаст блок IRAC по каждому пункту запроса с привязкой к практике; `gov-response` вшивает его в финальный ответ по своей структуре. Методология — `references/fas-ad-practice-methodology.md`.

## Поиск информации

При подготовке ответа часто требуется веб-поиск: разъяснения адресата запроса (fas.gov.ru, rospotrebnadzor.ru, fns.gov.ru и т. д.), актуальная редакция нормы, на которую ссылается запрос (pravo.gov.ru), практика обжалования аналогичных запросов / предписаний (kad.arbitr.ru, ras.arbitr.ru), позиции вышестоящих судов (vsrf.ru).

**Если в ответе госоргану упоминаются третьи лица (контрагенты, поставщики, дистрибьюторы и т. п.)** — подключать `skills/counterparty-check/SKILL.md` (DaData MCP) для сверки наименования, ИНН/ОГРН и адреса этих лиц перед включением в ответ. Ошибка в реквизитах третьего лица в ответе госоргану — отдельный риск (может быть истолкована как недостоверные сведения).

Использовать инструменты по `references/web-research-tools.md` (Tavily /search с фильтром по официальному домену органа; agent-browser для kad.arbitr.ru; WebFetch для прямого URL разъяснения).

Закрытие поиска — `references/skill-shared-steps.md`.

## Что запрещено

- Признавать факты, нарушения, вину без указания юриста.
- Включать в ответ информацию за пределами запроса.
- Передавать ПДн и сведения, составляющие коммерческую тайну, без основания.
- Ссылаться на «практику» без конкретных актов.
- Выдумывать реквизиты документов, даты, номера, должностных лиц.
- Указывать готовность к каким-либо действиям, которые не согласованы с бизнесом и юристом.

Если задача — конкретный тип ответа / документа госоргану, использовать соответствующий раздел `references/procedural-playbook.md`:

| Тип документа | Раздел | Норма-основание |
|---|---|---|

| Возражение на предостережение | 20 | ст. 49 ФЗ-248 |
| Сопроводительное письмо к госоргану | 21 | — (транспортный документ) |
| Жалоба в порядке досудебного обжалования по ФЗ-248 | 17 | готовит `procedural-document-drafter` |
| Заявление в АС об оспаривании акта госоргана | 18 | готовит `procedural-document-drafter` |

Для отраслевых дел (ФЗ-184, ФЗ-248, КНМ, отзыв продукции и т. п.) — подключать `skills/fz248-knm-rospotrebnadzor/SKILL.md` и `skills/fz184-technical-regulation/SKILL.md` (reference-файлы служат справочным фоном внутри этих скиллов).

Стиль, цитирование, оформление — те же общие reference-файлы (house-style, citation-rules, document-formatting); ответ собирается через `ProceduralDoc` (процессуальный профиль).

## Ответы на представления

Для ответов на **представления государственных органов** (прокурорские, должностных лиц по делам об АП, иные) использовать структуру и правила из `references/procedural-playbook.md` раздел 19. Триггеры — «представление прокурора», «представление об устранении причин и условий», «представление должностного лица», «ответ на представление». Срок ответа — 1 месяц с момента получения; норма-основание — ст. 24 Закона о прокуратуре или ст. 29.13 КоАП РФ в зависимости от типа.
