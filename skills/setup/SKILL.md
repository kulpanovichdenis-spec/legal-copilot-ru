# Setup

Архитектурный паттерн: **sequential, low freedom**. Единственный источник порядка, команд и fallback-путей — `SETUP.md`; этот skill служит детерминированной точкой входа и не дублирует bootstrap-инструкцию.

## Порядок работы

1. Прочитать `SETUP.md` полностью.
2. Сначала развернуть и проверить обязательный baseline, включая Tesseract OCR с языками `rus` и `eng` на Windows.
3. Показать пользователю доступные дополнительные возможности и подключить только выбранные.
4. После каждого существенного этапа кратко сообщать фактический результат.
5. На шагах с UAC, credentials, OAuth, CAPTCHA, крупной загрузкой или изменением внешней конфигурации остановиться и дождаться пользователя.
6. Завершить проверкой из `SETUP.md` и итогом: baseline / подключённые возможности / ограничения.

## Инварианты

- Не требовать конкретную правовую базу, snapshot, внешний provider или credential для базовой установки.
- Не запрашивать значения секретов в чате и не выводить их.
- Не считать отсутствие опционального компонента ошибкой baseline.
- Tesseract OCR на Windows не считать опциональным компонентом: проверить его наличие, при отсутствии показать команду системной установки и выполнить её только после подтверждения пользователя. Без Tesseract и языков `rus`/`eng` не сообщать о полной готовности обработки сканов и локального обезличивания.
- Не записывать машинные пути и локальный setup-статус в публичные файлы репозитория.
- Не обходить ошибку молча и не сообщать об успешной установке без проверки.
- Не выполнять push и не отправлять данные во внешние системы.

## Границы

- Обновление существующей установки выполняет `self-update`.
- Пошаговая standalone-установка и правила Git описаны в `INSTALL-SPLIT.md`.
- Пользовательский слой и его перенос описаны в `profile/README.md`.
- Подключение конкретного источника выполняется по его provider profile и профильной инструкции, а не по предположению агента.
