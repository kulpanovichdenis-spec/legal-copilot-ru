# Self-Update

Архитектурный паттерн: sequential + Low freedom — детерминированное ядро `tools/self_update/update.py` (git-операции, разбор изменений, ff-обновление, зависимости, smoke, перепривязка); модель только оркестрирует и держит чекпоинт подтверждения.

## Назначение

Безопасно обновить базовый код legal-copilot из GitHub без потери локальных данных. Базовый код (`skills/`, `references/`, `templates/`, `CLAUDE.md`) заменяется из `origin/main`; пользовательский слой `profile/` не трогается.

## Принципы

1. **Только быстрая перемотка.** Обновление применяется, лишь если это FF `origin/main`. Не-FF или грязная база → остановиться и показать причину, ничего не затирать.
2. **Обязательный чекпоинт.** После показа изменений — явный вопрос «Ставить?»; применять только по «да».
3. **Все git-операции — через скрипт** `tools/self_update/update.py`. Модель не делает `git pull`/`merge` руками.
4. **Профиль неприкосновенен.** `profile/**` не входит в обновление; перепривязка оверлея — часть шага apply.
5. **Не пушит.** Skill только тянет из GitHub. Публикация изменений — задача мейнтейнера.

## Ход работы

### Шаг 1 — проверить обновление

```
python tools/self_update/update.py check
```

Скрипт: проверяет чистоту базы (грязно → код возврата 2, показать список и остановиться), делает `git fetch origin main`, печатает: возможна ли FF, менялся ли `requirements.txt`, и сгруппированный список изменённых файлов. Если «Обновлений нет» — сообщить и закончить.

### Шаг 2 — показать и спросить

Пересказать юристу человеческим языком: сколько skills/references/шаблонов меняется, менялись ли зависимости, версия было→стало (из `profile.yaml` и вывода). **Задать явный вопрос: «Ставить обновление?»** Ждать «да».

### Шаг 3 — применить (только по «да»)

```
python tools/self_update/update.py apply
```

Скрипт: ещё раз проверяет базу/FF, делает `git merge --ff-only origin/main`, при изменении зависимостей — `pip install -r requirements.txt`, прогоняет smoke (`tests/doc_ingest_smoke.py`), вызывает перепривязку оверлея.

### Шаг 4 — отчёт

Коротко: версия было→стало, что изменилось, зависимости (ok/ошибка), smoke (PASS/FAIL), перепривязка (сколько своих skills/заметок/шаблонов; ⚠ висячие привязки, если базовый skill исчез — назвать их). При FAIL smoke или ошибке зависимостей — прямо сказать и предложить откат (`git reset --hard <прежний hash из profile.yaml>` только с согласия юриста).

## Что запрещено

- Применять обновление без явного «да».
- Обновляться при не-FF или грязной базе (разбирает мейнтейнер).
- Трогать `profile/**`.
- Пушить в GitHub.
