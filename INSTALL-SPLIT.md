# INSTALL — legal-copilot

`legal-copilot` устанавливается как самостоятельный репозиторий. Пользовательские данные, рабочие документы и настройки хранятся отдельно от версионируемой части проекта.

## Установка

```powershell
cd "$env:USERPROFILE\Desktop"
git clone https://github.com/kulpanovichdenis-spec/legal-copilot-ru.git
```

Использовать именно `git clone`, а не GitHub Download ZIP. Git-метаданные нужны
для штатного обновления, определения основного checkout и безопасной работы
автоматизации из worktree.

Подключить папку `legal-copilot` как workspace в Claude Code или OpenAI Codex и написать:

```text
Разверни legal-copilot.
```

Также сработают команды «setup», «установи проект» и «подними проект». Агент должен прочитать `SETUP.md`, развернуть базовую среду, выполнить проверки и отдельно предложить доступные дополнительные возможности.

## Что входит в базовую установку

- зависимости самого проекта;
- инструкции и skills для поддерживаемых AI-раннеров;
- локальный gateway `legal-overlay` без обязательного набора источников;
- Tesseract OCR с языками `rus` и `eng` для локальной обработки сканов на Windows;
- пользовательский слой `profile/`;
- рабочая папка `workflow/`;
- единый локальный watcher входных каналов; Windows-автозапуск подключается
  setup-агентом после показа параметров и подтверждения пользователя;
- автоматические проверки проекта.

Собственные правовые базы, внешние сервисы, браузерная автоматизация, Docling и другие тяжёлые ingestion-компоненты подключаются отдельно по потребности пользователя.

## Рабочие документы

`workflow/` — локальная рабочая зона. В Git входит только безопасный служебный каркас:

```text
workflow/
  README.md
  _anonymizer/
    _inbox/
    _ready/
  _claims/
  _counterparty/
    _inbox/
```

В `profile/knowledge/` Git также поставляет пустые `_inbox/` для `products`,
`corporate`, `clauses` и `document-samples`. `workflow/_watcher/` создаётся
автоматически при первом запуске и хранит локальный журнал и мета-очередь.

Документы по делам, проекты, данные контрагентов и персональные данные не коммитятся.

## Профиль пользователя

`profile/` хранит локальные настройки, собственные skills, дополнения к базовым правилам, шаблоны, знания и обратную связь. Обновление базового проекта не должно перезаписывать этот слой.

Профиль можно перенести на другую машину отдельно от репозитория. Подробности — `profile/README.md`.

## Пользовательские источники

Правовые корпуса и рабочие базы не поставляются вместе с `legal-copilot`. Пользователь может подключить:

- совместимые локальные корпуса;
- собственные образцы и внутреннюю юридическую память;
- официальные и открытые источники;
- профессиональные системы, к которым у него есть законный доступ;
- новый provider и adapter для собственной структуры данных.

Пути, параметры подключений и ссылки на секреты хранятся локально в `profile/settings/`. Значения credentials в Git не записываются.

## Обновление

На установленной машине написать агенту:

```text
Проверь обновление и установи.
```

Skill `self-update` должен:

1. проверить состояние репозитория;
2. показать доступные изменения;
3. запросить подтверждение;
4. применить обновление и зависимости;
5. повторно выполнить проверки;
6. не изменять содержимое `workflow/` и пользовательский слой `profile/`.

## Проверка

```powershell
powershell -ExecutionPolicy Bypass -File tools/verify_project.ps1
```

Ожидаемый финал:

```text
PASS: legal-copilot verification completed
```

Подключённые пользователем источники и дополнительные возможности проверяются отдельно. Их отсутствие не считается ошибкой базовой установки.

## Правила Git

В репозиторий можно включать:

- правила, skills, references и служебные templates;
- инструменты и тесты;
- документацию проекта;
- пустой безопасный каркас `workflow/` и `profile/`.

Не следует коммитить:

- рабочие документы и материалы конкретных дел;
- локальные настройки, ключи, токены и пароли;
- машинные пути и пользовательские MCP-конфигурации;
- персональные данные и конфиденциальные документы;
- машинно-зависимые setup-отчёты.
