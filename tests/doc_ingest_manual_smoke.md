# Doc Ingestion — ручной smoke-тест на реальных документах

Этот файл — шаблон ручного теста для **Направления 9.6**. Прогоняется юристом при первом реальном кейсе с настоящими документами (отсутствуют в репозитории по соображениям конфиденциальности).

Автоматизированная часть smoke-теста — `tests/doc_ingest_smoke.py` — покрывает только текстовые форматы из репозитория (`.md`, `.json`, `.txt`).

## Цель

Подтвердить на реальных юридических документах:
1. **markitdown** корректно конвертирует нативные `.docx` договоров с сохранением нумерации пунктов и таблиц.
2. **router** правильно определяет «текстовый PDF vs скан» и предлагает docling для сканов.
3. **docling MCP** (если активирован) распознаёт сканированные документы с штампами.
4. **markers** (`[ОЦР НЕ УВЕРЕН]`, `[ШТАМП НЕ РАСПОЗНАН]` и т. п.) появляются там, где должны.

## Условия

- Установлен `markitdown[all]` (см. `requirements.txt`).
- Опционально: активирован `docling` в `.mcp.json` (см. `references/docling-mcp-setup.md`).
- Все тестовые файлы — **не из репозитория** (репозиторий публичный/полу-публичный, реальные документы клиента туда не попадают).
- Результаты теста — **не коммитить** в репозиторий (содержат чувствительные данные).

## Тестовые сценарии

### Сценарий 1. Нативный `.docx` договора

**Файл**: любой `.docx` договор клиента.
**Команда**:
```powershell
python -m tools.doc_ingest.router "путь\к\Договор.docx" -o $env:TEMP\test1.md --json-meta -
```

**Ожидаемое**:
- `router=markitdown` (нативный Office формат);
- `metadata.char_count > 1000` для среднего договора;
- В `markdown` сохранены **номера пунктов** в исходном виде («1.», «2.1.», «5.2.3.» и т. п.);
- Таблицы (спецификации, реквизиты) сохранены как Markdown-таблицы или явные блоки.

**Проверить вручную**:
- Открыть `test1.md` в редакторе;
- Сравнить количество пунктов с исходным `.docx`;
- Найти пункт «5.2.3» в обоих — текст совпадает?
- Спецификации — читаемые таблицы или плоский текст?

**Если плохо**: переключиться на docling.

### Сценарий 2. Текстовый PDF судебного акта

**Файл**: судебный акт АС / СОЮ, скачанный из kad.arbitr.ru — текстовый PDF.
**Команда**:
```powershell
python -m tools.doc_ingest.router "путь\к\Постановление-АС.pdf" --recommend
# затем
python -m tools.doc_ingest.router "путь\к\Постановление-АС.pdf" -o $env:TEMP\test2.md --json-meta -
```

**Ожидаемое**:
- `router=markitdown` (текстовый слой найден);
- В выходе есть полный текст постановления, реквизиты в шапке (суд, дата, номер дела);
- Многоколоночные блоки (если есть в постановлении) могут быть нарушены — это известное ограничение markitdown.

**Если многоколоночность нарушена** (порядок чтения смешан) — переключиться на docling.

### Сценарий 3. Сканированный PDF (запрос ФАС / предписание / постановление КоАП)

**Файл**: PDF, полученный сканом с печатями и подписями.
**Команда**:
```powershell
python -m tools.doc_ingest.router "путь\к\Скан-предписание.pdf" --recommend
```

**Ожидаемое**:
- `router=docling` с reason типа «PDF без текстового слоя: текстовый слой пуст или почти пуст»;
- В `warnings` — `[ОЦР НЕОБХОДИМ]`.

**Если docling MCP активирован** — открыть Claude Code и запросить:
> Сконвертируй с помощью docling MCP файл `путь\к\Скан-предписание.pdf` в Markdown.

**Проверить**:
- Распознан ли текст в шапке (исходящий №, дата, орган)?
- Распознан ли текст основной части?
- Содержание штампа — есть ли маркер `[ШТАМП/ПЕЧАТЬ — НЕ РАСПОЗНАНА]`?
- Подпись — есть ли маркер?

### Сценарий 4. `.xlsx` со спецификацией (прайс, перечень товаров)

**Файл**: Excel-файл с прайсом или спецификацией.
**Команда**:
```powershell
python -m tools.doc_ingest.router "путь\к\Спецификация.xlsx" -o $env:TEMP\test4.md
```

**Ожидаемое**:
- `router=markitdown`;
- Все строки/столбцы извлечены в Markdown-таблицу;
- Числа сохранены (без преобразования в строки/научный формат для больших чисел).

### Сценарий 5. Креатив рекламы (`.png` / `.jpg`)

**Файл**: макет рекламы (картинка с текстом).
**Команда**:
```powershell
python -m tools.doc_ingest.router "путь\к\Макет.png" --recommend
```

**Ожидаемое**:
- `router=docling` (изображение требует OCR);
- В `warnings` — `[ОЦР НЕОБХОДИМ]`;
- Stub-вывод вместо реальной конверсии.

Если docling MCP активирован — запросить через Claude Code.

**Проверить**:
- Извлечён ли весь текст с макета?
- Маркер «реклама» / «*»-сноски / мелкий шрифт — распознаны?
